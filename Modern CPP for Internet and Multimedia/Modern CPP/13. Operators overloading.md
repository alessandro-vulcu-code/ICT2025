### Rules for Operator Overloading
#### Redefinable Operators
It is possible to redefine a large set of operators, including arithmetic (`+`, `*`, `/`), comparison (`==`, `!=`, `<`, `>`), compound assignment (`+=`, `*=`), stream operators (`<<`, `>>`), and special operators (`[]`, `()`, `new`, `delete`).

#### Non-Redefinable Operators
It is **not possible** to define new operators or redefine certain built-in operators:
- `::` (scope resolution)
- `.` (member selection)
- `.*` (member selection through pointer to member)
- `sizeof`, `alignof`, `typeid`
- `?:` (ternary operator)

#### Operator Forms
Operators can be overloaded as either **non-static member functions** or **non-member functions**.
- **Binary operators** (two arguments):
	- Member form: `aa.operator@(bb)`
	- Non-member form: `operator@(aa, bb)`
- **Unary operators** (one argument, prefix or postfix):
	- Member form: `aa.operator@()`
	- Non-member form: `operator@(aa)`
- **Non-member functions** are necessary when the left-hand argument (`aa`) is not in your control, such as when overloading an operator for built-in types or user-defined types defined by someone else.

---

### Overloading General Rules
- All operators to be used must be **explicitly overloaded**. For example, the compiler will not automatically infer `operator+=()` from `operator+()` and `operator=()`.
- The rules for passing arguments apply: **value** for built-in types and **const lvalue references** for user-defined types.
- For non-static member operators, it is common to return a **reference to `this`** (with return type `X&` for a class `X`).

---

### Overloading the Stream Insertion Operator (`<<`)

The `operator<<` is generally overloaded to **concatenate output on streams** like `std::cout`.
- For built-in types, `operator<<` is overloaded directly in the `<ostream>` header.
- For user-defined types, it **must be overloaded with a non-member function declaration**. This is because the first argument is `std::ostream&`, and you cannot add a new function declaration into the definition of the standard library's `ostream` class.
- If the overloaded operator needs access to the **private members** of the user-defined type, the access must be granted either by:
	- Calling a public **member function**.
	- Using the **`friend` keyword**.

---

### Accessing Private Members for `operator<<`
Since `operator<<` is typically implemented as a non-member function, it needs a way to access the private data of the user-defined type it's meant to print.

#### 1. Call to a Member Function
The non-member `operator<<` can call a public member function within the class to handle the actual printing.

```c++
std::ostream& operator<<(std::ostream& out, const Y& y) {
    return y.someFunction(out); // someFunction is a public member of Y
}
```

#### 2. `friend` Keyword
The `friend` keyword can be used inside the class declaration to grant a non-member function access to the class's private members.
- The `friend` declaration does **not** define the function; it only grants access rights.
- It can be placed in either the public or private section of the class declaration.
- **Caution**: The `friend` keyword is powerful and should be used with care, as it can **break the encapsulation principle**.

---

#### Overloading Special Operators
##### `operator[]` (Subscript Operator)
The subscript operator (`operator[]`) is overloaded to provide **subscript access** to elements of user-defined types, similar to how elements of a `std::vector<T>` are accessed.

##### `operator()` (Function Call Operator - Functors)
The function call operator (`operator()`) is overloaded to create **function objects (functors)**: objects that **behave as functions**.
- **Functors** can maintain an **internal state** across multiple calls, which is their key benefit over regular functions.
- **Example**: A class like `CalculateAverageOfPowers` stores its state (`acc`, `n`, `p`). When an object of this class is called like a function (`functor(10)`), it executes the body of its overloaded `operator()`.
- **Use Case**: Functors are commonly used with algorithms like `std::for_each`. When `std::for_each` is called, it iteratively calls the functor's `operator()` on each element in the collection, allowing the functor to **accumulate a result** or maintain a count over the entire range.
For instance, in the `CalculateAverageOfPowers` example, `std::for_each` updates the internal state (`acc` and `n`) with each element processed.
