# 1. C++ Type System Overview

## 1.1 Two Categories of Types

> [!info] Definition — Fundamental Types **Fundamental types** are built directly into the language and are available without any `#include` or additional declaration. Examples: `int`, `bool`, `char`, `double`, `void`

> [!info] Definition — User-Defined Types **User-defined types** are introduced either by the programmer or by a library header included in the translation unit. Example: `std::vector` (requires `#include <vector>`)

---

# 2. Fundamental Types — Deep Dive

## 2.1 Boolean (`bool`)

> [!info] Definition — `bool` Stores exactly one of two logical values: **`true`** (represented as integer `1`) or **`false`** (represented as integer `0`). Used to express logical conditions and the results of logical operations.

```cpp
bool b1 {1 == 0};  // b1 = false (0), because 1 does not equal 0
```

**Explanation:**

- `1 == 0` is a relational expression. Since 1 is not equal to 0, the expression evaluates to `false`.
- `b1` is initialized using **brace-initialization** (C++11 style — more on this in §5).
- **Expected result:** `b1` holds `false`.

---

## 2.2 Character Types (`char`, `signed char`, `unsigned char`, `wchar_t`)

> [!info] Definition — Character Types C++ provides several character types. The most common is `char`, which is almost universally **8 bits** wide. 7 bits suffice to represent the full **ASCII** table (128 characters).

**Available character types:**

- `char` — implementation-defined signedness
- `signed char` — explicitly signed
- `unsigned char` — explicitly unsigned
- `wchar_t` — wide character (for extended character sets)

> [!warning] Portability Pitfall — `signed` vs `unsigned char` Whether a plain `char` is signed or unsigned is **implementation-defined**. This can silently differ between platforms (Windows vs. Linux, 32-bit vs. 64-bit, ARM vs. x86). **Never rely on the signedness of a plain `char` for portable code.**

### Character Literals

- A single character enclosed in **single quotes** → type `char` → e.g., `'a'`, `'0'`
- **Escape sequences** use `\` + letter → e.g., `'\n'` (newline), `'\t'` (tab)
- **Hexadecimal ASCII** representation: `'\x'` + hex number → e.g., `'\x61'` = `'a'`

```cpp
char c1 = 'a';
char c2 = '\x61';   // hex 61 = decimal 97 = ASCII 'a'
char c3 = 97;       // decimal 97 = ASCII 'a'

std::cout << c1 << std::endl;  // prints: a
std::cout << c2 << std::endl;  // prints: a
std::cout << c3 << std::endl;  // prints: a
```

**Step-by-step explanation:**

|Variable|Value|Representation|Output|
|---|---|---|---|
|`c1`|`'a'`|character literal|`a`|
|`c2`|`'\x61'`|hexadecimal ASCII|`a`|
|`c3`|`97`|decimal ASCII|`a`|

All three variables hold the **same underlying value** (97). `std::cout` interprets a `char` as a printable character, so all three print `a`.

---

## 2.3 Integer Types

> [!info] Definition — Integer Types Integers represent whole numbers. C++ provides several widths and signedness variants.

**Available integer types:**

- `int`, `signed int`, `unsigned int`
- `short int` (shorter width)
- `long int` (longer width)
- `long long int` (longest standard width)

---

## 2.4 Floating-Point Types

> [!info] Definition — Floating-Point Types Used to represent real (fractional) numbers. Three standard types exist with increasing precision.

|Type|Precision|
|---|---|
|`float`|Single-precision|
|`double`|Double-precision|
|`long double`|Extended-precision|

> [!warning] Implementation-Defined Precision The exact bit-width of floating-point types is **implementation-defined**. Do not assume a specific size for portability.

---

## 2.5 `void`

> [!info] Definition — `void` `void` is a special type with two uses:
> 
> 1. Indicates a **function returns no value** → `void f() { ... }`
> 2. Acts as the **type of a pointer to an unknown object** → `void*` (covered in later lectures on pointers)

# 3. Sizes

## 3.1 Implementation-Defined Sizes

> [!important] The C++ Standard Does Not Fix Type Sizes The standard deliberately leaves the size of fundamental types to the **compiler/platform implementation**. Sizes are well-defined _per implementation_, but you **must not assume sizes for portable code**.
> 
> Key insight: **the C++ language ≠ what a specific compiler implements on a specific platform.**

## 3.2 `sizeof` Operator

> [!info] Definition — `sizeof` `sizeof(T)` returns the size of type `T` **in units of `char`** (i.e., bytes on virtually all modern platforms where `char` = 1 byte).

**Guaranteed size ordering (always valid regardless of platform):**

```
1 ≡ sizeof(char) ≤ sizeof(short) ≤ sizeof(int) ≤ sizeof(long) ≤ sizeof(long long)

sizeof(float) ≤ sizeof(double) ≤ sizeof(long double)
```

## 3.3 Portable Fixed-Width Types — `<cstdint>`

> [!tip] Best Practice — Use Fixed-Width Types for Portability Include `<cstdint>` to access types with guaranteed exact sizes.

|Type|Meaning|
|---|---|
|`int16_t`|Exactly 16-bit signed integer|
|`uint32_t`|Exactly 32-bit unsigned integer|
|`uint_fast32_t`|Fastest unsigned integer ≥ 32 bits (portable)|

> [!warning] `uint32_t` is NOT fully portable `uint32_t` may not exist on platforms where no type is exactly 32 bits. Prefer `uint_fast32_t` for maximum portability.

## 3.4 `size_t` — `<cstddef>`

> [!info] Definition — `size_t` `size_t` is an **unsigned integer type** large enough to hold the size in bytes of any object on the current platform. Always use `size_t` when storing results of `sizeof` or sizes of containers.

# 4. Declarations

## 4.1 Declaration vs. Definition

> [!info] Definition — Declaration A **declaration** introduces a **name** (bound to a type) into the program. A name is a sequence of characters starting with a letter that uniquely identifies an entity.

> [!info] Definition — Definition A **definition** is a declaration that _also_ provides all information the program needs to actually use the entity:
> 
> - **Memory** allocation for variables
> - **Body** for functions (what the function actually does)
> - **Fields and methods** for classes

> [!important] One Definition Rule (ODR) In a C++ program, each name must have **exactly one definition**. Multiple definitions of the same name (in the same scope) cause a compilation error.

## 4.2 Naming Conventions

> [!tip] Use Consistent Naming Conventions The course follows these conventions (see [C++ Coding Standards](https://gist.github.com/lefticus/10191322)):
> 
> - **Classes:** `PascalCase` (e.g., `ExampleClass`)
> - **Functions:** `camelCase` (e.g., `someFunction`)
> - **Variables:** `snake_case` (e.g., `local_scope_var`)

## 4.3 Anatomy of a Declaration

A declaration in C++ is composed of up to four parts:

```
[Optional prefix] + [Base type] + [Declarator] + [Optional suffix] + [Optional initializer]
```

|Part|Examples|Role|
|---|---|---|
|Optional prefix|`static`, `virtual`|Storage class / linkage specifier|
|Base type|`const char*`, `int`, `std::vector<double>`|The core type (cannot be omitted)|
|Declarator|name + optional operator (`*`, `[]`)|Name being declared + type modifier|
|Optional suffix|`const`, `noexcept`|Additional qualifiers|
|Optional initializer / body|`{...}`, `= value`|Initial value or function body|

```cpp
// Full example annotated:
static const char* universities[] {"Padova", "Venezia"};
//  ^      ^^^^^^^^^  ^             ^^^^^^^^^^^^^^^^^^^
// prefix  base type  declarator    initializer
```

**More examples:**

```cpp
int a_number {10};
// Base type: int
// Declarator: a_number
// Initializer: {10} → a_number = 10

const char* str_c {"example of declaration"};
// Base type: const char*  (pointer to const char)
// Declarator: str_c
// Initializer: {"example of declaration"}

std::vector<double> double_vec {0.1, 0.4, 0.5};
// Base type: std::vector<double>  (user-defined type)
// Declarator: double_vec
// Initializer: {0.1, 0.4, 0.5}  (initializer list)
```

## 4.4 Declarator Operators

Declarator operators modify the base type and bind to the name:

|Position|Operator|Meaning|
|---|---|---|
|prefix|`*`|pointer|
|prefix|`*const`|constant pointer|
|prefix|`*volatile`|volatile pointer|
|prefix|`&`|lvalue reference (§7.7.1)|
|prefix|`&&`|rvalue reference (§7.7.2)|
|prefix|`auto`|function using suffix return type|
|postfix|`[]`|array|
|postfix|`()`|function|
|postfix|`->`|returns from function|

> [!important] Postfix Binds Tighter than Prefix This affects how complex declarations are parsed:

```cpp
char* universities[]    // array of pointers to char
                        // [] binds first (postfix), then * (prefix)

char (*universities)[]  // pointer to array of char
                        // parentheses force * to bind first
```

> [!tip] Style Tip — Space Placement Put a space between the type and the operator to make intent clear:
> 
> ```cpp
> char* universities[]   // preferred
> ```

# 5. Scope

## 5.1 What is Scope?

> [!info] Definition — Scope **Scope** defines the region of a program where a declared name is valid and accessible. It is fundamental to C++ **resource management** (e.g., RAII — Resource Acquisition Is Initialization).

## 5.2 Types of Scope

### Local Scope (Block Scope)

Declared inside a function/block `{ }`. Valid from the point of declaration to the closing `}`.

```cpp
void f()
{
    int a {10};                      // 'a' declared here
    std::cout << a << std::endl;     // valid: inside block
}
// 'a' does not exist here — out of scope
```

### Class Scope

Member variables/functions declared inside a class (but outside member functions). The scope spans the entire class block `{ ... }`.

### Namespace Scope

Names declared inside a `namespace` block (but outside functions/enums/classes). Scope extends from the declaration to the end of the namespace.

### Global Scope

Names declared outside all functions, classes, enums, and namespaces. Scope extends from declaration to the **end of the file** and can be accessed from other files via **external linkage**.

### Statement Scope

Names declared in the `( )` control expression of `for`, `while`, `if`, or `switch`. Scope extends to the closing `}` of that statement.

```cpp
for (int index = 0; index < 10; ++index)
{
    std::cout << index << std::endl;   // valid
}
// 'index' does not exist here
```

## 5.3 Comprehensive Scope Example

```cpp
int global_var {10};  // GLOBAL scope

namespace Example {
    int namespace_scope_var {5};  // NAMESPACE scope

    class ExampleClass {
        int class_scope_var;      // CLASS scope

        void f() {
            int local_scope_var {2};  // LOCAL scope

            for (int statement_scope_idx = 0;
                 statement_scope_idx < local_scope_var;
                 ++statement_scope_idx)
            {                         // STATEMENT scope
                std::cout << statement_scope_idx;
            }
        }
    };  // end of ExampleClass scope
}  // end of namespace Example scope
```

**Visual scope nesting (outermost → innermost):**

```
Global → Namespace → Class → Local (function) → Statement (for loop)
```

## 5.4 Hiding / Shadowing

> [!danger] Avoid Variable Shadowing In nested blocks, a name can be **redeclared**, hiding the outer name. This is legal C++ but leads to subtle bugs. **Minimize or completely avoid it.**

```cpp
int index = 10;   // global 'index'

void f()
{
    char index = 'a';       // local index 1 — HIDES global int index
    std::cout << index << std::endl;

    for (int index = 0; index < 10; ++index)
    {                       // statement index — HIDES local index 1
        std::cout << index << std::endl;
    }

    {
        double index = 0.2; // local index 2 — HIDES local index 1
        std::cout << index << std::endl;
    }

    index = 'b';            // assigns to local index 1 (char)
}
```

**Step-by-step trace:**

|Location|`index` resolves to|Value printed|
|---|---|---|
|First `cout`|`char index = 'a'`|`a`|
|Inside `for`|`int index` (0–9)|`0 1 2 ... 9`|
|Inside inner `{}`|`double index = 0.2`|`0.2`|
|Final `index = 'b'`|`char index`|(assignment, no print)|

# 6. Initialization

## 6.1 Four Initialization Syntaxes

```cpp
T a1 {v};       // ✅ Brace-initialization (C++11) — RECOMMENDED
T a2 = {v};     // ✅ Copy brace-initialization
T a3 = v;       // ⚠️  Copy initialization (C++03 style)
T a4(v);        // ⚠️  Direct initialization (constructor syntax)
```

> [!tip] Always Prefer Brace-Initialization `{}` Brace-initialization was introduced in **C++11** and is the recommended modern style because it **prevents narrowing conversions** at compile time.

## 6.2 Narrowing Prevention

> [!danger] Narrowing Conversion — Compile Error with `{}` A **narrowing conversion** silently truncates or loses data (e.g., assigning a `double` to an `int`). Brace-initialization catches this at **compile time**.

```cpp
int a1 {0.2};   // ❌ COMPILATION ERROR: narrowing conversion from double to int
int a2 = 0.2;   // ⚠️  Compiles with a warning — value silently truncated to 0
int a3(0.2);    // ⚠️  Same silent truncation
```

## 6.3 Default Initialization with `{}`

```cpp
int x {};       // x = 0  (default initialized)
double d {};    // d = 0.0
bool b {};      // b = false
```

> [!tip] Use `{}` for Zero/Default Initialization An empty `{}` initializes a variable to its type's **default value** (zero for arithmetic types).

# 7. The `auto` Type Specifier

> [!info] Definition — `auto` The `auto` keyword instructs the compiler to **automatically deduce the type** of a variable from the type of its initializer. This is purely a compile-time feature — the type is always fully resolved before the program runs.

```cpp
int a1 = 2292;
auto a2 = 2292;   // compiler deduces: a2 is int
```

**Primary advantage — avoiding verbose type names:**

```cpp
// Without auto:
std::vector<int>::iterator a1 = vec.begin();

// With auto:
auto a1 = vec.begin();    // cleaner, same type
```

> [!danger] Do NOT use `{}` with `auto` Combining `auto` and brace-initialization creates a `std::initializer_list<T>`, not the scalar type you likely intended:
> 
> ```cpp
> auto x {42};    // x is std::initializer_list<int>, NOT int!
> auto y = 42;    // y is int ✅ — use = with auto
> ```

> [!warning] Limit `auto` to Small Scopes In large functions or complex code, `auto` makes it hard to understand what type a variable actually is during debugging and code review. **Use `auto` mainly in small, tightly-scoped blocks.**

# 8. Consistent Initialization

> [!important] Always Initialize Variables at Declaration Failing to initialize a variable leads to **undefined behavior** for local variables and heap objects. The behavior varies based on storage class:

```cpp
int globalVariable;    // means globalVariable{} → value is 0
                       // Valid for: static, global, namespace-scoped variables

void f()
{
    int localVariable; // ⚠️ NO well-defined value!
                       // Contains whatever garbage was in memory
}
```

> [!danger] Uninitialized Local Variables Local variables and heap-allocated objects (via `new`) have **no well-defined value** unless explicitly initialized — **unless** they are user-defined types with a default constructor (which auto-initializes member fields).
> 
> **Rule of thumb: always initialize every variable at the point of declaration.**

# 9. Objects

## 9.1 What is a C++ Object?

> [!info] Definition — C++ Object A C++ **object** is a **contiguous region of storage in memory**. An object has three defining characteristics:
> 
> 1. **Has identity** — the program has a name, pointer, or reference that uniquely identifies it.
> 2. **Is not movable** (in the classical sense) — you cannot move its value to another location and leave the original in an unspecified state; only **copying** is possible.
> 3. **Is referred to by an lvalue** (see §9.2).

## 9.2 lvalues and rvalues

> [!info] Definition — lvalue An **lvalue** (_locator value_) has a persistent identity in memory. It has a name/address and **cannot be implicitly moved**. It refers to an object that exists beyond the current expression.

> [!info] Definition — rvalue An **rvalue** is a temporary, movable value. It **may or may not** have identity, but it **is movable**. Typical examples: return values of functions, temporary objects.

||Has Identity|Is Movable|
|---|---|---|
|**lvalue**|Yes|No|
|**rvalue**|Depends|Yes|

```cpp
std::vector<int> vec1 {1, 2, 3};       // vec1 is an lvalue

auto vec2 = someFunction(vec1);
//   ^^^^    ^^^^^^^^^^^^^^^^^^^^^^^
// lvalue         rvalue (temporary returned by function)

auto vec3 = vec1;
//           ^^^^
//          lvalue (named variable)
```

**Key insight:** `someFunction(vec1)` produces a **temporary** result — an rvalue. The result is then used to initialize `vec2` (an lvalue).

---

## 9.3 Object Lifetime

> [!info] Definition — Object Lifetime An object's **valid lifetime** runs from the completion of its constructor to the start of its destructor. C++ defines several lifetime categories:

|Category|When Created|When Destroyed|
|---|---|---|
|**Automatic**|At explicit initialization|When it goes out of scope|
|**Static**|At program start|When program terminates|
|**Free store**|Explicitly via `new`|Explicitly via `delete`|
|**`thread_local`**|When the thread starts|When the thread ends|
|**Temporary**|During expression evaluation|At end of the full expression|

```cpp
// Temporary object example:
std::cout << std::string("tmp").size() << std::endl;
//           ^^^^^^^^^^^^^^^^^^^
//           Temporary std::string object (rvalue)
//           Created, .size() called, then DESTROYED at end of statement
```

**Explanation:**

- `std::string("tmp")` creates a **temporary** (unnamed) `std::string` object → this is an **rvalue**.
- `.size()` is called on it immediately.
- The temporary is **destroyed** at the semicolon (end of the full expression).
- This is a classic example of a **temporary object with automatic lifetime**.

# 10. Type Aliases

> [!info] Definition — Type Alias A **type alias** creates a **synonym** (alternative name) for an existing type. The alias and the original type are fully interchangeable.

**Two syntaxes:**

```cpp
// Modern C++11 syntax (preferred):
using viter = std::vector<int>::iterator;

// Legacy C-style syntax:
typedef std::vector<int>::iterator viter;
```

**Usage example:**

```cpp
std::vector<int> vec = {1, 2, 3};

std::vector<int>::iterator a = vec.begin();   // verbose original type
viter b = a;                                   // using the alias — same type
```

> [!tip] Use `using` Over `typedef` The modern `using` syntax is clearer, especially with templates, and is the preferred form in C++11 and beyond.

# 11. `const` and `constexpr`

## 11.1 `const`

> [!info] Definition — `const` The `const` qualifier declares that an **object cannot be modified** after its initialization within its scope. It is a **compile-time contract** enforced by the compiler.

**Key rules:**

- A `const` variable **must be initialized** at the point of declaration (with one exception: `const` member variables of a class, initialized in the constructor).
- A `const` object can be **read** but never **written** after initialization.

**Common use case — read-only function arguments:**

```cpp
void printValue(const int x) {
    // x = 5;  ❌ COMPILE ERROR: cannot modify const parameter
    std::cout << x;  // ✅ reading is fine
}
```

## 11.2 `constexpr`

> [!info] Definition — `constexpr` The `constexpr` qualifier declares that an **expression or function can be evaluated at compile time** (not just at runtime). This enables optimizations and use in contexts that require compile-time constants (e.g., array sizes, template parameters).

**Valid `constexpr` operands:**

- Integer literals
- Floating-point literals
- Enum values
- Operators applied to the above
- Other `constexpr` expressions/functions

```cpp
constexpr int array_size = 10;         // evaluated at compile time
int arr[array_size];                    // valid: array size must be compile-time constant

constexpr double pi = 3.14159265358979;
constexpr double circle_area = pi * 5 * 5;  // all constexpr: computed at compile time
```

> [!tip] `const` vs `constexpr`
> 
> ||`const`|`constexpr`|
> |---|---|---|
> |Value fixed at|runtime (or compile time)|**compile time** (guaranteed)|
> |Purpose|prevent modification|enable compile-time computation|
> |Use for arrays/templates|❌ not guaranteed|✅ always valid|

# 12. Quick Reference — Key Takeaways

> [!tip] Summary of Best Practices from This Lecture
> 
> 1. **Always use brace-initialization `{}`** — prevents narrowing, avoids undefined behavior from uninitialized variables.
> 2. **Never rely on plain `char` signedness** — use `signed char` or `unsigned char` explicitly when it matters.
> 3. **Use `<cstdint>` types** (`int32_t`, `uint_fast32_t`) when portability of integer sizes matters.
> 4. **Avoid variable shadowing** — redeclaring names in nested scopes is legal but dangerous.
> 5. **Use `auto` with `=`, not `{}`** — `auto x {v}` creates an `initializer_list`, not a scalar.
> 6. **Use `const` for read-only semantics**, and `constexpr` when a value must be known at compile time.
> 7. **Follow naming conventions:** `PascalCase` for classes, `camelCase` for functions, `snake_case` for variables.
> 8. **One Definition Rule (ODR):** every name in a program must have exactly one definition.
