## Introduction: Streaming Model

**Typical scenario:** data arrives as a **continuous stream** because it is generated by evolving processes (tweets, financial orders, sensors) or because the massive volume discourages random accesses (sequential disk reads). Analysis must happen **on the fly** using limited memory, without storing all data for offline processing.

**Applications:**
- **Network management:** traffic statistics (e.g., average number of connections/second to the same IP)
- **Online auctions:** statistical estimates on auction data (average selling price, highest bid in a period)
- **Internet of Things:** outlier detection, learning from data generated by millions of sensors
- **Sequential disk access:** processing of massive files read sequentially; multiple passes are allowed (**multi-pass**)

### Formal Model

Sequential machine with **limited working memory** and input provided as a **continuous one-way stream**.

![[PLACEHOLDER_Fig_1 — diagram: "Input data stream" → "processor" ↔ "Limited working memory", outgoing "query" arrow]]

Let $\Sigma = x_1, x_2, \ldots, x_n, \ldots$ denote the **input stream**. Upon receiving $x_n$:
- **UPDATE task:** update the data structures stored in working memory
- **QUERY task:** compute the solution for $\{x_1, \ldots, x_n\}$ from the data in memory

**Key Performance Indicators (KPI):**

| KPI | Parameter | Goal |
|-----|-----------|------|
| KPI 1 | Size $s$ of working memory | $s \ll |\Sigma|$ |
| KPI 2 | Number $p$ of sequential passes over $\Sigma$ | $p = 1$ |
| KPI 3 | Update time $T_u$ per item | $T_u = O(1)$ |
| KPI 4 | Query time $T_q$ | independent of $n$ |

### Algorithm Design Techniques

- **Approximate solutions:** exact ones may require excessive space
- **Synopsis data structure:** lossy summary of the stream kept in memory (e.g., random sample, hash-based sketch)

**Typical tasks:** frequent items, frequency moments, quantiles, histograms, clustering, triangle counting.

**Goal:** suitable tradeoffs between accuracy, working memory, and throughput (update/query time).

## Warm-up: Finding the Majority Element

> [!Important] Majority Problem
> Given a stream $\Sigma = x_1, x_2, \ldots, x_n$, return the element $x$ (if any) that occurs $> n/2$ times in $\Sigma$.
>
> **Intuition:** find an element with absolute dominance in the sequence.

**Examples:**
- $\Sigma = A, B, A, C, A, D, A, A$ → majority: $A$
- $\Sigma = A, B, C, D, D, E, E$ → no majority element exists

**Offline:** solvable in $O(n \log n)$ (sorting) or $O(n)$ expected (hashing), using linear space.

**Streaming (1 or 2 passes):**
1. **1st pass** — *Boyer-Moore*: find candidate $x$ (which is the true majority, if one exists)
2. **2nd pass** (optional): verify whether $x$ actually occurs $> n/2$ times

### Boyer-Moore Algorithm

Maintains 2 integers: **cand** (candidate element) and **count** (counter).

**Initialization:** $\text{cand} \leftarrow \text{null}$, $\text{count} \leftarrow 0$

```
For each x_t in Σ do
  if count = 0 then {cand ← x_t; count ← 1}
  else {
    if cand = x_t then count ← count + 1
    else           count ← count − 1
  }
At the end: return cand
```

> [!Example] Example 1: $\Sigma = A, A, A, C, C, B, B, A, A$ (A is the majority)
> | Step | cand | count |
> |------|------|-------|
> | 0 | null | 0 |
> | 1 | A | 1 |
> | 2 | A | 2 |
> | 3 | A | 3 |
> | 4 | A | 2 |
> | 5 | A | 1 |
> | 6 | A | 0 |
> | 7 | B | 1 |
> | 8 | B | 0 |
> | 9 | A | 1 |
> **Result:** A — correct ✓

> [!Example] Example 2: $\Sigma = A, A, A, C, C, C, B, B, B$ (no majority)
> | Step | cand | count |
> |------|------|-------|
> | 0 | null | 0 |
> | 3 | A | 3 |
> | 6 | A | 0 |
> | 9 | B | 3 |
> **Result:** B — but no true majority exists (2nd pass needed to detect this) ✗

### Correctness Proof

> [!Important] Theorem: Boyer-Moore Correctness
> The Boyer-Moore algorithm is correct (returns the true majority if one exists) and requires:
> - Working memory $O(1)$
> - 1 pass (+ 1 optional for verification)
> - Update time $O(1)$, query time $O(1)$
>
> **Invariant:** For any $t \geq 0$, $x_1, \ldots, x_t$ can be partitioned into:
> - $\text{count}_t \geq 0$ occurrences of $\text{cand}_t$
> - $\dfrac{t - \text{count}_t}{2}$ pairs $(e_1, e_2)$ with $e_1 \neq e_2$
>
> *(proof by induction — exercise)*
>
> **Proof of correctness (by contradiction):**
> Let $m$ be the true majority. Suppose $\text{cand}_n \neq m$.
> By the invariant at $t = n$, element $m$ can occur at most $\dfrac{n - \text{count}_n}{2} \leq \dfrac{n}{2}$ times (since $\text{count}_n \geq 0$).
> This contradicts the assumption that $m$ occurs $> n/2$ times. $\square$

## Sampling

> [!Important] Definition: $m$-sample (Uniform Sampling)
> Given a set $X$ of $n$ elements and $1 \leq m < n$, an **$m$-sample** is a random subset $S \subset X$, $|S| = m$, such that:
> $$\forall x \in X: \quad \Pr(x \in S) = \frac{m}{n}$$
> (uniform sampling without replacement)

**Offline:** straightforward — select $m$ indices with uniform probability.

**Streaming:** harder, especially for potentially unbounded streams where at every step a random sample of the elements seen so far is required.

> [!Important] Sampling Problem
> Given a (possibly unbounded) stream $\Sigma = x_1, x_2, \ldots$ and an integer $m$, maintain for every $t \geq m$ an $m$-sample $S$ of the prefix $\Sigma_t = x_1, \ldots, x_t$.

### Reservoir Sampling

Algorithm by **J.S. Vitter (1985)**. Does not require knowledge of the stream size.

**Initialization:** $S \leftarrow \emptyset$

```
For each x_t in Σ do
  if t ≤ m then add x_t to S
  else with probability m/t:
    evict a uniform random element from S
    add x_t to S
```

![[PLACEHOLDER_Fig_2 — reservoir evolution for m=6: rows of red circles (in S) and blue circles (not sampled), green arrows mark current position in the stream]]

> [!Important] Theorem: Reservoir Sampling Correctness
> For any $t \geq m$, the set $S$ maintained by the algorithm is an $m$-sample of $\Sigma_t$. Update time is $O(1)$.
>
> **Proof (by induction on $t \geq m$):**
>
> *Claim:* $\forall i \in [1,t]: P(x_i \in S_t) = m/t$
>
> **Base case** $t = m$: all first $m$ elements are in $S$, so $P(x_i \in S_m) = 1 = m/m$. ✓
>
> **Inductive step:** Assume $\forall i \in [1,t-1]: P(x_i \in S_{t-1}) = \frac{m}{t-1}$
>
> Let $A$ = "event: $x_t$ is added to $S_t$", with $P(A) = m/t$.
>
> For $x_t$: $P(x_t \in S_t) = m/t$ by construction. ✓
>
> For $x_i$ with $i < t$, by the law of total probability:
> $$P(x_i \in S_t) = P(x_i \in S_t \mid A)\cdot P(A) + P(x_i \in S_t \mid \neg A)\cdot P(\neg A)$$
>
> **Term (1):** $P(x_i \in S_t \mid A) = \underbrace{\frac{m}{t-1}}_{\text{ind. hyp.}} \cdot \underbrace{\left(1-\frac{1}{m}\right)}_{\text{not evicted}}$, so:
> $$(1) = \frac{m}{t-1}\cdot\frac{m-1}{m}\cdot\frac{m}{t}$$
>
> **Term (2):** $P(x_i \in S_t \mid \neg A) = \frac{m}{t-1}$ (inductive hypothesis), so:
> $$(2) = \frac{m}{t-1}\cdot\left(1-\frac{m}{t}\right)$$
>
> Summing both terms:
> $$P(x_i \in S_t) = \frac{m}{t-1}\left(\frac{m}{t}-\frac{1}{t}+1-\frac{m}{t}\right) = \frac{m}{t-1}\cdot\frac{t-1}{t} = \frac{m}{t} \quad \square$$

### Frequent Items

> [!Important] Frequent Items Problem
> Given $\Sigma = x_1, \ldots, x_n$ over universe $U$ and frequency threshold $\varphi \in (0,1)$, determine all distinct items occurring at least $\varphi \cdot n$ times in $\Sigma$.

> [!Example] Example: Frequent Items
> $n = 100$, $\varphi = 0.3$: $A$: 30, $B$: 30, $C$: 20, $D$: 10, $E$: 10
> → Frequent Items $= \{A, B\}$

**Observations:**
1. The number of frequent items is $\leq 1/\varphi$
2. **Exact strategy:** maintain a Hash Table $T$ counting occurrences of every distinct item; at the end return all with $\geq \varphi \cdot n$ occurrences
   - **Weakness:** if the number of distinct items $\bar{n} \approx n$ but $1/\varphi \ll n$, space and time proportional to $\bar{n}$ are unavoidable with the exact approach

**Approximation via Reservoir Sampling:**
1. Extract an $m$-sample $S$ (an item may appear multiple times)
2. Return $S'$ = set of distinct items in $S$

If $m \geq 1/\varphi$: every frequent item $a$ is expected to appear at least once in $S$.
Limitations: **false negatives** (missed frequent items) and **false positives** (low-frequency items included) are possible.

### ε-Approximate Frequent Items (ε-AFI)

> [!Important] ε-AFI Problem
> Given $\Sigma$, threshold $\varphi \in (0,1)$, and accuracy parameter $\varepsilon \in (0,\varphi)$, return a set of distinct items that:
> - **includes all** items with frequency $\geq \varphi \cdot n$ (**no false negatives**)
> - **contains no** item with frequency $< (\varphi - \varepsilon) \cdot n$ (**no deep false positives**)
>
> **Intuition:** false positives are tolerated only in the grey band $[(\varphi-\varepsilon)n,\ \varphi n)$.

![[PLACEHOLDER_Fig_3 — number line [0,1]: "forbidden" zone [0, φ-ε], "tolerated" zone [φ-ε, φ], "target" zone [φ, 1]]]

> [!Example] Example: ε-AFI
> $n=100$, $\varphi=0.3$, $\varepsilon=0.1$: $A$:30, $B$:30, $C$:20, $D$:10, $E$:10
> - Legal outputs: $\{A,B\}$ or $\{A,B,C\}$
> - $D$ and $E$ must never be included

### Sticky Sampling

**Sticky Sampling** provides a probabilistic solution to ε-AFI. **Requires $n$ to be known.**

**Main ingredients:**
- Confidence parameter $\delta \in (0,1)$
- Hash Table $S$ with entries $(x,\ f_e(x))$: $f_e(x)$ is a *lower bound* on the number of occurrences of $x$ seen so far
- Sampling rate $r/n$ where:
$$r = \left\lceil\frac{\ln(1/(\delta\varphi))}{\varepsilon}\right\rceil$$

**Algorithm:**

```
Initialization: S ← empty Hash Table
r = ⌈ln(1/(δφ))⌉ / ε   // sampling rate = r/n

For each x_t in Σ do
  if (x_t, f_e(x_t)) ∈ S then f_e(x_t) ← f_e(x_t) + 1
  else add (x_t, 1) to S with probability r/n

At the end: return all x in S with f_e(x) ≥ (φ − ε)n
```

> [!Important] Theorem: Sticky Sampling
> Sticky Sampling solves ε-AFI correctly with probability $\geq 1-\delta$ and requires:
> - Working memory $O(r) = O\!\left(\dfrac{\ln(1/(\delta\varphi))}{\varepsilon}\right)$ in expectation — **independent of $n$**
> - 1 pass, update time $O(1)$ in expectation, query time $O(r)$ in expectation
>
> For fixed $\delta$, $\varepsilon$, the sampling rate is $o\!\left(\dfrac{1}{\varphi n}\right)$: smaller than that required by Reservoir Sampling.
>
> **Proof (sketch):**
>
> *Memory size:* each $x_t$ creates a new entry with probability $\leq r/n$. Let $X_t = \mathbf{1}[x_t \text{ creates a new entry}]$:
> $$\mathbb{E}[|S|] = \sum_{t=1}^{n} \mathbb{E}[X_t] \leq n \cdot \frac{r}{n} = r \implies \text{memory } O(r)$$
>
> *Property (B) — no deep false positives:* immediate by construction; only items with $f_e(x) \geq (\varphi-\varepsilon)n$ are returned, and $f_e$ is always a lower bound on the true frequency.
>
> *Property (A) — all frequent items returned with probability $\geq 1-\delta$:*
>
> Let $a$ be a true frequent item. Since $a$ occurs $\geq \varphi n > \varepsilon n$ times, it suffices that at least one of its first $\lceil\varepsilon n\rceil$ occurrences is sampled:
> $$P(a \text{ not returned}) \leq \left(1-\frac{r}{n}\right)^{\varepsilon n} \leq e^{-\varepsilon r}$$
>
> Let $a_1,\ldots,a_k$ be all true frequent items, with $k \leq 1/\varphi$. By **union bound**:
> $$P(\exists\, a_i \text{ not returned}) \leq k \cdot e^{-\varepsilon r} \leq \frac{1}{\varphi}\cdot e^{-\varepsilon \cdot \frac{\ln(1/(\delta\varphi))}{\varepsilon}} = \frac{1}{\varphi}\cdot\delta\varphi = \delta$$
> $$\implies P(\text{all frequent items returned}) \geq 1 - \delta \quad \square$$

### Extension to Unknown n

For unbounded streams ($n$ unknown), a **dynamic sampling rate** is used:

- $\Sigma$ is divided into **batches** $B_0, B_1, \ldots$ with $|B_i| = 2^i \cdot r$
- For batch $B_i$: sampling rate $= 1/2^i$ (geometrically decreasing)
- The hash table $S$ is recalibrated after each batch
