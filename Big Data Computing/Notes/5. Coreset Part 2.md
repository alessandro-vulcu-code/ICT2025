# k-center as a coreset primitive

---

## Diameter

The **diameter** of a set $P$ of $N$ points from a metric space $(M, d)$ is the **maximum distance between two points**, i.e.,

$$\Delta(P) = \max_{x,y \in P} d(x, y).$$

**Many applications, e.g.:**
- **Shape analysis:** used in computational geometry, visualization, robotics
- **Network analysis:** used in social network analysis, biology, etc.

> *Intuitively, the diameter is the length of the longest "segment" that can be drawn connecting two points of the set $P$.*

---

### Exact diameter computation

Sadly, the computation of the exact diameter **requires almost quadratic operations** (except for special cases such as low-dimensional Euclidean spaces), hence it is **impractical for large, high-dimensional pointsets**.

> [!note] **Exercise**
> Design an MR algorithm to compute the exact diameter of a set $P$ of $N$ points, which requires $R = O(1)$, $M_L = O\!\left(\sqrt{N}\right)$ and $M_A = O(N^2)$.

---

### 2-approximation to the diameter

For an arbitrary $x \in P$, define

$$\Delta_x = \max\{d(x, y) : y \in P\}.$$

> [!abstract] **Lemma**
> For any $x \in P$ we have $\Delta(P) \in [\Delta_x,\, 2\Delta_x]$.

> [!quote] **Proof**
> - **$\Delta(P) \geq \Delta_x$:** since $\Delta(P)$ is the maximum distance over *all* pairs of points, while $\Delta_x$ is the maximum distance over all pairs that *include $x$*.
>
> - **$\Delta(P) \leq 2\Delta_x$:** let $z, w$ be such that $\Delta(P) = d(z, w)$. Then, by the **triangle inequality**:
>
> $$\Delta(P) = d(z, w) \leq d(z, x) + d(x, w) \leq 2\Delta_x. \quad \square$$

> [!note] **Exercise**
> Show that for any arbitrary $x \in P$, the value $\Delta_x$ can be computed in MapReduce using 2 rounds, $M_L = O\!\left(\sqrt{N}\right)$ and $M_A = O(N)$.

---

### Better, coreset-based diameter approximation

**Coreset-based approximation:**

- Fix a suitable $k \geq 2$.
- Extract a **coreset** $T \subseteq P$ of size $k$ by running a k-center clustering algorithm on $P$ and taking the $k$ returned centers as set $T$.
- Return $\Delta(T) = \max_{x,y \in T} d(x, y)$ as an approximation of $\Delta(P)$.

**Can the approximation be computed efficiently?**

If $k = O(1)$, $\Delta(T)$ can be computed:
- **Sequentially:** in $O(N)$ time (using Farthest-First Traversal)
- **In MapReduce:** in 2 rounds, with local space $M_L = O\!\left(\sqrt{N}\right)$ and aggregate space $M_A = O(N)$ (through MR-Farthest-First Traversal)

**Is $\Delta(T)$ a good approximation of $\Delta(P)$?**

---

#### Approximation quality analysis

Let $R$ denote the **radius of the k-center clustering** (i.e., the maximum distance from any point to its closest center in $T$). Consider:

- $T = \{c_1, c_2, \ldots, c_k\}$ — the set of centers
- $\Delta(P) = d(z, w)$ — the true diameter, achieved by the pair $(z, w)$
- $c_i$ = center of $T$ closest to $z$
- $c_j$ = center of $T$ closest to $w$

Since every point is within distance $R$ from its closest center:

$$\Delta(P) = d(z, w) \leq d(z, c_i) + d(c_i, c_j) + d(c_j, w) \leq 2R + d(c_i, c_j) \leq 2R + \Delta(T)$$

Therefore:

$$\boxed{\Delta(T) \leq \Delta(P) \leq \Delta(T) + 2R}$$

The left inequality holds because $T \subseteq P$; the right inequality follows from the above derivation.

---

#### Observations on the approximation

- $R$ provides a **quantitative estimate of the quality** of the approximation, and it can be easily computed while determining the coreset $T$.
- $R$ is **non-increasing with $k$**. Moreover, for low-dimensional datasets it can be shown that $R$ **decreases sharply as $k$ increases**.
- Suppose that $k$ is chosen so that $R \leq \varepsilon \cdot d(c_1, c_2)$ where $\varepsilon \in (0, 1)$ is an accuracy parameter. Then:

$$\Delta(P) \leq \Delta(T) + 2R \leq \Delta(T) + 2\varepsilon \cdot \Delta(T) = (1 + 2\varepsilon)\,\Delta(T)$$

As $\varepsilon \to 0$, **the approximation ratio tends to $1$**.

## Diversity maximization

**Objective:** Determine the **most diverse subset of size $k$** (for a given small $k$) from a dataset.

**Applications:**

| Domain | Use case |
|---|---|
| **Aggregator websites** (e.g., Google News) | Selection of documents for home page; diversified set of representative docs |
| **E-commerce** | Selection of *consideration set*: products returned by portal upon user query; diversity correlates to user satisfaction |
| **Facility location** | Selection of non-competing franchise store locations; selection of strategic facility locations (to avoid simultaneous attacks) |

---

### Formal definition of the problem

> [!abstract] **Definition — Diversity Maximization Problem (max-sum / remote clique variant)**
> Given a set $P$ of points from a metric space $(M, d)$ and a positive integer $k < |P|$, return a subset $S \subset P$ of $k$ points which **maximizes** the diversity function
>
> $$\operatorname{div}(S) = \sum_{x,y \in S} d(x, y).$$
>
> There are $\binom{k}{2}$ terms in the sum. The problem is also called **MIN-SUM DIVERSIFICATION**.

**Observations:**
- **NP-hard** problem.
- A $c$-approximation algorithm is known with $c = 2 - 2/k$, which however requires **quadratic time** (impractical for large inputs!).
- **Other variants:** different functions $\operatorname{div}(\cdot)$ to maximize (all NP-hard).

---

### Coreset-based approach to diversity maximization

For a given input $P$, define the value of the optimal solution as:

$$\operatorname{div}^{\text{opt}}(P, k) = \max_{S \subseteq P,\, |S|=k} \operatorname{div}(S).$$

Can we extract a good solution from a small coreset $T \subset P$? **Yes**, as long as $T$ is a *good coreset*. The quality of a coreset is quantified as follows.

> [!abstract] **Definition — $(1+\varepsilon)$-coreset for Diversity Maximization**
> Let $\varepsilon \in (0, 1)$ be an accuracy parameter. A subset $T \subset P$ is a **$(1+\varepsilon)$-coreset** for the diversity maximization problem on $P$ if
>
> $$\operatorname{div}^{\text{opt}}(T, k) \geq \frac{1}{1+\varepsilon}\,\operatorname{div}^{\text{opt}}(P, k).$$

**Observation:** Since we are solving a maximization problem, **the smaller $\varepsilon$, the better** the optimal solution in $T$ approximates the optimal solution in $P$.

Note that for any $T$ we have $\operatorname{div}^{\text{opt}}(T, k) \leq \operatorname{div}^{\text{opt}}(P, k)$, so a $(1+\varepsilon)$-coreset is a subset that *nearly* achieves the full optimum.

---

#### Key implication of the coreset definition

The definition implies that: if $T$ is a $(1+\varepsilon)$-coreset and $S$ is a $c$-approximation to the optimal solution for diversity maximization **on $T$**, then $S$ is a $c(1+\varepsilon)$-approximation to the optimal solution for diversity maximization **on $P$**. That is:

$$\operatorname{div}(S) \geq \frac{1}{c(1+\varepsilon)}\,\operatorname{div}^{\text{opt}}(P, k).$$

*Observation: although we think of $\varepsilon$ as small, it can be $> 1$.*

---

#### Fact: relation between k-center and diversity maximization

> [!abstract] **Fact**
> $$\Phi^{\text{opt}}_{\text{kcenter}}(P, k) \leq \frac{\operatorname{div}^{\text{opt}}(P, k)}{\binom{k}{2}}$$

This property is crucially exploited by the coreset-based approach described below.

---

### High-level coreset-based algorithm

**Given $P$ and $k$:**

1. Extract a set $W \subseteq P$ of $h > k$ centers, using **Farthest-First Traversal**, for a suitable $h > k$.
2. Let $P = C_1 \cup C_2 \cup \cdots \cup C_h$ be the **clustering induced by $W$**.
3. Compute a coreset $T$ of size $\leq h \cdot k$ selecting $\max\{k, |C_i|\}$ points from each $C_i$ *(including the center)*, for $1 \leq i \leq h$.
4. Compute the **final solution $S$** by running the best sequential algorithm for diversity maximization on $T$.

**Questions:** Is this approach effective? What is a good choice for $h$?

**Example ($k=3$, $h=5$):** We will have 5 clusters $C_1, \ldots, C_5$, each with center $c_i$ and clustering radius $R$. The coreset $T = h \cdot k$ points, obtained by selecting from each cluster:
- The **center**
- **$k - 1$ additional points**

---

#### Why the algorithm works — key idea

> [!quote] **Argument**
> Let $S^*$ = optimal solution to diversity maximization on $P$ (the $k$ points that maximize $\operatorname{div}(\cdot)$).
>
> **Crucial observation:** We select $k$ points from each cluster to be included in $T$, and a cluster cannot contain more than $k$ points of $S^*$. This implies:
>
> $$\forall x \in S^*\ \exists \text{ a distinct proxy } \tau(x) \in T \text{ which belongs to the same cluster as } x.$$
>
> Therefore $d(x, \tau(x)) \leq 2R$ (by triangulating with the center of the cluster).
>
> Now, if $R$ is **very small**, the set $S = \{\tau(x) : x \in S^*\} \subseteq T$ contains $k$ points which are a good *"image"* of $S^*$ in $T$. Intuitively, $\operatorname{div}(S)$ would not be too far from $\operatorname{div}(S^*)$, and since $S \subseteq T$, we have $\operatorname{div}(S) \leq \operatorname{div}^{\text{opt}}(T, k)$.
>
> Indeed, it can be shown that if
>
> $$R \leq \frac{1}{8}\,\Phi^{\text{opt}}_{\text{kcenter}}(P, k)$$
>
> then (using the previous Fact):
>
> $$\operatorname{div}(S) \geq \frac{1}{2}\,\operatorname{div}^{\text{opt}}(P, k).$$
>
> Thus $\operatorname{div}^{\text{opt}}(T, k) \geq \operatorname{div}(S) \geq \frac{1}{2}\,\operatorname{div}^{\text{opt}}(P, k)$, **proving that $T$ is a 2-coreset** (i.e., a $(1+\varepsilon)$-coreset with $\varepsilon = 1$).
>
> In general, making $R$ even smaller makes the quality of $T$ even better (i.e., smaller $\varepsilon$).

# k-means/median

---

## Definition of the problems

Given a pointset $P$ of $N$ points from a metric space $(M, d)$, determine a set $S \subseteq P$ of $k$ *centers* which minimizes:

$$\Phi_{\text{kmeans}}(P, S) = \sum_{x \in P} (d(x, S))^2 \qquad \text{(k-means)}$$

$$\Phi_{\text{kmedian}}(P, S) = \sum_{x \in P} d(x, S) \qquad \text{(k-median)}$$

where $d(x, S) = \min_{s \in S} d(x, s)$ is the distance from $x$ to its closest center.

**Observation:** depending on the application and/or the algorithm used, the requirement that $S$ be a subset of $P$ may be lifted, and the centers can be allowed to be arbitrary points of $M$.

---

## Current popular algorithms for k-means/median

### Lloyd's algorithm (a.k.a. "k-means algorithm")

- **APPLICABILITY.** Used only for k-means when $M = \mathbb{R}^D$, $d(\cdot,\cdot)$ is the standard Euclidean distance ($L_2$-distance), and centers can be selected outside $P$.
- **ACCURACY.** If initial centers are selected well (e.g., through k-means++) it usually provides good solutions, but if not, it may be trapped into local optima.
- **EFFICIENCY.** Efficient implementations are provided by most common software packages, but a limit on the number of iterations is needed in case of very slow convergence.
- **SUITABILITY FOR MASSIVE INPUTS.** Yes if data can be processed by a distributed platform and only few iterations are executed. However, it is **not suitable to process data streams**.

---

### k-means++ algorithm *(Arthur & Vassilvitskii, 2007)*

```
c₁ ← random point chosen from P with uniform probability
S ← {c₁}
for 2 ≤ i ≤ k do
    foreach x ∈ P − S do
        π(x) ← (d(x,S))² / Σ_{y∈P−S}(d(y,S))²
    cᵢ ← random point in P − S according to distribution π(·)
    S ← S ∪ {cᵢ}
return S
```

*Observation: $S$ is a **random variable**!*

k-means++ is a **randomized algorithm**. It is known that in expectation, the returned solution is an $\alpha$-approximation, with $\alpha = \Theta(\ln k)$. More precisely:

$$\mathbb{E}\!\left[\Phi_{\text{kmeans}}(P,S)\right] \leq \alpha \cdot \Phi^{\text{opt}}_{\text{kmeans}}(P, k)$$

where the expectation is over the distribution of $S$.

- **APPLICABILITY.** Can be used for both k-means and k-median, and enforces $S \subseteq P$.
- **ACCURACY.** Provides decent solutions, but it is often useful to refine them (e.g., with Lloyd's) to get better accuracy.
- **EFFICIENCY.** Very easy and efficient implementation.
- **SUITABILITY FOR MASSIVE INPUTS.** Yes if data can be processed by a distributed platform and $k$ is small. However, it is **not suitable to process data streams**.

---

### Partitioning Around Medoids (PAM) algorithm *(a.k.a. k-medoids)*

Devised by Kaufman and Rousseeuw in 1987. Based on a **local search strategy** which starts from an arbitrary solution $S$ and progressively improves it by performing the best swap between a point in $S$ and a point in $P - S$, until no improving swap exists.

- **APPLICABILITY.** Mainly used for k-median, and enforces $S \subseteq P$.
- **ACCURACY.** Provides good solutions.
- **EFFICIENCY.** Very slow since each iteration requires checking about $N \cdot k$ possible swaps and the convergence can be very slow.
- **SUITABILITY FOR MASSIVE INPUTS.** **Not at all!**

---

#### Summary comparison

| Algorithm | k-means | k-median | $S \subseteq P$ | Massive inputs |
|---|:---:|:---:|:---:|:---:|
| Lloyd's | yes | no | Optional | Partial |
| k-means++ | yes | yes | yes | Partial |
| PAM | no | yes | yes | no |

*From now on we focus on **k-means** (what we say applies as well to k-median with very minor adaptations).*

---

## Coreset-based approach for k-means/median

The **composable coreset technique** can be employed to devise k-means/median algorithms which are able to:
1. Handle **massive data** (in a distributed setting)
2. Provide **good accuracy**

The input $P$ is partitioned into $\ell$ subsets $P_1, P_2, \ldots, P_\ell$. For each partition $P_i$:
- A **local coreset $T_i$** is computed using a sequential algorithm for k-means/median.
- Each point $x \in T_i$ is given a **weight** $w(x) =$ the number of points in $P_i$ for which $x$ is the closest representative in $T_i$.

The local coresets are gathered into $T = \bigcup_i T_i$ (***weighted***), and the **final solution $S$** is computed using a sequential algorithm for k-means/median, adapted to handle weights.

---

### Weighted k-means clustering

> [!abstract] **Definition — Weighted k-means problem**
> **Input:**
> - Set $P$ of $N$ points from $\mathbb{R}^D$.
> - Integer weight $w(x) > 0$ for every $x \in P$.
> - Target number $k$ of clusters.
>
> **Output:** Set $S$ of $k$ centers in $\mathbb{R}^D$ minimizing
>
> $$\Phi^w_{\text{kmeans}}(P, S) = \sum_{x \in P} w(x) \cdot (d(x, S))^2.$$
>
> **Observations:**
> - This formulation **allows centers outside $P$**.
> - If $w(x) = 1$ for every $x \in P$ we have the **standard k-means clustering problem**.

---

### MR-kmeans($\mathcal{A}_1, \mathcal{A}_2$)

**Input:** Set $P$ of $N$ points in $\mathbb{R}^D$, integer $k > 1$, sequential k-means algorithms $\mathcal{A}_1$ and $\mathcal{A}_2$ such that:
- $\mathcal{A}_1$ solves the **standard variant without weights**
- $\mathcal{A}_2$ solves the **more weighted variant**
- Both $\mathcal{A}_1$ and $\mathcal{A}_2$ require space proportional to the input size

*Observation: $\mathcal{A}_2$ can be used (with unit weights) in place of $\mathcal{A}_1$.*

**Output:** Set $S$ of $k$ centers in $\mathbb{R}^D$ which is a good solution to the k-means problem on $P$.

#### Round 1

- **Map Phase:** Partition $P$ arbitrarily in $\ell$ subsets of equal size $P_1, P_2, \ldots, P_\ell$.
- **Reduce Phase:** for every $i \in [1, \ell]$ separately, run $\mathcal{A}_1$ on $P_i$ to determine a set $T_i \subseteq P_i$ of $k$ centers, and define:
  - For each $x \in P_i$: the **proxy** $\tau(x)$ as $x$'s closest center in $T_i$.
  - For each $y \in T_i$: the **weight** $w(y)$ as the number of points of $P_i$ whose proxy is $y$.

#### Round 2

- **Map Phase:** empty.
- **Reduce Phase:** run $\mathcal{A}_2$ on $T = \bigcup_{i=1}^{\ell} T_i$ (with the given weights) to determine a set $S = \{c_1, c_2, \ldots, c_k\}$ of $k$ centers, which is then returned as output.

*Illustration: each partition $P_i$ independently produces $k$ local centers (green points). Each non-center point maps to its closest local center as its proxy, and each center accumulates the weight of all points mapped to it. Round 2 then runs on the aggregated weighted set $T$.*

---

### Analysis of MR-kmeans: performance

Assume $k \leq \sqrt{N}$. By setting $\ell = \sqrt{N/k}$, it is easy to see that MR-kmeans$(\mathcal{A}_1, \mathcal{A}_2)$ requires:

- **Local space** $M_L = O\!\left(\max\{N/\ell,\, \ell \cdot k\}\right) = O\!\left(\sqrt{N \cdot k}\right) = o(N)$
- **Aggregate space** $M_A = O(N)$

---

### Analysis of MR-kmeans: accuracy

To analyze the quality of the solutions computed by MR-kmeans$(\mathcal{A}_1, \mathcal{A}_2)$ we need to introduce the following notion:

> [!abstract] **Definition — $\gamma$-coreset for k-means**
> Given a pointset $P$, a coreset $T \subseteq P$ and a proxy function $\tau : P \to T$, we say that $T$ is a **$\gamma$-coreset** for $P$, $k$ and the k-means objective if
>
> $$\sum_{p \in P} (d(p,\, \tau(p)))^2 \leq \gamma \cdot \Phi^{\text{opt}}_{\text{kmeans}}(P, k).$$

*Visually: the sum of squared distances from $P \setminus T$ to $T$ is at most $\gamma \cdot \Phi^{\text{opt}}_{\text{kmeans}}(P, k)$.*

---

> [!abstract] **Theorem — Accuracy of MR-kmeans**
> Suppose that:
> - $\mathcal{A}_1$ is a $\gamma$-approximation algorithm for the **unweighted** k-means problem;
> - $\mathcal{A}_2$ is an $\alpha$-approximation algorithm for the **weighted** k-means problem.
>
> Then:
> - The coreset $T$ computed in Round 1 is a **$\gamma$-coreset**.
> - The solution $S$ computed in Round 2 is such that
>
> $$\Phi_{\text{kmeans}}(P, S) = O\!\left((1 + \gamma) \cdot \alpha\right) \cdot \Phi^{\text{opt}}_{\text{kmeans}}(P, k).$$
>
> *(Proof skipped. See [MPP19].)*

---

### Observations on MR-kmeans($\mathcal{A}_1, \mathcal{A}_2$)

- For **k-means** (as well as for k-center and k-median), good coresets are obtained by combining solutions to the same problem on smaller partitions. However, this is **not always the case** for other problems (e.g., diameter, diversity maximization).
- In practice, the algorithm is **fast and accurate**.
- Typically, one could use **k-means++ as $\mathcal{A}_1$** in Round 1, and a **weighted version of k-means++ plus Lloyd's as $\mathcal{A}_2$** in Round 2.
- If $h > k$ centers are selected from each $P_i$ in Round 1 (e.g., through k-means++), the quality of $T$, hence the quality of the final clustering, **improves**. In fact, for low dimensional spaces, a $\gamma$-coreset $T$ with $\gamma \ll \alpha$ can be built in this fashion using a value $h$ not too large.

> Let $Q$ be the unit square in $\mathbb{R}^2$, with bottom-left corner $(0,0)$, and consider $Q$ subdivided into $c^2$ square *cells* of side $1/c$.
>
> Consider a set of points $P$ from $Q$ and a subset $T \subset P$ of $c^2$ points, which contains one point from each cell (assume one always exists). Let $d_{\max}(P)$ be the maximum pairwise distance between any 2 points of $P$ and $d_{\max}(T)$ the maximum pairwise distance between any 2 points of $T$. Quantify how well $d_{\max}(T)$ approximates $d_{\max}(P)$.

> [!note] **Exercise 4 — Weighted clusters / 2-round MapReduce**
> Let $P$ be a set of $N$ weighted points partitioned into $k$ clusters $C_1, C_2, \ldots, C_k$ with respective centers $c_1, c_2, \ldots, c_k$. Each point $x \in P$ is represented by the pair $(x, (i_x, w_x))$, where $i_x$ is the index of the cluster of $x$, and $w_x$ is the weight of $x$. For every cluster $C_i$ its *weighted closest neighbor* is the cluster $C_j$, with $j \neq i$, which minimizes the following sum
>
> $$\sum_{x \in C_i} w_x \cdot d^2(x, c_j) \qquad (c_j \text{ center of } C_j).$$
>
> 1. Design an efficient **2-round MapReduce algorithm** that for each $1 \leq i \leq k$ computes the index $j$ of $C_i$'s closest neighbor. *(You can assume $k$ constant and that $c_1, \ldots, c_k$ are global variables.)*
> 2. Analyze the local and aggregate space required by your algorithm. For full score, your algorithm must require $o(N)$ local space and $O(N)$ aggregate space.

> [!note] **Exercise 5 — k-means++ probability boosting**
> Recall that k-means++ is a randomized algorithm and the quality of the solution is a random variable. Letting $S$ be the set of centers returned by k-means++ for $P$ it is known that there is a value $\alpha = \Theta(\ln k)$ such that
>
> $$\Pr\!\left(\Phi_{\text{kmeans}}(P, S) \leq \alpha \cdot \Phi^{\text{opt}}_{\text{kmeans}}(P, k)\right)\ \geq\ 1/2.$$
>
> Show that the above probability can be made $\geq 1 - 1/N$, if we run several *independent* instances of k-means++, and return the set of centers which yields the minimum value of the objective function, among the ones computed in the various runs.
