## Introduction

**Apache Spark** is an open-source framework for developing and running big data applications on clusters. Devised at *UC Berkeley* in 2009, later donated to the *Apache Software Foundation*.

Spark provides:

- **Spark Core:** unified computing engine handling task scheduling, optimization, and data abstractions.
- **Programming interface** for Scala, Java, Python, R (Spark itself is written in Scala).
- **APIs for data analysis:**
  - *Spark SQL* — structured data
  - *MLlib* — machine learning
  - *GraphX* — graph analytics
  - *Spark Streaming* — real-time streaming analytics

![[Spark-000.png]]

Spark runs on the **Java Virtual Machine (JVM)**.

---

## Main Features

- **In-memory caching:** enables efficient execution of multi-round algorithms — substantial improvement over Hadoop.
- **Fault tolerance.**
- **Optimized scheduling** of data transformations based on *DAGs* (*Directed Acyclic Graphs*).

**Spark can run on:**
- Single machine (*local mode*)
- Cluster managed by *Spark Standalone*, *YARN*, or *Mesos*

**Storage:** Spark does not include its own storage system; it operates on *HDFS*, *Amazon S3*, *Cassandra*, *HIVE*, relational DBMS, etc.

---

## Why Spark?

Goal: process **big data efficiently at moderate cost** by:

1. Pooling together resources of several inexpensive machines into one platform.
2. Managing and coordinating the execution of applications on such a platform.

> Without careful management and coordination, the potential of the platform is likely to be wasted.

## Spark Application Architecture

![[Spark-001.png]]

### Driver

The **driver** (a.k.a. *master*) is the heart of the application:

- Creates the **SparkContext** — an object acting as channel to all Spark functionalities.
  - *(Obs.: Spark 2.0.0 introduced **SparkSession**, which encapsulates SparkContext and provides more functionalities.)*
- Distributes tasks to executors.
- Monitors execution status.

Runs Java/Python/Scala/R code.

### Executors

**Executors** (a.k.a. *workers*) execute tasks assigned by the driver (via Scala code) and report their status back to the driver.

### Cluster Manager

When running on a distributed platform, the **cluster manager** controls physical machines (compute nodes) and allocates resources to applications.

### Execution Modes

| Mode | Description |
|------|-------------|
| **Local** | Driver and executors run as threads on a single machine |
| **Cluster** | Driver and executors can run on different machines |

**MapReduce tasks:** a task assigned to an executor typically comprises running a map function on several key-value pairs, or a reduce function on several key-listOfValues pairs.

> [!Important] Obs. on task execution
> 1. The code for map/reduce functions is executed **one pair at a time**.
> 2. Spark tries to assign map/reduce tasks to **minimize data movement** and to **optimize caching**.

## Resilient Distributed Dataset (RDD)

> [!Important] Definition — RDD
> **Fundamental abstraction** in Spark. An RDD is a collection of elements of the **same type**, partitioned and distributed across several machines (if available).
> An RDD provides a *coarse-grained* interface: transformations involve all data at once.
> RDDs ensure **fault-tolerance**.

![[Spark-002.jpg|500]]

---

### Main Characteristics

- RDDs are created:
  - from data in **stable storage** (e.g., HDFS), or
  - from **other RDDs** via transformations.
- RDDs are **immutable** (read-only) → consistency in multithreaded settings.
- RDDs use **lazy evaluation**: materialized only when an action is performed.
- Spark maintains the **lineage** of each RDD — the sequence of transformations that generated it — enabling materialization or reconstruction after failure, starting from stable storage.

---

### Partitioning

Each RDD is broken into chunks called **partitions** distributed among available machines.

- A program can specify the number of partitions (otherwise Spark chooses).
- Default partitioner: **HashPartitioner** (based on objects' hash codes); custom partitioners are also possible.
- **Typical number of partitions:** $2\times$ or $3\times$ the number of cores → helps balance the work.

Partitioning enhances performance:
- Spark creates map tasks so each executor applies the map function on **locally stored partitions** (if possible).
- Programmers can access partitions explicitly via `mapPartition`.
- Some ready-made Spark primitives exploit partitioning implicitly (e.g., `reduceByKey`).

---

### Operations

#### Transformations

A **transformation** generates a new RDD $Y$ from RDD $X$.

> [!Important] Narrow vs. Wide Transformations
>
> - **Narrow transformation:** each partition of $X$ contributes to **at most one** partition of $Y$, stored on the same machine. No shuffling needed → maximum parallelism. Example: `map`.
> - **Wide transformation:** each partition of $X$ may contribute to **many** partitions of $Y$. Shuffling across machines may be required. Example: `groupByKey`.

![[Spark-003.png]]
#### Actions

An **action** computes on the elements of $X$ and **returns a value** to the application. Example: `count()`.

> [!Important] Lazy Evaluation
> RDD $X$ is materialized **only when an action is performed**.
> This must be carefully considered when measuring running times.

#### Persistence

Methods `cache()` or `persist(storage-level)` save RDD data after the first action that materializes it.

| Method | Behavior |
|--------|----------|
| `cache()` = `persist(StorageLevel.MEMORY_ONLY)` | Store in RAM. Partitions not fitting in RAM are **recomputed** when needed. |
| `persist(StorageLevel.MEMORY_AND_DISK)` | Store in RAM. Partitions not fitting in RAM are stored on **disk** and retrieved from there. |

## Implementing MapReduce in Spark

Key points:

- Spark enables MapReduce algorithms but offers a **much richer** set of processing methods.
- Spark exploits a core idea of functional programming: *functions can be arguments to other functions*.
- A MapReduce program typically comprises:
  1. Spark configuration steps (e.g., context creation).
  2. Definitions of global variables and data structures (in driver memory).
  3. Reading of input data into one or more RDDs.
  4. Code for the various rounds.

**Implementing a round:**

- **Map Phase:** on input RDD $X$, invoke a map method (*narrow transformation*) passing the desired map function as argument.
- **Reduce Phase:** on $X'$ (result of Map Phase):
  1. Invoke a grouping method (*wide transformation*) → produces *key-ListOfValues* pairs.
  2. Invoke a map method applying the reduce function to each *key-ListOfValues* pair.

  Alternatively, use ready-made reduce primitives such as `reduceByKey`.

## DataFrames and Datasets

- **RDDs** — most basic data model: low-level, schema-less.
- On top of RDDs, the **Spark SQL** module provides:
  - **DataFrame:** distributed collection organized into named columns (like a table in a relational DB).
  - **Dataset:** extension of DataFrame (Java/Scala only) with type-safe, object-oriented interface.

*(Nota: in this course, only RDDs are used.)*

## Summary Table

| Concept | Description | Key Detail |
|---------|-------------|------------|
| **RDD** | Fundamental Spark abstraction | Immutable, lazy, fault-tolerant, partitioned |
| **Lineage** | Sequence of transformations generating an RDD | Enables reconstruction after failure |
| **Narrow transformation** | Each input partition → at most one output partition | No shuffle, max parallelism. E.g., `map` |
| **Wide transformation** | Each input partition → many output partitions | Requires shuffle. E.g., `groupByKey` |
| **Action** | Triggers materialization, returns value | E.g., `count()` |
| **Lazy evaluation** | RDD materialized only on action | Affects runtime measurement |
| **cache()** | Persist in RAM only | Unfit partitions recomputed |
| **persist(MEMORY\_AND\_DISK)** | Persist in RAM + disk fallback | Unfit partitions saved to disk |
| **Driver** | Orchestrates application | Creates SparkContext, schedules tasks |
| **Executor** | Runs assigned tasks | Reports status to driver |
| **Cluster Manager** | Allocates resources | Standalone / YARN / Mesos |
| **Partitions** | RDD chunks distributed across machines | Typical: 2×–3× number of cores |
| **DataFrame** | Named-column distributed collection | Part of Spark SQL |
| **Dataset** | Type-safe DataFrame (Java/Scala) | Extension of DataFrame |
