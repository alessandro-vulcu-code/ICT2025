## k-Center as a Coreset Primitive

### Diameter

> [!Important] Definition — Diameter
> The **diameter** of a pointset $P$ in metric space $(M, d)$ is:
> $$\Delta(P) = \max_{x,y \in P} d(x, y)$$
>
> **Intuizione:** largest pairwise distance in $P$.

**Applications:** shape analysis (computational geometry, robotics), network analysis (social networks, biology).

![[Coreset2-000.jpg]]
#### Exact Computation

Exact diameter computation requires **almost quadratic** operations (except for low-dimensional Euclidean spaces) → impractical for large, high-dimensional datasets.

*(Exercise: exact MR algorithm with $R = O(1)$, $M_L = O(\sqrt{N})$, $M_A = O(N^2)$.)*

#### 2-Approximation via a Single Point

For any arbitrary $x \in P$, define:
$$\Delta_x = \max\{d(x,y) : y \in P\}$$

> [!Important] Lemma — 2-Approximation of Diameter
> For any $x \in P$:
> $$\Delta(P) \in [\Delta_x,\ 2\Delta_x]$$
>
> **Dimostrazione:**
> - $\Delta(P) \geq \Delta_x$: diameter maximizes over all pairs, $\Delta_x$ only over pairs including $x$.
> - $\Delta(P) \leq 2\Delta_x$: let $z, w$ achieve $\Delta(P)$. By triangle inequality:
> $$\Delta(P) = d(z,w) \leq d(z,x) + d(x,w) \leq 2\Delta_x \quad\square$$

![[Pasted image 20260428114521.png]]

*(Exercise: compute $\Delta_x$ in MapReduce with 2 rounds, $M_L = O(\sqrt{N})$, $M_A = O(N)$.)*

#### Coreset-Based Diameter Approximation

**Algorithm:**
1. Fix $k \geq 2$.
2. Run a k-center algorithm on $P$ → extract $k$ centers as coreset $T$.
3. Return $\Delta(T)$ as approximation of $\Delta(P)$.

**Efficiency (for $k = O(1)$):**
- Sequential: $O(N)$ via FFT.
- MapReduce: 2 rounds, $M_L = O(\sqrt{N})$, $M_A = O(N)$ via MR-FFT.

**Quality:** Let $R = \Phi_{\text{kcenter}}(P, T)$ (radius of the k-center clustering used to build $T$). Let $c_i, c_j \in T$ be the centers closest to $z$ and $w$ (the diameter pair). By triangle inequality:

$$\Delta(P) = d(z,w) \leq d(z,c_i) + d(c_i,c_j) + d(c_j,w) \leq 2R + \Delta(T)$$

$$\Rightarrow \quad \boxed{\Delta(T) \leq \Delta(P) \leq \Delta(T) + 2R}$$
![[Pasted image 20260428130825.png]]

**Observations:**
- $R$ is computable while building $T$; it quantifies approximation quality.
- $R$ is non-increasing with $k$; for low-dimensional data it decreases sharply as $k$ grows.

**Accuracy parameter $\varepsilon$:** if $k$ is chosen so that $R \leq \varepsilon \cdot d(c_1, c_2)$ for some $\varepsilon \in (0,1)$:

$$\Delta(P) \leq \Delta(T) + 2R \leq \Delta(T) + 2\varepsilon\,\Delta(T) = (1+2\varepsilon)\,\Delta(T)$$

As $\varepsilon \to 0$, the approximation ratio tends to 1.

### Diversity Maximization

**Objective:** find the *most diverse* subset of size $k$ from a dataset.

![[Coreset2-003.jpg]]

**Applications:**
- *Aggregator websites (e.g., Google News):* select diverse representative documents for homepage.
- *E-commerce:* diversified product recommendations correlate with user satisfaction.
- *Facility location:* non-competing store locations; strategic facilities to avoid simultaneous attacks.

#### Formal Definition

> [!Important] Definition — Diversity Maximization (max-sum / remote clique)
> Given $P$ in metric space $(M,d)$ and integer $k < |P|$, find $S \subset P$, $|S|=k$, maximizing:
> $$\text{div}(S) = \sum_{x,y \in S} d(x,y) \qquad \left(\binom{k}{2} \text{ terms}\right)$$
>
> Also called **MIN-SUM DIVERSIFICATION**.
>
> **Properties:**
> - NP-hard.
> - Best known sequential approximation: $(2 - 2/k)$-approximation, but requires **quadratic time** (impractical for large inputs).
> - Other variants with different $\text{div}(\cdot)$ functions all NP-hard.

Define: $\text{div}^{\text{opt}}(P,k) = \max_{S \subset P,\, |S|=k} \text{div}(S)$.

#### (1+ε)-Coreset for Diversity

> [!Important] Definition — $(1+\varepsilon)$-Coreset for Diversity Maximization
> Let $\varepsilon \in (0,1)$. A subset $T \subset P$ is a **$(1+\varepsilon)$-coreset** if:
> $$\text{div}^{\text{opt}}(T, k) \geq \frac{1}{1+\varepsilon}\,\text{div}^{\text{opt}}(P, k)$$
>
> *(Note: always $\text{div}^{\text{opt}}(T,k) \leq \text{div}^{\text{opt}}(P,k)$ since $T \subseteq P$.)*
>
> **Implication:** if $T$ is a $(1+\varepsilon)$-coreset and $S$ is a $c$-approximation on $T$, then $S$ is a $c(1+\varepsilon)$-approximation on $P$:
> $$\text{div}(S) \geq \frac{1}{c(1+\varepsilon)}\,\text{div}^{\text{opt}}(P,k)$$
>
> **Obs.** Although $\varepsilon$ is usually thought of as small, it can be $> 1$.

> [!Important] Fact — Relation between k-center and Diversity
> $$\Phi^{\text{opt}}_{\text{kcenter}}(P,k) \leq \frac{\text{div}^{\text{opt}}(P,k)}{\binom{k}{2}}$$

#### Coreset-Based Algorithm

**High-level algorithm (given $P$ and $k$):**
1. Extract $W \subseteq P$ of $h > k$ centers using FFT (for suitable $h > k$).
2. Compute clustering $P = C_1 \cup \cdots \cup C_h$ induced by $W$.
3. Build coreset $T$ of size $\leq h \cdot k$: select $\min\{k, |C_i|\}$ points from each $C_i$ (including the center $c_i$).
4. Run best sequential $(2-2/k)$-approximation algorithm for diversity maximization on $T$ → return $S$.

> [!Example] Example: k=3, h=5
> Five clusters $C_1,\ldots,C_5$ with centers $c_1,\ldots,c_5$.
> From each cluster: 1 center + $k-1 = 2$ additional points → $|T| = h \cdot k = 15$.
> Radius of clustering = $R$.

![[Pasted image 20260428114730.png]]
#### Quality Analysis and Choice of h

**Key insight:** since $\min\{k, |C_i|\}$ points are selected from each cluster, **no cluster can contain more than $k$ points of $S^*$** (optimal solution). Therefore:

$\forall x \in S^*\ \exists$ a **distinct proxy** $\tau(x) \in T$ in the same cluster as $x$, with:
$$d(x, \tau(x)) \leq 2R \quad \text{(triangle inequality through cluster center)}$$

The set $S' = \{\tau(x) : x \in S^*\} \subseteq T$ is a "good image" of $S^*$ in $T$ when $R$ is small: intuitively, since $d(x, \tau(x)) \leq 2R$ is small, $\tau(x) \approx x$ and therefore $\text{div}(S') \approx \text{div}(S^*) = \text{div}^{\text{opt}}(P,k)$.

Since $S' \subseteq T$, by definition $\text{div}^{\text{opt}}(T,k) \geq \text{div}(S')$ (the optimal on $T$ is at least as good as any feasible solution on $T$).

> [!Important] Coreset Quality for Diversity
> If $R \leq \frac{1}{8}\,\Phi^{\text{opt}}_{\text{kcenter}}(P,k)$, then (using the Fact above):
> $$\text{div}^{\text{opt}}(T,k) \geq \text{div}(S') \geq \frac{1}{2}\,\text{div}^{\text{opt}}(P,k)$$
> The first inequality holds because $S' \subseteq T$; the second follows from the formal bound using the k-center ↔ diversity Fact and the condition on $R$.
>
> Hence $T$ is a **2-coreset** (i.e., $(1+\varepsilon)$-coreset with $\varepsilon = 1$).
>
> In general, smaller $R$ → smaller $\varepsilon$ → better approximation.

**Choice of $h$:** governs a tradeoff between accuracy and cost:
- Larger $h$ → smaller $R$ → better approximation, but larger $|T|$ → higher computation.
- In practice: pick $h$ near the **elbow point** of the quality-vs-$h$ curve.

## k-Means and k-Median Clustering

**Objectives (recall):**
$$\Phi_{\text{kmeans}}(P,S) = \sum_{x \in P}(d(x,S))^2, \qquad \Phi_{\text{kmedian}}(P,S) = \sum_{x \in P} d(x,S)$$

*(Note: in some formulations, centers can be arbitrary points of $M$, not necessarily $\in P$.)*

### Sequential Algorithms Overview

#### Lloyd's Algorithm

*(a.k.a. "k-means algorithm")*

| Property | Details |
|----------|---------|
| **Applicability** | k-means only; requires $M = \mathbb{R}^D$, Euclidean distance; centers can be outside $P$ |
| **Accuracy** | Good solutions if initialized well (e.g., k-means++); may trap in local optima otherwise |
| **Efficiency** | Efficient; limit on iterations needed for slow convergence cases |
| **Massive inputs** | Suitable if distributed + few iterations; **not** suitable for data streams |

#### k-means++ Algorithm

*(Arthur & Vassilvitskii, 2007)*

```
c₁ ← uniform random point from P;
S ← {c₁};
for i = 2 to k do
    for each x ∈ P − S: π(x) ← (d(x,S))² / Σ_{y∈P−S}(d(y,S))²;
    cᵢ ← random point from P−S according to π(·);
    S ← S ∪ {cᵢ};
return S
```

> [!Important] k-means++ Approximation Guarantee
> k-means++ is a **randomized algorithm** ($S$ is a random variable). In expectation:
> $$\mathbb{E}[\Phi_{\text{kmeans}}(P, S)] \leq \alpha \cdot \Phi^{\text{opt}}_{\text{kmeans}}(P, k), \quad \alpha = \Theta(\ln k)$$
>
> **Intuizione:** centers are selected with probability proportional to squared distance from current set, favoring spread — much better initialization than uniform random.

| Property | Details |
|----------|---------|
| **Applicability** | Both k-means and k-median; enforces $S \subset P$ |
| **Accuracy** | Decent; often refined afterwards |
| **Efficiency** | Easy, efficient implementation |
| **Massive inputs** | Yes if distributed + $k$ small; **not** suitable for data streams |

#### PAM — Partitioning Around Medoids

*(Kaufman & Rousseeuw, 1987; a.k.a. k-medoids)*

Local search: start from arbitrary $S$, repeatedly perform the best swap $(s \in S) \leftrightarrow (p \in P - S)$ until no improving swap exists.

| Property | Details |
|----------|---------|
| **Applicability** | Mainly k-median; enforces $S \subset P$ |
| **Accuracy** | Good solutions |
| **Efficiency** | Very slow: each iteration checks $\approx N \cdot k$ swaps; convergence can be very slow |
| **Massive inputs** | **Not at all** |

### Why Coresets Are Essential

Clustering of massive data remains challenging when:
- Data comes from **general metrics** (not just Euclidean space).
- **Very high accuracy** is required (especially high-dimensional spaces).
- Data arrives as possibly **unbounded streams**.

In these scenarios, **coreset-based strategies are essential**.

### Weighted k-Means

When building a coreset for k-means/median, each center $x \in T$ represents multiple points of $P$ → must account for how many points it represents via **weights**.

**Why weights are needed:**
- For k-center: $d(x, S)$ alone is a good estimate of all represented points' contribution.
- For k-means: $w(x) \cdot d(x,S)^2$ is needed (not $d(x,S)^2$ alone), since the number of represented points affects the sum of squared distances.

> [!Important] Definition — Weighted k-Means Problem
> **Input:** Pointset $P \subset \mathbb{R}^D$, weights $w(x) > 0$ for all $x \in P$, target $k$.
> **Output:** Set $S$ of $k$ centers in $\mathbb{R}^D$ minimizing:
> $$\Phi^w_{\text{kmeans}}(P, S) = \sum_{x \in P} w(x) \cdot (d(x, S))^2$$
>
> Standard k-means is the special case $w(x) = 1$ for all $x$.

### Adapting Algorithms to Handle Weights

**k-means++ with weights** — change the selection probability:
$$\pi(x) = \frac{(d(x,S))^2}{\sum_{y \in P-S}(d(y,S))^2} \quad\longrightarrow\quad \frac{w(x)\cdot(d(x,S))^2}{\sum_{y \in P-S} w(y)\cdot(d(y,S))^2}$$

**Lloyd's algorithm with weights** — change the centroid formula for cluster $C = \{x_1,\ldots,x_t\}$:
$$\frac{1}{t}\sum_{i=1}^t x_i \quad\longrightarrow\quad \frac{1}{\sum_{i=1}^t w(x_i)}\cdot\sum_{i=1}^t w(x_i)\cdot x_i$$

*(For k-median, PAM can be adapted to weights similarly.)*

### MR-kmeans Algorithm

$\text{MR-kmeans}(\mathcal{A}_1, \mathcal{A}_2)$: 2-round MapReduce algorithm using:
- $\mathcal{A}_1$: sequential algorithm for **unweighted** k-means (space proportional to input).
- $\mathcal{A}_2$: sequential algorithm for **weighted** k-means (space proportional to input).

*(Note: $\mathcal{A}_2$ with unit weights can replace $\mathcal{A}_1$.)*

**Algorithm:**

**Round 1:**
- *Map Phase:* partition $P$ arbitrarily into $\ell$ equal subsets $P_1, \ldots, P_\ell$.
- *Reduce Phase:* for each $i \in [1,\ell]$ separately:
  - Run $\mathcal{A}_1$ on $P_i$ → $T_i \subseteq P_i$ of $k$ centers.
  - For each $x \in P_i$: proxy $\tau(x)$ = closest center in $T_i$.
  - For each $y \in T_i$: weight $w(y)$ = number of points in $P_i$ whose proxy is $y$.
  - *(The $\tau(x)$'s need not be stored; only the $w(y)$'s are stored.)*

**Round 2:**
- *Map Phase:* empty.
- *Reduce Phase:* run $\mathcal{A}_2$ on $T = \bigcup_{i=1}^\ell T_i$ with weights → return $S = \{c_1,\ldots,c_k\}$.

> [!Example] Round 1 example: k=4, partition P_i
> $T_i = \{a, b, c, d\}$
> $w(a)=10,\quad w(b)=6,\quad w(c)=4,\quad w(d)=5$

![[Pasted image 20260428131301.png]]

#### Space Analysis

Setting $\ell = \sqrt{N/k}$ (same analysis as MR-FFT):

$$M_L = O\!\left(\max\!\left\{\frac{N}{\ell},\ \ell \cdot k\right\}\right) = O\!\left(\sqrt{Nk}\right) = o(N) \quad \text{(for } k = o(N)\text{)}$$
$$M_A = O(N)$$

#### γ-Coreset Definition

> [!Important] Definition — $\gamma$-Coreset for k-Means
> Given $P$, coreset $T \subseteq P$, and proxy function $\tau : P \to T$, $T$ is a **$\gamma$-coreset** for $P$, $k$, and the k-means objective if:
> $$\sum_{p \in P} (d(p, \tau(p)))^2 \leq \gamma \cdot \Phi^{\text{opt}}_{\text{kmeans}}(P, k)$$
>
> **Intuizione:** the total squared error of approximating $P$ by $T$ (via the proxy mapping) is at most $\gamma$ times the optimal k-means cost. Small $\gamma$ → the error from using $T$ instead of $P$ is small.

#### Accuracy Theorem

> [!Important] Theorem — Approximation Ratio of MR-kmeans
> Suppose:
> - $\mathcal{A}_1$ is a $\gamma$-approximation for unweighted k-means.
> - $\mathcal{A}_2$ is an $\alpha$-approximation for weighted k-means.
>
> Then:
> 1. The coreset $T$ computed in Round 1 is a **$\gamma$-coreset**.
> 2. The final solution $S$ satisfies:
> $$\Phi_{\text{kmeans}}(P, S) = O\!\left((1+\gamma)\cdot\alpha\right)\cdot\Phi^{\text{opt}}_{\text{kmeans}}(P,k)$$
>
> The total approximation loss has two contributions:
> - $(1+\gamma)$: loss from using $T \subseteq P$ instead of $P$ (coreset approximation error).
> - $\alpha$: loss from using an approximation algorithm $\mathcal{A}_2$ to compute $S$ from $T$.

---

### Observations on MR-kmeans

- For k-means (as well as k-center, k-median), **good coresets are obtained by combining solutions to the same problem on smaller partitions**. This is not always the case for other problems (e.g., diameter, diversity maximization need special treatment).
- In practice: fast and accurate.
- **Typical usage:** $\mathcal{A}_1$ = k-means++, $\mathcal{A}_2$ = weighted k-means++ followed by weighted Lloyd's.
- **Improved quality:** selecting $h > k$ centers from each $P_i$ in Round 1 (e.g., via k-means++) yields a better $\gamma$-coreset. For low-dimensional spaces, $\gamma \ll \alpha$ is achievable with moderate $h$.

## Exercises

> [!Example] Exercise 1 (Slide 60) — k-means++ probability boosting
> k-means++ is randomized. For any input $P$, letting $S$ be the returned centers, it is known that $\alpha = \Theta(\ln k)$ satisfies:
> $$\Pr\!\left(\Phi_{\text{kmeans}}(P, S) \leq \alpha \cdot \Phi^{\text{opt}}_{\text{kmeans}}(P, k)\right) \geq \tfrac{1}{2}$$
>
> Show that by running $t$ **independent** instances of k-means++ and returning the solution with minimum objective value, the success probability can be boosted to $\geq 1 - 1/N$.

> [!Example] Exercise 2 (Slide 61) — Unit square diameter approximation via grid coreset
> Let $Q = [0,1]^2$ be the unit square subdivided into $c^2$ cells of side $1/c$. Consider a pointset $P \subseteq Q$ and a subset $T \subset P$ of $c^2$ points containing **one point per cell**. Let $d_{\max}(P)$ and $d_{\max}(T)$ be the maximum pairwise distances within $P$ and $T$ respectively.
>
> Quantify how well $d_{\max}(T)$ approximates $d_{\max}(P)$.

> [!Example] Exercise 3 (Slide 62) — Weighted closest-neighbor per cluster
> Let $P$ be a set of $N$ weighted points partitioned into $k$ clusters $C_1, \ldots, C_k$ with centers $c_1, \ldots, c_k$. Each point $x \in P$ is represented as $(x, (i_x, w_x))$, where $i_x$ is the cluster index and $w_x$ the weight of $x$. The **weighted closest neighbor** of cluster $C_i$ is the cluster $C_j$ ($j \neq i$) minimizing:
> $$\sum_{x \in C_i} w_x \cdot d^2(x, c_j)$$
>
> 1. Design an efficient 2-round MapReduce algorithm that, for each $1 \leq i \leq k$, computes the index $j$ of $C_i$'s weighted closest neighbor. *(Assume $k$ constant and $c_1, \ldots, c_k$ are global variables.)*
> 2. Analyze the local and aggregate space. Target: $o(N)$ local space, $O(N)$ aggregate space.
