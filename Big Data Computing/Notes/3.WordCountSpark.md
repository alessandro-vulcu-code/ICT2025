## Introduction

The Word Count example illustrates how to implement the **MapReduce Word Count algorithm** in Spark, both in Java and Python. It serves as a concrete reference for understanding Spark's RDD programming model and MapReduce round structure.

---

## Functional Programming

Core idea: **functions can be arguments to other functions**. Spark's API relies heavily on this — many RDD operations (e.g., `map`, `flatMap`) require functions as arguments.

Two ways to pass functions in Spark:

1. **Anonymous functions (lambdas):** defined inline where the argument is expected.
2. **Named functions:** defined outside the method, referenced by name.

### Passing Functions: Java

> [!Example] Anonymous function — single statement (Java)
> ```java
> JavaRDD<Double> squaredValues = values.map((x) -> x*x);
> ```

> [!Example] Anonymous function — multiple statements (Java)
> ```java
> double fixed = 1.5;
> JavaRDD<Double> normValues = values.map((x) -> {
>   double diff = fixed - x;
>   return diff;
> });
> ```

> [!Example] Named function (Java)
> ```java
> class myMethods {
>   public static double mySquare(double x) { return x * x; }
> }
> // usage:
> JavaRDD<Double> squaredValues = values.map(myMethods::mySquare);
> ```

### Passing Functions: Python

> [!Example] Anonymous function (Python)
> ```python
> squaredValues = values.map(lambda x: x * x)
> ```
> *Note: Python does not allow multiple statements in anonymous functions.*

> [!Example] Named function (Python)
> ```python
> def mySquare(x):
>     return x * x
> squaredValues = values.map(mySquare)
> ```

## Implementation of Word Count in Spark

### Common Assumptions

- **Input:** file of documents, one document per line.
- **Output:** $(w, c(w))$ pairs, where $w$ = word and $c(w)$ = number of occurrences of $w$ across all documents.
- **Command-line arguments:**
  - $L$: number of partitions for the RDD
  - `data_path`: path to the input file

### Spark Configuration and Input Reading

**Java:**
```java
SparkConf conf = new SparkConf(true).setAppName("WordCount");
JavaSparkContext sc = new JavaSparkContext(conf);
int L = Integer.parseInt(args[0]);
JavaRDD<String> docs = sc.textFile(args[1]).repartition(L).cache();
```

**Python:**
```python
conf = SparkConf(True).setAppName('WordCount')
sc = SparkContext(conf=conf)
L = int(sys.argv[1])
docs = sc.textFile(data_path).repartition(L).cache()
```

Key methods:
- **`textFile`:** loads the input file as an RDD of Strings, one element per line (= one document).
- **`repartition(L)`:** redistributes RDD elements randomly into $L$ partitions.
- **`cache()`:** instructs Spark to store the RDD in executor memory upon first materialization.

---

### Initial Map Phase

Transform the RDD of documents into an RDD of $(w, c(w))$ pairs, where each $c(w)$ is the count of $w$ **within a single document**.

![[PLACEHOLDER_Fig_1 — Initial Map Phase: RDD of Strings → flatMapToPair → RDD of (w, c(w)) pairs (count per document)]]

**Java** uses `flatMapToPair`; **Python** uses `flatMap` (Python does not distinguish between pair and non-pair outputs).

**Java — `wordCountPerDoc`:**
```java
public static Iterator<Tuple2<String,Long>> wordCountPerDoc(String document) {
    String[] tokens = document.split(" ");
    HashMap<String, Long> counts = new HashMap<>();
    for (String token : tokens)
        counts.put(token, 1L + counts.getOrDefault(token, 0L));
    ArrayList<Tuple2<String, Long>> pairs = new ArrayList<>();
    for (Map.Entry<String, Long> e : counts.entrySet())
        pairs.add(new Tuple2<>(e.getKey(), e.getValue()));
    return pairs.iterator();
}
```

**Python — `word_count_per_doc`:**
```python
def word_count_per_doc(document):
    pairs_dict = {}
    for word in document.split(' '):
        pairs_dict[word] = pairs_dict.get(word, 0) + 1
    return [(key, pairs_dict[key]) for key in pairs_dict.keys()]
```

> [!Important] Key Types in Java
> - **`Tuple2<K,V>`**: represents a key-value pair. `T._1()` = key, `T._2()` = value.
> - **`JavaPairRDD<K,V>`**: RDD of `Tuple2<K,V>` elements.
> - **`flatMapToPair`**: maps each element to $\geq 0$ `Tuple2` pairs (use `mapToPair` if exactly one pair).
> - **`flatMap`** (Python): maps each element to $\geq 0$ new elements (use `map` if exactly one).

### 1-Round Algorithm

#### groupByKey + mapValues

![[PLACEHOLDER_Fig_2 — 1-Round RDD flow: RDD of Strings → flatMapToPair → RDD of (w, c(w)) → groupByKey → RDD of (w, list-of-counts) → mapValues → RDD of (w, c(w)) final counts]]

**Java:**
```java
JavaPairRDD<String, Long> wordCounts = docs
    .flatMapToPair(myMethods::wordCountPerDoc)  // MAP PHASE
    .groupByKey()                               // SHUFFLE + GROUPING
    .mapValues((it) -> {
        long sum = 0;
        for (long c : it) sum += c;
        return sum;
    });                                         // REDUCE PHASE
```

**Python:**
```python
word_count = (docs
    .flatMap(word_count_per_doc)
    .groupByKey()
    .mapValues(lambda vals: sum(vals)))
```

- **`groupByKey`:** collects all pairs with the same key, returns RDD of $(key, \text{list-of-values})$. In Java, list-of-values is an iterator.
- **`mapValues`:** transforms each pair retaining the key, applying the function to its value (here, a list).

#### More Efficient: reduceByKey

`groupByKey` + `mapValues` can be replaced by `reduceByKey`:

**Java:**
```java
JavaPairRDD<String, Long> wordCounts = docs
    .flatMapToPair(myMethods::wordCountPerDoc)
    .reduceByKey((x, y) -> x + y);
```

**Python:**
```python
word_count = (docs.flatMap(word_count_per_doc)
    .reduceByKey(lambda x, y: x + y))
```

> [!Important] reduceByKey — Behavior and Constraints
> For each key $k$, `reduceByKey` combines all values using the binary operator passed as argument, in a **tree-like fashion**.
>
> **Constraints:** the function must be **commutative and associative** (no control over aggregation order).
>
> **Efficiency:** Spark aggregates first **within** each partition, then **across** partitions → effectively a 2-round algorithm in disguise.

![[PLACEHOLDER_Fig_3 — Tree-like aggregation of reduceByKey: leaves = values per partition (red circles), internal nodes = partial aggregations (blue circles), final root = result]]

### 2-Round Algorithm

#### General Structure

**Round 1**
- **Map Phase:** for each document $D_i$, compute local count $c_i(w)$ of each word $w$; partition $(w, c_i(w))$ pairs among $L$ groups.
- **Reduce Phase:** for each word $w$, aggregate local counts **within each partition**, producing at most $L$ pairs $(w, c(x,w))$, one per partition $x \in [0, L)$.

**Round 2**
- **Map Phase:** empty.
- **Reduce Phase:** for each word $w$, aggregate the $c(x,w)$ counts into the final count $c(w)$, producing the pair $(w, c(w))$.

Two techniques to implement Round 1 grouping:

#### Technique 1 — Random Keys (groupBy)

Assign a random integer key $k \in [0, L)$ to each $(w, c(w))$ pair, then group by that key to gather pairs into $L$ buckets. The reduce function `gatherPairs` aggregates counts within each bucket.

![[PLACEHOLDER_Fig_4 — 2-Round Random Keys RDD flow: RDD of Strings → flatMapToPair → RDD of (w, c(w)) → groupBy(random key) → RDD of (k, list-of-(w,c(w))) → flatMapToPair(gatherPairs) → RDD of (w, c(w)) (≤L per word) → reduceByKey → final (w, c(w))]]

**Java:**
```java
JavaPairRDD<String, Long> wordCounts = docs
    .flatMapToPair(myMethods::wordCountPerDoc)           // MAP PHASE (R1)
    .groupBy((wordcountpair) -> randomGenerator.nextInt(L))  // SHUFFLE + GROUPING
    .flatMapToPair(myMethods::gatherPairs)               // REDUCE PHASE (R1)
    .reduceByKey((x, y) -> x + y);                      // REDUCE PHASE (R2)
```

**Python:**
```python
word_count = (docs
    .flatMap(word_count_per_doc)
    .groupBy(lambda x: rand.randint(0, L-1))
    .flatMap(gather_pairs)
    .reduceByKey(lambda x, y: x + y))
```

**`gatherPairs` (Java):**
```java
public static Iterator<Tuple2<String,Long>> gatherPairs(
        Tuple2<Integer, Iterable<Tuple2<String, Long>>> element) {
    HashMap<String, Long> counts = new HashMap<>();
    for (Tuple2<String, Long> c : element._2())
        counts.put(c._1(), c._2() + counts.getOrDefault(c._1(), 0L));
    ArrayList<Tuple2<String, Long>> pairs = new ArrayList<>();
    for (Map.Entry<String, Long> e : counts.entrySet())
        pairs.add(new Tuple2<>(e.getKey(), e.getValue()));
    return pairs.iterator();
}
```

> [!Important] groupBy — Behavior
> 1. Transforms each element into a $(key, element)$ pair, where key is assigned via the function argument.
> 2. For each key $k$, collects all elements with key $k$ into $(k, \text{list-of-elements})$.
>
> Result in the example: RDD of $(k,\ \text{list-of-(word,count)-pairs})$, then processed individually by the subsequent `flatMapToPair`.

#### Technique 2 — Spark Partitions (mapPartitions)

Exploit existing RDD partitions directly: aggregate $(w, c(w))$ pairs **within each partition** without explicit key assignment.

![[PLACEHOLDER_Fig_5 — 2-Round Spark Partitions RDD flow: RDD of Strings → flatMapToPair → RDD of (w, c(w)) → mapPartitionsToPair → RDD of (w, c(w)) (≤L per word) → groupByKey + mapValues (or reduceByKey) → final (w, c(w))]]

**Java:**
```java
JavaPairRDD<String, Long> wordCounts = docs
    .flatMapToPair(myMethods::wordCountPerDoc)
    .mapPartitionsToPair(element -> {               // REDUCE PHASE (R1)
        HashMap<String, Long> counts = new HashMap<>();
        while (element.hasNext()) {
            Tuple2<String, Long> tuple = element.next();
            counts.put(tuple._1(), tuple._2() + counts.getOrDefault(tuple._1(), 0L));
        }
        ArrayList<Tuple2<String, Long>> pairs = new ArrayList<>();
        for (Map.Entry<String, Long> e : counts.entrySet())
            pairs.add(new Tuple2<>(e.getKey(), e.getValue()));
        return pairs.iterator();
    })
    .reduceByKey((x, y) -> x + y);                 // REDUCE PHASE (R2)
```

**Python:**
```python
def gather_pairs_partitions(pairs):
    pairs_dict = {}
    for p in pairs:
        word, occurrences = p[0], p[1]
        pairs_dict[word] = pairs_dict.get(word, 0) + occurrences
    return [(key, pairs_dict[key]) for key in pairs_dict.keys()]

word_count = (docs.flatMap(word_count_per_doc)
    .mapPartitions(gather_pairs_partitions)
    .groupByKey()
    .mapValues(lambda vals: sum(vals)))
```

> [!Important] mapPartitions / mapPartitionsToPair — Behavior
> For each RDD partition (created by Spark), **separately**, applies the function to all elements of that partition. Elements are provided as an iterator; the function returns $\geq 0$ pairs.
>
> **Effect in the example:** after `mapPartitionsToPair`, for each word $w$ there are at most $L$ counts (one per partition), ready for the final aggregation in Round 2.

## Important Observations on Partitioning

> [!Important] RDD Partitioning After Transformations
> - The partitioning of a derived RDD is inherited from the last `repartition` call, or from the initial load.
> - After substantial data transformations, **balance is not guaranteed** — partitions may become skewed.
> - To re-balance, call `repartition` again — but this involves **shuffling** all data.

## Summary Table

| Method | Language | Type | Description |
|--------|----------|------|-------------|
| `flatMapToPair(f)` | Java | Narrow/Wide | Maps each element to $\geq 0$ `Tuple2` pairs |
| `flatMap(f)` | Python | Narrow/Wide | Maps each element to $\geq 0$ new elements |
| `mapToPair(f)` | Java | Narrow | Maps each element to exactly 1 `Tuple2` pair |
| `map(f)` | Python | Narrow | Maps each element to exactly 1 new element |
| `groupByKey()` | Java/Python | Wide | Groups pairs by key → $(k, \text{list-of-values})$ |
| `mapValues(f)` | Java/Python | Narrow | Applies `f` to values, retains keys |
| `reduceByKey(f)` | Java/Python | Wide | Aggregates values per key via binary commutative+associative `f`; tree-like schedule |
| `groupBy(f)` | Java/Python | Wide | Assigns key via `f`, then groups by that key |
| `mapPartitionsToPair(f)` | Java | Narrow | Applies `f` to each partition as a whole (iterator in, iterator of pairs out) |
| `mapPartitions(f)` | Python | Narrow | Same as above for Python |
| `repartition(L)` | Java/Python | Wide | Randomly redistributes elements into $L$ partitions |
| `cache()` | Java/Python | — | Stores RDD in executor RAM after first materialization |

| Algorithm | Rounds | Technique | Key Idea |
|-----------|--------|-----------|----------|
| 1-Round (groupByKey) | 1 | Wide shuffle | All pairs → groupByKey → mapValues |
| 1-Round (reduceByKey) | 1 (2 in disguise) | Tree aggregation | Partial within-partition reduction first |
| 2-Round (random keys) | 2 | groupBy + random $k \in [0,L)$ | Explicit random partitioning in Round 1 |
| 2-Round (Spark partitions) | 2 | mapPartitions | Reuse existing RDD partitions for Round 1 aggregation |
