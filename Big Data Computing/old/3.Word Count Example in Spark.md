## 1. Functional Programming

A core idea in functional programming is that **functions can be arguments to other functions**.

- In a MapReduce algorithm, the map and reduce functions used in each round can be thought of as _"arguments"_ for the round.
- Spark's API leans heavily on this: many RDD operations take functions as arguments.

There are **two ways** to pass functions as arguments to a method in Spark:

|Method|Description|
|---|---|
|**Anonymous functions** (lambdas)|Defined _inline_, without a name, where the actual argument is expected|
|**Named functions**|Defined _outside_ the method, in a separate class or function definition|

---

### 1.1 Functional Programming: Java Examples

Let `values` be an RDD of doubles (type `JavaRDD<Double>`).

**Using anonymous functions:**

```java
// Single statement
JavaRDD<Double> squaredValues = values.map((x) -> x*x);

// Multiple statements
double fixed = 1.5;
JavaRDD<Double> normValues = values.map((x) -> {
    double diff = fixed - x;
    return diff;
});
```

> **Note:** The variable `fixed` is _"captured"_ by the anonymous function. It is defined outside the lambda but used inside it.

**Using named functions:**

```java
// Define a separate class
class myMethods {
    public static double mySquare(double x) {
        return x * x;
    }
}

// Then use it in the main program
JavaRDD<Double> squaredValues = values.map(myMethods::mySquare);
```

---

### 1.2 Functional Programming: Python Examples

Let `values` be an RDD of doubles.

**Using anonymous functions (lambdas):**

```python
squaredValues = values.map(lambda x: x * x)
```

> **Note:** Python does **not** allow multiple statements in anonymous functions (lambdas).

**Using named functions:**

```python
def mySquare(x):
    return x * x

squaredValues = values.map(mySquare)
```

## 2. Implementation of Word Count in Spark

### Common Assumptions

- **Input:** a file of documents, _one document per line_.
- **Output:** `(w, c(w))` pairs, where `w` is a word and `c(w)` is the number of occurrences of `w` across all documents.
- **Command line arguments:**
    - `L` — number of partitions for the RDD
    - `data_path` — path to the input file

---

### 2.1 Spark Configuration and Input Reading

**Java:**

```java
import ....
public class WordCountExample {
    public static void main(String[] args) throws IOException {
        // SPARK SETUP
        SparkConf conf = new SparkConf(true).setAppName("WordCount");
        JavaSparkContext sc = new JavaSparkContext(conf);

        // INPUT READING
        int L = Integer.parseInt(args[0]);
        JavaRDD<String> docs = sc.textFile(args[1]).repartition(L).cache();
```

**Python:**

```python
def main():
    # SPARK SETUP
    conf = SparkConf(true).setAppName('WordCount')
    sc = SparkContext(conf=conf)

    # INPUT READING
    L = int(sys.argv[1])
    data_path = sys.argv[2]
    docs = sc.textFile(data_path).repartition(L).cache()
```

**Explanation of each step:**

|Method|What it does|
|---|---|
|`SparkConf` / `SparkContext`|Sets up the configuration object, the context object, and the application name|
|`textFile(path)`|Transforms the input file into an RDD of Strings, where each element corresponds to one line of the file (i.e., one document)|
|`repartition(L)`|Subdivides the RDD elements, _at random_, into `L` partitions|
|`cache()`|Tells Spark that the first time the RDD is materialized, its elements must be stored permanently in the executors' main memory (if they fit)|

---

### 2.2 Initial Map Phase

This phase transforms each document (a string) into a set of `(word, count)` pairs, where the count is local to that document.

**Java:**

```java
JavaPairRDD<String, Long> wordCounts = docs
    .flatMapToPair(myMethods::wordCountPerDoc) // <-- MAP PHASE
    ....

class myMethods {
    public static Iterator<Tuple2<String, Long>>
    wordCountPerDoc(String document) {
        String[] tokens = document.split(" ");
        HashMap<String, Long> counts = new HashMap<>();
        ArrayList<Tuple2<String, Long>> pairs = new ArrayList<>();
        for (String token : tokens) {
            counts.put(token, 1L + counts.getOrDefault(token, 0L));
        }
        for (Map.Entry<String, Long> e : counts.entrySet()) {
            pairs.add(new Tuple2<>(e.getKey(), e.getValue()));
        }
        return pairs.iterator();
    }
}
```

> **Key Java types:**
>
> - `Tuple2<K,V>`: a key-value pair. `T._1()` returns the key, `T._2()` returns the value.
> - `JavaPairRDD<K,V>`: an RDD of key-value pairs whose elements are `Tuple2<K,V>` instances.
> - `flatMapToPair`: transforms each RDD element (a document) into zero or more `Tuple2` pairs. The function must return the pairs as an iterator. Use `mapToPair` instead when exactly one pair is returned.

**Python:**

```python
def word_count_per_doc(document):
    pairs_dict = {}
    for word in document.split(' '):
        if word not in pairs_dict.keys():
            pairs_dict[word] = 1
        else:
            pairs_dict[word] += 1
    return [(key, pairs_dict[key]) for key in pairs_dict.keys()]

def word_count_1(docs):
    word_count = (docs.flatMap(word_count_per_doc) # <-- MAP PHASE
        ....
```

> **Note (Python):** Key-value pairs are plain Python tuples. `flatMap` transforms each RDD element into zero or more new elements. Use `map` instead of `flatMap` when exactly one pair is returned.

### 2.3 1-Round Algorithm

The full 1-round word count applies the map phase, groups by key, then reduces.

**Java:**

```java
JavaPairRDD<String, Long> wordCounts = docs
    .flatMapToPair(myMethods::wordCountPerDoc) // <-- MAP PHASE
    .groupByKey()                              // SHUFFLING + GROUPING
    .mapValues((it) -> {                       // <-- REDUCE PHASE
        long sum = 0;
        for (long c : it) sum += c;
        return sum;
    });
```

> **Note:** `flatMapToPair` takes a _named function_, while `mapValues` takes an _anonymous function_, showing both styles in practice.

**Python:**

```python
word_count = (docs
    .flatMap(word_count_per_doc)           # <-- MAP PHASE
    .groupByKey()                          # <-- SHUFFLE + GROUPING
    .mapValues(lambda vals: sum(vals)))    # <-- REDUCE PHASE
```

> **Key methods:**
>
> - `groupByKey`: collects all elements with the same key and returns an RDD of `(key, list-of-values)` pairs. In Java, the list is returned as an iterator.
> - `mapValues`: keeps the key and applies the given function to its value. Here, the value is a list of counts that gets summed.

---

#### More Efficient Implementation: `reduceByKey`

`groupByKey` + `mapValues` can be replaced by `reduceByKey`:

**Java:**

```java
JavaPairRDD<String, Long> wordCounts = docs
    .flatMapToPair(myMethods::wordCountPerDoc) // <-- MAP PHASE
    .reduceByKey((x, y) -> x + y);            // <-- REDUCE PHASE
```

**Python:**

```python
word_count = (docs
    .flatMap(word_count_per_doc)             # <-- MAP PHASE
    .reduceByKey(lambda x, y: x + y))        # <-- REDUCE PHASE
```

> **Important observations on `reduceByKey`:**
>
> - For each key `k`, it combines all values for that key using the given function as a _binary operator_ (addition here), in a **tree-like** fashion.
> - The programmer has **no control** over the order of binary aggregations, so the function **must be commutative and associative**.
> - Spark aggregates _first within each partition_, then _across partitions_, so it internally behaves like a 2-round algorithm.

### 2.4 2-Round Algorithm

#### General Structure

The 2-round algorithm cuts down on network shuffle by doing partial aggregation locally before the final global reduce.

**Round 1:**

- _Map Phase:_ for each document `Di`, compute the local count `ci(w)` of each word `w`, and partition the `(w, ci(w))` pairs among `L` partitions.
- _Reduce Phase:_ for each word `w`, aggregate local counts _separately for each partition_, producing at most `L` pairs `(w, c(x,w))`, one per partition `x`, with `0 <= x < L`.

**Round 2:**

- _Map Phase:_ empty.
- _Reduce Phase:_ for each word `w`, aggregate the `c(x,w)` counts across all partitions into the final count `c(w)` and produce the final pair `(w, c(w))`.

---

There are two partitioning techniques:

|Technique|Description|
|---|---|
|**Random keys on the fly**|Random keys are assigned during `groupBy` in Round 1|
|**Reuse of Spark partitions**|The existing RDD partitions defined by Spark are used directly|

> **Note:** The complete `WordCountExample` code also includes a _third_ version where random keys are assigned explicitly during the Map Phase of Round 1. It is functionally equivalent to the `groupBy` approach but _less efficient_, and is included to show another way to use a Map Phase for element transformation.

---

#### 2-Round Algorithm with Random Keys

**Java:**

```java
JavaPairRDD<String, Long> wordCounts = docs
    .flatMapToPair(myMethods::wordCountPerDoc)
    .groupBy((wordcountpair) -> randomGenerator.nextInt(L))
    // IMPLEMENTS RANDOM KEY ASSIGNMENT, SHUFFLE AND GROUPING
    .flatMapToPair(myMethods::gatherPairs)    // <-- REDUCE PHASE (R1)
    .reduceByKey((x, y) -> x + y);           // <-- REDUCE PHASE (R2)
```

The `gatherPairs` function used in Round 1's reduce phase:

```java
class myMethods {
    public static Iterator<Tuple2<String, Long>>
    gatherPairs(Tuple2<Integer, Iterable<Tuple2<String, Long>>> element) {
        HashMap<String, Long> counts = new HashMap<>();
        for (Tuple2<String, Long> c : element._2()) {
            counts.put(c._1(), c._2() + counts.getOrDefault(c._1(), 0L));
        }
        ArrayList<Tuple2<String, Long>> pairs = new ArrayList<>();
        for (Map.Entry<String, Long> e : counts.entrySet()) {
            pairs.add(new Tuple2<>(e.getKey(), e.getValue()));
        }
        return pairs.iterator();
    }
}
```

> **How `groupBy` works here:**
>
> 1. Each element becomes a pair `(key, element)`, where the key comes from the function argument — here, a random integer in `[0, L)`.
> 2. For each key `k`, all pairs with that key are collected into `(k, list-of-values)` — here, a list of `(word, count)` pairs.
>
> The result is an RDD of `(randomKey, list-of-(word,count)-pairs)`. Each element is then processed individually by `flatMapToPair` via `gatherPairs`.

**Python:**

```python
def gather_pairs(pairs):
    pairs_dict = {}
    for p in pairs[1]:
        word, occurrences = p[0], p[1]
        if word not in pairs_dict.keys():
            pairs_dict[word] = occurrences
        else:
            pairs_dict[word] += occurrences
    return [(key, pairs_dict[key]) for key in pairs_dict.keys()]

def word_count_2(docs, L):
    word_count = (docs
        .flatMap(word_count_per_doc)                    # <-- MAP PHASE (R1)
        .groupBy(lambda x: (rand.randint(0, L-1)))      # <-- SHUFFLE + GROUPING
        .flatMap(gather_pairs)                          # <-- REDUCE PHASE (R1)
        .reduceByKey(lambda x, y: x + y))               # <-- REDUCE PHASE (R2)
    return word_count
```

#### 2-Round Algorithm with Spark Partitions

Instead of assigning random keys manually, this version uses the **existing partitions** already defined by Spark on the RDD. Round 1's reduce phase aggregates within each partition using `mapPartitionsToPair` / `mapPartitions`.

**Java:**

```java
JavaPairRDD<String, Long> wordCounts = docs
    .flatMapToPair(myMethods::wordCountPerDoc)
    .mapPartitionsToPair((element) -> {    // <-- REDUCE PHASE (R1)
        HashMap<String, Long> counts = new HashMap<>();
        while (element.hasNext()) {
            Tuple2<String, Long> tuple = element.next();
            counts.put(tuple._1(), tuple._2() +
                counts.getOrDefault(tuple._1(), 0L));
        }
        ArrayList<Tuple2<String, Long>> pairs = new ArrayList<>();
        for (Map.Entry<String, Long> e : counts.entrySet()) {
            pairs.add(new Tuple2<>(e.getKey(), e.getValue()));
        }
        return pairs.iterator();
    })
    .groupByKey()                           // <-- SHUFFLE + GROUPING
    .mapValues(.. as before ..);
```

> **How `mapPartitionsToPair` works:**
>
> For each Spark partition, `mapPartitionsToPair` runs the given function on all elements in that partition. Elements arrive as an iterator; the function returns zero or more `Tuple2` pairs.
>
> Here, each partition holds `(word, count)` pairs with per-document counts. After `mapPartitionsToPair`, counts are **aggregated within each partition**, so the output is still `(word, count)` pairs but with fewer, larger values.

**Python:**

```python
def gather_pairs_partitions(pairs):
    pairs_dict = {}
    for p in pairs:
        word, occurrences = p[0], p[1]
        if word not in pairs_dict.keys():
            pairs_dict[word] = occurrences
        else:
            pairs_dict[word] += occurrences
    return [(key, pairs_dict[key]) for key in pairs_dict.keys()]

def word_count_with_partition(docs):
    word_count = (docs
        .flatMap(word_count_per_doc)                    # <-- MAP PHASE (R1)
        .mapPartitions(gather_pairs_partitions)          # <-- REDUCE PHASE (R1)
        .groupByKey()                                   # <-- SHUFFLE + GROUPING
        .mapValues(lambda vals: sum(vals)))              # <-- REDUCE PHASE (R2)
    return word_count
```

#### Important Note on Partition Balancing

> **Important observation:**
>
> If an RDD is the result of a sequence of transformations:
>
> - Its partitioning is _inherited_ from the last call to `repartition`, if any, or from the partitioning created when data was initially loaded into memory.
> - But since data may have changed substantially through transformations, **balance is not guaranteed**. Calling `repartition` again will restore balance, at the cost of **shuffling the data**.
