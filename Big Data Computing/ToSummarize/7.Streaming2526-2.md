## Sketching

---

**Sketch**: space-efficient data structure that can be used to provide (typically **probabilistic**) estimates of (statistical) characteristics of a data stream.

---

## Frequency Moments

Consider a stream $\Sigma = x_1, x_2, \ldots, x_n$, whose elements belong to a universe $U$. (*In fact, $\Sigma$ could represent an arbitrary prefix of a longer, possibly unbounded, stream.*)

For each $u \in U$ occurring in $\Sigma$ define its (*absolute*) *frequency*

$$f_u = |\{j : x_j = u,\ 1 \leq j \leq n\}|,$$

i.e., the number of occurrences of $u$ in $\Sigma$

> **Definition: Frequency Moments**
>
> For every $k \geq 0$, the $k$-th frequency moment $F_k$ of $\Sigma$ is
>
> $$F_k = \sum_{u \in U} f_u^k.$$

(We assume $0^0 = 0$)

---

## Frequency Moments

**Relevant informations from frequency moments:**

- $F_0$ = number of distinct items in $\Sigma$. It is useful, for instance, in the analysis of web-logs.
- $F_1 = |\Sigma|$: trivial to maintain with a counter.
- $1 - F_2/|\Sigma|^2$ = Gini index of $\Sigma$. It provides info on data impurity: the closer to 1 and the higher is the impurity (i.e., diversity). It is used for decision tree induction.

---

## Observations on the GINI INDEX

*(handwritten)*

* If $x_1 = x_2 = \cdots = x_n$ (MIN IMPURITY) then
  $F_2 = n^2 = |\Sigma|^2 \Rightarrow$ GINI INDEX $= 1 - F_2/|\Sigma|^2 = 0$

* If $\Sigma$ contains $m$ distinct elements each occurring $n/m$ times (HIGH IMPURITY for large $m$) then
  $F_2 = m \cdot (n/m)^2 = n^2/m \Rightarrow$
  GINI INDEX $= 1 - F_2/|\Sigma|^2 = 1 - (n^2/m)/n^2 = 1 - 1/m$
  which tends to 1 as $m$ grows large

---

## Estimating $F_0$ for $\Sigma$ (i.e., distinct elements)

**Exact computation:** use $|U|$ counters or dictionary with $|F_0|$ elements (not suited for streaming setting).

**Probabilistic Counting Algorithm** ([Flajolet, Martin 1983])

- Working memory $O(\log|U|)$.
- $F_0$ approximated within a factor $c$, with probability $\geq 1 - 2/c$ (accuracy-confidence tradeoff).
- **Main idea:**
  - Map each $u \in U$ to a hash value $h(u) \in [0, |U| - 1]$.
    $\Rightarrow$ $h(u)$ is a $O(\log|U|)$-bit binary string.
  - Keep track of max number of trailing 0's in a hash code, which grows, probabilistically, with the number of distinct elements.

---

## Probabilistic Counting Algorithm

**Ingredients:**

- Integer $R \in [0, \lceil \log_2 |U| \rceil]$, which requires $\Theta(\log \log |U|)$ bits.
- Hash Function $h : U \to [0..|U| - 1]$. We assume:
  - For every $u \in U$, $h(u)$ has uniform distribution in $[0..|U| - 1]$
  - All $h(u)$'s are pairwise independent
- Notation: for $i \in [0..|U| - 1]$, define

  $tr(i)$ = number of trailing zeroes in binary representation of $i$

  e.g., $12 = (1100)_2 \Rightarrow tr(12) = 2$

**Initialization:** $R \leftarrow 0$

**Algorithm:** For each $x_t \in \Sigma$ do $R \leftarrow \max\{R,\ tr(h(x_t))\}$

After processing $x_n$, estimate $F_0$ as

$$\tilde{F}_0 = 2^R.$$

---

## Example *(handwritten)*

$\Sigma = A, D, A, A, C, B, F, F, B, A, E, C$

$U =$ Alphabet $\Rightarrow |U| = 26 \quad \lceil \log_2 |U| \rceil = 5$

$\Rightarrow R \in [0, 5]$

|-----|--------|-----------|-----|

| F   | 10100  | 2         | 3   |
| E   | 10011  | 0         | 3   |

After processing the entire stream $\Sigma$:

Estimate $\tilde{F}_0 = 2^R = 2^3 = 8$

True Value $F_0 = 6$

## Why does it work? (Intuition)

For simplicity, assume $|U|$ a power of 2.

For $x \in \Sigma$, what is the probability that $h(x)$ has at least $j$ trailing zeros?

- $\text{Prob}(tr(h(x)) \geq 1) = 1/2$
- $\text{Prob}(tr(h(x)) \geq 2) = 1/4$

  .....

- $\text{Prob}(tr(h(x)) \geq j) = 1/2^j$

---

*(handwritten)*

The fact that for any $x \in \Sigma$, $\Pr(tr(h(x)) \geq j) = 1/2^j$ is easily proved by regarding $h(x)$ as a string of $\lceil \log_2 |U| \rceil$ random and independent bits: thus $tr(h(x)) \geq j$ if the first $j$ bits are 0, irrespective of the other bits, which happens with probability $1/2^j$.

This has 2 consequences:

**(A)** $\Pr(\text{At the end of } \Sigma,\ R \geq j)$
$= \Pr(\exists \text{ an item } x \in \Sigma : tr(h(x)) \geq j)$
$\leq F_0 \cdot 1/2^j \quad$ (union bound on the distinct elements in $\Sigma$)

---

*(handwritten)*

**(B)** Among the $F_0$ random hash values associated with the distinct elements of $\Sigma$, those whose binary configurations have $\geq j$ trailing 0's is $F_0 \cdot (1/2^j)$ in EXPECTATION

$\Rightarrow$ It is reasonable to expect that $R$ is such that

$$\frac{F_0}{2^R} \geq 1 \quad \text{and for } R' > R \quad \frac{F_0}{2^{R'}} < 1$$

$\Rightarrow 2^R \approx F_0$ which provides an intuitive justification for the algorithm

## Probabilistic guarantees

The following theorem summarizes the properties of the algorithm.

> **Theorem**
>
> For a stream $\Sigma$ of $n$ elements, the **probabilistic counting algorithm** returns a value $\tilde{F}_0$ such that, for any $c > 2$:
>
> $$\Pr(\tilde{F}_0 < F_0/c) \leq 1/c \quad \text{and} \quad \Pr(\tilde{F}_0 > cF_0) \leq 1/c,$$
>
> hence
>
> $$\Pr(F_0/c \leq \tilde{F}_0 \leq cF_0) \geq 1 - 2/c.$$
>
> The algorithm requires a working memory of $O(\log|U|)$ bits, 1 pass, and $O(\log|U|)$ update/query time per element.

---

## Proof *(handwritten)*

* $\Pr(\tilde{F}_0 > cF_0) \leq 1/c$

  $\Pr(\tilde{F}_0 > cF_0) = \Pr(2^R > cF_0)$
  $= \Pr(R > \log_2(cF_0))$
  $\leq F_0 \cdot (1/2^{\log_2(cF_0)}) = \dfrac{1}{c} \quad$ (see (A) from slide 14)

* $\Pr(\tilde{F}_0 < F_0/c) \leq 1/c \quad$ we skip this proof

---

*(handwritten)*

* Working memory: $O(\log|U|)$
  - $R$ requires $O(\log \log |U|)$ bits
  - $h(x) \in [0, |U|-1] \Rightarrow$ requires $O(\log|U|)$ bits

* Update time: $O(\log|U|)$ to process the binary configuration of $h(x_t)$
* Query time: $O(\log|U|)$ to compute $2^R$

## Estimating individual frequencies and $F_2$ for $\Sigma$

**OBJECTIVE:** in one pass over $\Sigma$, we want to compute a **small sketch** that enables to derive **unbiased probabilistic estimates** of

- $f_u$ for any given $u \in U$ (*individual frequencies*)
- $F_2 = \sum_{u \in U}(f_u)^2$ (*second moment*)

with provable space-accuracy tradeoffs

**Observation:** clearly, the exact computation of all $f_u$'s or of $F_2$ might require space proportional to $|\Sigma|$.

---

## Count-min sketch

The first approach we consider is based on the **count-min sketch** invented by [Cormode, Muthukrishnan 2003].

**Main ingredients**

- $d \times w$ array $C$ of counters ($O(\log n)$ bits each)
- $d$ hash functions: $h_0, h_1, \ldots, h_{d-1}$, with

$$h_j\ :\ U \to \{0, 1, \ldots, w - 1\},$$

for every $j$.

---

## Count-min sketch: algorithm

**Initialization:** $C[j, k] = 0$, for every $0 \leq j < d$ and $0 \leq k < w$.

**For each $x_t$ in $\Sigma$ do**
&emsp;**For** $0 \leq j \leq d - 1$ **do** $C[j, h_j(x_t)] \leftarrow C[j, h_j(x_t)] + 1$;

**At the end of the stream:** for any $u \in U$, its frequency $f_u$ can be estimated as:

$$\tilde{f}_u = \min_{0 \leq j \leq d-1} C[j, h_j(u)].$$

**Observations:**

- $d$ and $w$ are *design parameters* that regulate the tradeoff between space, time, and accuracy.
- By construction, for any $u \in U$ and $0 \leq j < d$, we clearly have $C[j, h_j(u)] \geq f_u$. This justifies the minimum, but also shows that $\tilde{f}_u$ **is a BIASED ESTIMATOR!**

---

## Example: $n = 15,\ d = 3,\ w = 3$ *(handwritten)*

$\Sigma = A, B, C, B, D, A, C, D, A, B, D, C, A, A, B$

| $u, f_u$ | $h_0$ | $h_1$ | $h_2$ |
|---------|-------|-------|-------|
| A, 5    | 0     | 1     | 1     |
| B, 4    | 1     | 2     | 1     |
| C, 3    | 0     | 0     | 2     |
| D, 3    | 1     | 1     | 2     |

Array $C$:

|        | col 0          | col 1          | col 2  |
|--------|----------------|----------------|--------|
| row 0  | $8 = 5A+3C$    | $7 = 4B+3D$    | $0$    |
| row 1  | $3 = 3C$       | $8 = 6A+3D$    | $4 = 4B$ |
| row 2  | $0$            | $9 = 5A+4B$    | $6 = 3C+3D$ |

- $\tilde{f}_A = \min\{8, 8, 9\} = 8 > f_A = 5 \quad h_0(A) = 0$
- $\tilde{f}_B = \min\{7, 4, 9\} = 4 = f_B$
- $\tilde{f}_C = \min\{8, 3, 6\} = 3 = f_C$
- $\tilde{f}_D = \min\{7, 8, 6\} = 6 > f_D = 3$

---

## Count-min sketch: analysis of accuracy

**We assume that:**

- For each $j \in [0, d - 1]$ and each $u, v \in U$ with $u \neq v$, $h_j(u)$ and $h_j(v)$ are independent random variables uniformly distributed in $[0, w - 1]$.
- The $d$ hash functions $h_1, h_2, \ldots, h_d$ are mutually independent.

> **Theorem**
>
> Consider a $d \times w$ count-min sketch for a stream $\Sigma$ of length $n$, where $d = \log_2(1/\delta)$ and $w = 2/\epsilon$, for some $\delta, \epsilon \in (0, 1)$. The sketch ensures that for any given $u \in U$ occurring in $\Sigma$
>
> $$\tilde{f}_u - f_u \leq \epsilon \cdot n,$$
>
> with probability $\geq 1 - \delta$.

**Obs.:** The bias in the estimated frequencies discourages their use to estimate the second moment $F_2$.

---

## APPLICATIONS of the COUNT-MIN SKETCH *(handwritten)*

1) **HEAVY HITTERS**. The sketch allows to quickly and effectively identify frequent items ($f_u \geq \phi n$) detecting each such item as soon as $f_u \geq \phi n$ rather than a posteriori, which would be expensive.

2) **QUERY PLANNING**. In a relational database query that requires joining several large tables, the order of execution of the joins may heavily affect the running time. To choose the best ordering it is important to estimate the resulting size of each individual join. For example, consider the join of 2 tables $A, B$ with a common attribute $x$.

SQL query:
```
SELECT *
FROM  A, B
WHERE A.x = B.x
```

To estimate the number of rows in the resulting table do:

* Create a $d \times w$ count-min sketch $C_A$ for $A.x$
* Create a $d \times w$ count-min sketch $C_B$ for $B.x$

IMPORTANT: use the same $d$ hash functions for $C_A$ and $C_B$

---

*(handwritten, pagina 29)*

An estimate of the number of rows in the table resulting from the join is given by:

$$\min_{0 \leq j < d} \sum_{k=0}^{w-1} C_A[j,k] * C_B[j,k]$$

**PROOF OF THEOREM**: let's fix an arbitrary item $u \in \Sigma$. For each row $j$ ($0 \leq j < d$) the error in the estimate of $f_u$ provided by row $j$ is $C[j, h_j(u)] - f_u$. Note that $C[j, h_j(u)]$ receives "in expectation" a fraction $w$ of the entire mass $n$ (= total number of elements in $\Sigma$). Precisely

$$E\left[C[j, h_j(u)] - f_u\right] = \sum_{\substack{a \in U \\ a \neq u}} f_a \cdot \Pr(h_j(a) = h_j(u))$$

$$= \sum_{\substack{a \in U \\ a \neq u}} f_a \cdot \frac{1}{w} \leq \sum_{a \in U} f_a \cdot \frac{1}{w} = \frac{n}{w} = \frac{n \cdot \epsilon}{2}$$

Now we are interested in $\Pr\left(C[j, h_j(u)] - f_u > \epsilon n\right)$

---

*(handwritten, pagina 31)*

$$\Pr\left(C[j, h_j(u)] - f_u > \epsilon n\right) = \Pr\left(C[j, h_j(u)] - f_u > \frac{2\epsilon n}{2}\right)$$

$$\leq \Pr\left(C[j, h_j(u)] - f_u > 2 E\left[C[j, h_j(u)] - f_u\right]\right)$$

since $E\left[C[j, h_j(u)] - f_u\right] \leq \epsilon n/2$

$$\leq \Pr\left(C[j, h_j(u)] - f_u \geq 2 E\left[C[j, h_j(u)] - f_u\right]\right)$$

$$\leq \frac{1}{2} \quad \text{by Markov's inequality}$$

Final steps:

$$\Pr\left(\tilde{f}_u - f_u > \epsilon n\right) = \Pr\left(\forall\ 0 \leq j < d\ \ C[j, h_j(u)] - f_u > \epsilon n\right)$$

---

*(handwritten, pagina 32)*

$$= \prod_{j=0}^{d-1} \Pr\left(C[j, h_j(u)] - f_u > \epsilon n\right) \quad \text{by independence of the } h_j\text{'s}$$

$$\leq \left(\frac{1}{2}\right)^d$$

Since $d = \log_2(1/\delta)$, $\left(\frac{1}{2}\right)^d = \delta$

Therefore, $\Pr\left(\tilde{f}_u - f_u \leq \epsilon n\right) \geq 1 - \delta \quad \square$

## Count sketch

The **count sketch** was invented by [Charikar, Chen, Farach-Colton 2002], and can be seen as an **unbiased variant of the count-min sketch**.

**IDEA:** for each item $u \in U$ multiply its contributions to each row by a value in $\{-1, +1\}$ randomly selected, so to **cancel out collisions**.

**Main ingredients**

- $d \times w$ array $C$ of counters ($O(\log n)$ bits each)
- $d$ hash functions: $h_0, h_1, \ldots, h_{d-1}$, with

$$h_j\ :\ U \to \{0, 1, \ldots, w - 1\},$$

for every $j$.

- $d$ hash functions: $g_0, g_1, \ldots, g_{d-1}$, with

$$g_j\ :\ U \to \{-1, +1\},$$

for every $j$.

---

## Count sketch: algorithm

**Initialization:** $C[j, k] = 0$, for every $0 \leq j < d$ and $0 \leq k < w$.

**For each $x_t$ in $\Sigma$ do**
&emsp;**For** $0 \leq j \leq d - 1$ **do** $C[j, h_j(x_t)] \leftarrow C[j, h_j(x_t)] + g_j(x_t)$;

**At the end of the stream:** for any $u \in U$ and $0 \leq j < d$, let

$$\tilde{f}_{u,j} = g_j(u) \cdot C[j, h_j(u)].$$

The frequency of $u$ can be estimated as:

$$\tilde{f}_u = \text{median of the } \tilde{f}_{u,j}\text{'s}$$

---

## Count sketch: analysis of accuracy

**Assumptions:** for both sets of hash functions (the $h_j$'s and the $g_j$'s) we make the same assumptions of independence and uniform distribution, which we made for the $h_j$'s in the analysis of the count-min sketch.

> **Theorem**
>
> Consider a $d \times w$ count sketch for a stream $\Sigma$ of length $n$, where $d = \log_2(1/\delta)$ and $w = O(1/\epsilon^2)$, for some $\delta, \epsilon \in (0, 1)$. The sketch ensures that for any given $u \in U$ occurring in $\Sigma$:
>
> 1. $E[\tilde{f}_{u,j}] = f_u$, for any $j \in [0, d - 1]$, i.e., $\tilde{f}_{u,j}$ is an unbiased estimator of $f_u$;
>
> 2. With probability $\geq 1 - \delta$,
>
> $$|\tilde{f}_u - f_u| \leq \epsilon \cdot \sqrt{F_2},$$
>
> where $F_2 = \sum_{u \in U}(f_u)^2$ (true second moment).

*(handwritten annotation: we skip the proof of this point)*

**Intuition.** Due to the random signs, on average the "noise" created by several items colliding on the same column as $u$, cancel out.

## COMPARISON: Count-min VS Count Sketch *(handwritten)*

|          | count-min   | count sketch |
|----------|-------------|--------------|
| BIAS     | biased      | unbiased     |

ACCURACY: For any $u \in U$, with prob $\geq 1 - \delta$

count-min: $\tilde{f}_u - f_u \leq \epsilon n$

count sketch: $|\tilde{f}_u - f_u| \leq \epsilon \sqrt{F_2}$

Now: $F_2 = \sum_{u \in U} (f_u)^2 \leq \left(\sum_{u \in U} f_u\right)^2 = n^2 \Rightarrow \sqrt{F_2} \leq n$

So, count sketch has an error bound not worse than the one of count-min (but uses a larger $w$)

If the distribution of the frequencies is not too skewed, however, we can have $\sqrt{F_2} \ll n$ and the error bound for count sketch becomes much lower.

---

## PROOF OF THEOREM (only point 1) *(handwritten)*

Fix $u \in U$ and $j \in [0, d-1]$ arbitrarily. We now show that $E[\tilde{f}_{u,j}] = f_u$. Recall that $\tilde{f}_{u,j} = g_j(u) \cdot C[j, h_j(u)]$.

For every $a \in U$, $a \neq u$, we define a random variable $Y_a$ which represents the contribution of $a$ to $\tilde{f}_{u,j}$:

$$Y_a = \begin{cases} f_a & \text{if } h_j(a) = h_j(u) \text{ AND } g_j(a) = g_j(u) \\ -f_a & \text{if } h_j(a) = h_j(u) \text{ AND } g_j(a) = -g_j(u) \\ 0 & \text{otherwise} \end{cases}$$

It is easy to see that $\tilde{f}_{u,j} = f_u + \displaystyle\sum_{\substack{a \in U \\ a \neq u}} Y_a$

Now observe that:
- $\Pr(Y_a = f_a) = \dfrac{1}{w} \cdot \dfrac{1}{2}$
- $\Pr(Y_a = -f_a) = \dfrac{1}{w} \cdot \dfrac{1}{2}$

their sum is $1/w$

- $\Pr(Y_a = 0) = 1 - 1/w$

---

*(handwritten, pagina 42)*

We have:

$$E[\tilde{f}_{u,j}] = E\left[f_u + \sum_{\substack{a \in U \\ a \neq u}} Y_a\right] = f_u + E\left[\sum_{\substack{a \in U \\ a \neq u}} Y_a\right]$$

$$= f_u + \sum_{\substack{a \in U \\ a \neq u}} E[Y_a] \quad \text{by linearity of expectation}$$

And $E[Y_a] = f_a \cdot \dfrac{1}{w} \cdot \dfrac{1}{2} - f_a \cdot \dfrac{1}{w} \cdot \dfrac{1}{2} + 0 \cdot (1 - 1/w) = 0$

$$\Rightarrow E[\tilde{f}_{u,j}] = f_u + \sum_{\substack{a \in U \\ a \neq u}} 0 = f_u \quad \square$$

## Estimation of $F_2$

Given a $d \times w$ count sketch for $\Sigma$, define

$$\tilde{F}_{2,j} = \sum_{k=0}^{w-1} (C[j,k])^2 \quad \text{for } 0 \leq j < d$$

We can derive the following estimate for the true second moment $F_2$:

$$\tilde{F}_2 = \text{median of the } \tilde{F}_{2,j}\text{'s}$$

## Proof of point 1 (only a hint) *(handwritten)*

Follow these steps. Fix an arbitrary row $j$.

1. If $a, b \in U$, $a \neq b$, define

$$Y_{ab} = \begin{cases} f_a f_b & \text{if } h_j(a) = h_j(b) \text{ AND } g_j(a) = g_j(b) \\ -f_a f_b & \text{if } h_j(a) = h_j(b) \text{ AND } g_j(a) = -g_j(b) \\ 0 & \text{otherwise} \end{cases}$$

So, $Y_{ab}$ relates to the noise contributed by $a$ and $b$ to $\tilde{F}_{2,j}$.

## Analysis of performance metrics

Both **count-min** and **count sketches** can be computed in **1 pass**

**To assess space and time performance, we assume:**

- Each hash function can be applied in constant time
- The space occupied by the sketch dominates over the one needed to store the hash functions

**For both sketches we have:**

- **Working memory:** $O(d \cdot w)$, which becomes $O(\log(1/\delta)/\epsilon)$, for the count-min sketch, and $O(\log(1/\delta)/\epsilon^2)$, for the count sketch, in order to attain the probabilistic accuracy stated before.
- **Update time:** $O(d) = O(\log(1/\delta))$,
- **Query time:** any $\tilde{f}_u$ (individual frequency) is computed in $O(d)$ time, while $\tilde{F}_2$ (second moment) in $O(d \cdot w)$ time.

## Filtering

---

## Motivation

For many applications, processing a data stream $\Sigma = x_1, x_2, \ldots$ entails essentially the identification of the $x_i$'s which meet a certain criterion.

Some criteria can be checked very easily with a minimum cost in terms of space and time. However, this is not always the case.

**Example.** Suppose that the $x_i$'s are email addresses and that when $x_i$ arrives we need to check whether it belongs to a set $S$ of *verified* addresses. If $S$ is very large (e.g., 1 billion addresses of approximately 20 bytes each), we face two issues:

- If $S$ does not fit into main memory, it must be **stored on disk**.
- Standard exact techniques to check $x_i \in S$, especially if $S$ is on disk, may be time consuming and **not compatible with a high arrival rate**.

**Can we check membership efficiently with reasonable accuracy?**

---

## Bloom filter

> **Approximate membership problem**
>
> Given a stream $\Sigma = x_1, x_2, \ldots$ of elements from some universe $U$, and let $S$ be a set of $m$ elements from $U$. Store $S$ into a compact data structure that, for any given $x_t$, allows to check whether $x_t \in S$ with
>
> - no error, when $x_t \in S$ (**No false negatives**)
> - small probability error, when $x_t \notin S$ (**Small false positive rate**)

A solution to the problem comes from the **Bloom filter**, introduced in [Bloom 1970]. Its **main ingredients** are:

- Array $A$ of $n$ bits, all initially 0.
- $k$ hash functions: $h_0, h_1, \ldots, h_{k-1}$, with

$$h_j\ :\ U \to \{0, 1, \ldots, n - 1\} \quad \text{for every } 0 \leq j < k$$

Note that $n$ and $k$ are *design parameters* that regulate the tradeoff between space/time and accuracy.

---

## Bloom filter

**Initialization of the bit array $A$:**

```
for each e ∈ S do
    for 0 ≤ j < k do A[h_j(e)] ← 1;
```

**Membership test:** for any $x_t$ in $\Sigma$

```
if A[h_0(x_t)] = A[h_1(x_t)] = ··· = A[h_{k-1}(x_t)] = 1 then claim x_t ∈ S
else claim x_t ∉ S
```

**Straightforward properties:**

- The approach ensures that there are **no false negatives**
- Assuming that $k \ll n$, and that the hash functions can be stored compactly, the **required working memory** is dominated by the storage of $A \Rightarrow n$ bits.
- Assuming that each hash function can be applied in $O(1)$ time, the membership test requires $O(k)$ time.

---

## Bloom filter: analysis of false positive rate

**Assumptions:** for the set of hash functions (the $h_j$'s) we make the same assumptions of independence and uniform distribution, which we made in the analysis of the count-min sketch.

> **Theorem**
>
> Suppose that $n$ is sufficiently large. For any given $x_i$ which does not belong to $S$, the probability that $x_i$ is erroneously claimed to be in $S$ is
>
> $$\Pr(A[h_j(x_i)] = 1 \text{ for each } 0 \leq j < k) \simeq (1 - e^{-km/n})^k$$
>
> This probability is referred to as **false positive rate**.

**Email example:** In the case of email addresses mentioned before, $m = 10^9$ and storing the entire set $S$ would require **20GB** (assuming that each ~~email~~ address *(handwritten annotation)* takes 20 bytes). Using a Bloom filter with $n = 8m$ (hence $|A| = 1\text{GB}$), and $k = 6$, the false positive rate is about 2.15%.

---

## Proof *(handwritten)*

Assuming that the $h_j$'s are independent and uniform in $[0, n-1]$, after the initialization of $A$ the indices of $A$ which are set to 1 can be seen as $k \cdot m$ independent random variables in $[0, n-1]$. With this observation we can now compute the probability that $A[\ell] = 0$, for any $\ell \in [0, n-1]$ (after the initialization).

$$\Pr(A[\ell] = 0) = \left(1 - \frac{1}{n}\right)^{km}$$

$$= \left(1 - \frac{1}{n}\right)^{n \cdot \frac{km}{n}} \quad \text{for large } n$$

$$= \left[\left(1 - \frac{1}{n}\right)^n\right]^{\frac{km}{n}} \approx e^{-km/n}$$

Define $p = e^{-km/n}$. We make the SIMPLIFYING ASSUMPTION that $A$ contains EXACTLY $p \cdot n$ 0's. (The theorem can be proved also without the assumption.)

Consider an element $x \in \Sigma$ such that $x \notin S$.

---

*(handwritten, pagina 62)*

Let $\ell_j = h_j(x)$, $0 \leq j < k$.

Since $\ell_j$ is uniformly distributed in $[0, n-1]$ we have that

$$\Pr(A[\ell_j] = 1) = 1 - \frac{p \cdot n}{n} = 1 - p \quad \leftarrow \text{probability of not hitting a 0}$$

Therefore

$$\Pr(A[\ell_0] = A[\ell_1] = \cdots = A[\ell_{k-1}] = 1) = (1 - p)^k$$

$$= \left(1 - e^{-km/n}\right)^k \quad \square$$

---

## OBSERVATIONS *(handwritten)*

It can be shown that for fixed $n, m$, the FALSE POSITIVE RATE (FPR) is minimized for $k = (\ln 2)\, n/m$. With this value of $k$, the FPR becomes

$$(1 - e^{-km/n})^k = \left(\frac{1}{2}\right)^k = (0.6185)^{n/m}$$

For example, $n = 8m$ and $k = 5$ or $6$, we get $\text{FPR} \in [0.01, 0.03]$ between $1\% - 3\%$.

---

## Alternative approach: FINGERPRINTING *(handwritten)*

An alternative approach to approximate membership is through FINGERPRINTING.

* Map each $x \in S$ into an integer $[0, 2^b - 1]$
* Let $r_1, r_2, \ldots, r_m$ be integers (FINGERPRINTS) associated to the elements of $S$
* A new element $x \in \Sigma$ is claimed to be in $S$ iff its fingerprint is equal to some $r_i$

To store the $r_i$'s we need $\Theta(m \cdot b)$ bits.

It can be shown that to get $\text{FPR} = 0.02$, $b$ must be $\Omega(\log m)$ while with the Bloom filter using 8 bits per element (independently of the value $m$) was sufficient to get $\text{FPR} \approx 0.02$.

## Hash functions

Hash functions are fundamental ingredients of many data processing tools: e.g., hash tables, sketches, filters, signatures, integrity checks.

A hash function $h$ usually maps the elements of a universe $U$ (e.g., all 64-bit numbers) into hash values represented by the integers in the range $[m] = \{0, 1, \cdots, m - 1\}$, for some $1 \leq m \leq |U|$. *(handwritten annotation: usually $m \ll |U|$)*

To simplify the analysis, it is often assumed that $h$ is a **truly random hash function**, in the sense that $\{h(x) : x \in U\}$ is a set of $|U|$ independent random variables with uniform distribution over $[m]$

---

## Hash functions

A truly random hash function can be regarded as a random variable with uniform distribution over $[m] \times [m] \times \cdots \times [m]$ ($|U|$ times). $\Rightarrow$ representing a truly random hash function requires $|U| \log_2 m$ bits *(handwritten annotation: $m^{|U|}$ possible functions)*.

*(handwritten annotation: $\log_2 m^{|U|} = |U| \log_2 m$)*

$\Rightarrow$ representing a truly random hash function requires $|U| \log_2 m$ bits *(handwritten annotation: $= |U| \log_2 m$)*

In practice, we need hash functions which provide sufficient randomness for the application of interest, and are efficient in terms of

- **Space:** number of bits required by their representation
- **Speed:** time to compute the hash values.

---

## k-universality

> **Definition: k-universality**
>
> A family $\mathcal{H}$ of hash functions from $U$ to $[m]$ is said to be **k-universal** if for any $k$ distinct elements $x_1, x_2, \ldots, x_k$ from $U$, we have that for a hash function $h$ extracted from $\mathcal{H}$ uniformly at random
>
> $$\Pr(h(x_1) = h(x_2) = \cdots = h(x_k)) \leq \frac{1}{m^{k-1}}.$$
>
> Moreover, $\mathcal{H}$ is said to be **strongly k-universal** if for any $k$ distinct elements $x_1, x_2, \ldots, x_k$ of $U$, and any $k$ values $y_1, y_2, \ldots, y_k$ from $[m]$, we have that for a hash function $h$ extracted from $\mathcal{H}$ uniformly at random
>
> $$\Pr((h(x_1) = y_1) \wedge (h(x_2) = y_2) \wedge \cdots \wedge (h(x_k) = y_k)) = \frac{1}{m^k}$$

**Remark.** Using hash functions randomly extracted from a 2-universal family yield the same theoretical guarantees as truly random functions for: hash tables with chaining, count-min sketch, signature.

---

## Practical hash functions

Let the universe $U$ be the set of integers $[u] = \{0, 1, \ldots, u - 1\}$, and $[m]$ be the range. Fix a prime number $p > u$. For $1 \leq a \leq p - 1$ and $0 \leq b \leq p - 1$ define the function $h_{a,b} : [u] \to [m]$ so that

$$h_{a,b}(x) = ((ax + b) \bmod p) \bmod m \quad \text{for every } x \in [u].$$

> **Theorem**
>
> The family
>
> $$\mathcal{H}_p = \{h_{a,b} : 1 \leq a \leq p - 1,\ \text{and}\ 0 \leq b \leq p - 1\}$$
>
> is **2-universal**

*(handwritten annotation: \# bits needed to represent any $h_{a,b}$ is $\Theta(\log_2 p)$ and if $p$ is not too large w.r.t. $u$, $\Theta(\log_2 u)$ bits suffice)*

---

## Practical hash functions

Convenient primes to be used for the family defined in the previous slide, are the so called **Mersenne primes**, that is, primes of the form $p = 2^q - 1$. For example,

$$p = 2^{13} - 1 = 8191$$
$$p = 2^{61} - 1$$
$$p = 2^{89} - 1$$

are all Mersenne primes. The latter two, can be used when $U$ is the set of 32-bit integers or the set of 64-bit integers, respectively.

The advantage of using a Mersenne prime $p = 2^q - 1$ is that the modulo operation is simplified by the relation

$$x \bmod p = ((x \bmod 2^q) + \lfloor x/2^q \rfloor) \bmod p,$$

which reduces the modulo to fast bit shifts and additions, thus yielding an efficient implementation.
