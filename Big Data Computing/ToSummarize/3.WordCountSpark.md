## Slide 5 — Functional programming

One of the core ideas of functional programming is that functions can be arguments to other functions.

- In a MapReduce algorithm, the map and reduce functions used in each round can be regarded as "arguments" for the round.
- Spark's API relies heavily on passing functions. For example, many methods (e.g., RDD operations) require functions as arguments.

In Spark there are essentially 2 ways to pass functions as arguments to a method.

- as anonymous functions or lambdas which are defined inline without a name, where the actual argument is expected.
- as named functions defined outside the method.

---

## Slide 6 — Functional programming: Java example

Let `values` be an RDD of doubles (i.e., of type `JavaRDD<Double>`)

USE of ANONYMOUS FUNCTIONS

- **Single statement**:

```java
JavaRDD<Double> squaredValues = values.map((x) -> x*x);
```

- **Multiple statements**:

```java
double fixed = 1.5;
JavaRDD<Double> normValues = values.map((x) -> {
  double diff = fixed - x;
  return diff;
});
```

**Obs.:** `squaredVales` (resp. `normValues`) are RDDs containing the elements of `values` squared (resp., normalized).

## Slide 10 — Common assumptions

- **Input:** file of documents, one document per line.
- **Output:** $(w, c(w))$ pairs, with $w \equiv$ word and $c(w) \equiv$ number of occurrences of $w$ in the documents
- **Command Line Arguments:**
  - *L*: number of partitions for the RDD
  - *data\_path*: where the input file is located

## Slide 13 — Spark Configuration and Input Reading: spiegazione

- **Spark Setup:** sets the configuration object, the context object, and the name of the application. (See "Introduction to Programming in Spark" for details)
- **textfile:** transforms the input file into an RDD of Strings, whose elements correspond to the distinct lines of the file (i.e., the documents in the example)
- **repartition(L):** subdivides the RDD elements, at random, into $L$ groups, referred to as *partitions*
- **cache():** tells Spark that the first time that the RDD is materialized, its elements must be stored permanently in the executors' main memories, if they fit.

## Slide 14 — Initial Map Phase (scritta a mano)

↓ flatMapToPair (Java) or flatMap (Python)

RDD of (w, c(w)) pairs

At this point ∀ word w we have a pair (w, c(w)) for every document where w occurs, and the value c(w) is the number of occurrences of w in that particular document

## Slide 15 — Initial Map Phase: Java

```java
JavaPairRDD<String, Long> wordCounts = docs
  .flatMapToPair(myMethods::wordCountPerDoc) // <-- MAP PHASE
....

Class myMethods {
    public static Iterator<Tuple2<String,Long>>
                    wordCountPerDoc(String document) {
        String[] tokens = document.split(" ");
        HashMap<String, Long> counts = new HashMap<>();
        ArrayList<Tuple2<String, Long>> pairs = new ArrayList<>();
        for (String token : tokens) {
            counts.put(token, 1L + counts.getOrDefault(token, 0L));
        }
        for (Map.Entry<String, Long> e : counts.entrySet()) {
            pairs.add(new Tuple2<>(e.getKey(), e.getValue()));
        }
        return pairs.iterator();
    }
....
}
```

## Slide 16 — Initial Map Phase: spiegazione Java

- **Tuple2:** In Java, key-value pairs are represented using type `Tuple2<K,V>`, where K and V are the domains for keys and values, respectively. For a Tuple2 object T
  - `T._1()` returns the key
  - `T._2()` returns the value

- **JavaPairRDD:** In Java, RDDs of (key,value) pairs are represented as instances of type `JavaPairRDD<K,V>`, whose elements are instances of type `Tuple2<K,V>`.

- **flatMapToPair:** transforms each RDD element (a document, in the example) into $\geq 0$ pairs (of type Tuple2). The function passed as argument (`wordCountPerDoc`, in the example) must return the pairs as an iterator.

**Obs.** In case exactly one pair must be returned, `MapToPair` instead of `flatMapToPair` can be used.

## Slide 19 — 1-Round Algorithm: Java

```java
JavaPairRDD<String, Long> wordCounts = docs
    .flatMapToPair(myMethods::wordCountPerDoc) // <-- MAP PHASE
    .groupByKey() // SHUFFLING+GROUPING
    .mapValues((it) -> { // <-- REDUCE PHASE
        long sum = 0;
        for (long c : it) sum += c;
        return sum;
    })
```

Observation: to illustrate the various possibilities to pass functions, `flatMapToPair` receives in input a named function, while `mapValues` receives in input an anonymous function

## Slide 22 — groupByKey e mapValues: spiegazione

- **groupByKey:** collects the elements (pairs) of the RDD with the same key, and returns an RDD of (key,list-of-values) pairs. In Java, list-of-values is returned as an iterator.

- **mapValues:** transforms each pair by retaining the key and processing its value through the function passed as argument. In the example, the value of each pair is, in fact, a list (provided as an iterator in Java).

## Slide 23 — More Efficient Implementation

Thee combination of `groupByKey` and `mapValues` can be replaced by the ready-made method `reduceByKey` as follows:

JAVA:

```java
JavaPairRDD<String, Long> wordCounts = docs
  .flatMapToPair(myMethods::wordCountPerDoc) // <-- MAP PHASE
  .reduceByKey((x, y) -> x+y);    // <-- REDUCE PHASE
```

PYTHON:

```python
word_count = (docs.flatMap(word_count_per_doc) # <-- MAP PHASE
    .reduceByKey(lambda x, y: x + y))          # <-- REDUCE PHASE
```

---

## Slide 24 — reduceByKey: spiegazione

- **reduceByKey:** for each key $k$ occurring in the RDD, the method combines the values of all pairs with key $k$ in the RDD, applying the function passed as argument, which is regarded as a binary operator (the sum, in the example), in a tree-like fashion.

IMPORTANT OBSERVATIONs:

- The programmer has no control on the sequence of binary aggregations performed by `reduceByKey`, hence the function passed as argument must be commutative and associative.
- For efficiency, Spark will do the aggregation first within the partitions of the RDD, and then across partitions. Thus, it is a sort of 2-round algorithm in disguise

---

## Slide 26 — 2-Round Algorithm: general structure

**Round 1**

- **Map Phase:** for each document $D_i$ compute local count $c_i(w)$ of each word $w$ and partition $(w, c_i(w))$ pairs among $L$ partitions.
- **Reduce Phase:** for each word $w$ aggregate local counts separately for each partition producing (at most) $L$ pairs $(w, c(x,w))$, one for every partition $x$, with $0 \leq x < L$

**Round 2**

- **Map Phase:** empty.
- **Reduce Phase:** for each word $w$ aggregate the $c(x,w)$ counts into the final count $c(w)$ and produce the pair $(w, c(w))$.

---

## Slide 27 — 2-Round: due tecniche di partitioning

We will explore two partitioning techniques:

1. Random keys assigned on the fly during groupBy in Round 1
2. Reuse of the RDD partitions defined by Spark

NOTE. In the complete `WordCountExample` code that we provide, you will find a third version where random keys are assigned explicitly during the Map Phase of Round 1. This version, which is not discussed in these slides, is functionally equivalent (but less efficient) than the one that does the key assignment within groupBy. However, it is useful as a further example of how a Map Phase can transform an initial set of elements.

## Slide 31 — 2-Round Random Keys: Java — gatherPairs

```java
class myMethods {

  public static Iterator<Tuple2<String,Long>>
          wordCountPerDoc(String document) {... seen before ...}

  public static Iterator<Tuple2<String,Long>> gatherPairs
        (Tuple2<Integer,Iterable<Tuple2<String, Long>>> element) {
    HashMap<String, Long> counts = new HashMap<>();
    for (Tuple2<String, Long> c : element._2()) {
        counts.put(c._1(),c._2()+counts.getOrDefault(c._1(),0L));
    }
    ArrayList<Tuple2<String, Long>> pairs = new ArrayList<>();
    for (Map.Entry<String, Long> e : counts.entrySet()) {
        pairs.add(new Tuple2<>(e.getKey(), e.getValue()));
    }
    return pairs.iterator();
  }
}
```

## Slide 32 — groupBy: spiegazione

`groupBy` does the following actions:

- Transforms each element of the RDD into a pair (key,element), where key is assigned through the function passed as argument. In the example, a random integer key in $[0, L)$ is assigned, and element is a (word,count) pair.
- For each key $k$, collects the pairs with key $k$ into a new pair ($k$, list-of-values). In the example, the list-of-values is a list of (word,count) pairs.

**Observation.** Thus, in the example, `groupBy` produces, as a result, an RDD of (key, list-of-(word,count)-pairs). The elements of this RDD are then processed, individually, by the subsequent `flatMapToPair` (using the `gatherPairs` function in the example)

  for p in pairs[1]:
    word, occurrences = p[0], p[1]
    if word not in pairs_dict.keys():
        pairs_dict[word] = occurrences

def word_count_2(docs, L):

## Slide 37 — mapPartitionsToPair: spiegazione

For each partition of the RDD (created by Spark), separately, `mapPartitionsToPair` applies the function, passed as argument, to the elements of RDD which belong to that partition. The elements of the partition are provided in input to the function as an iterator. The function must return $\geq 0$ pairs (of type Tuple2).

In the example, each partition contains (word,count) pairs, where the counts are relative top individual documents. The execution `mapPartitionsToPair` will result again in an RDD of (word,count) pairs where, however, the counts have been aggregated within each partitions.

---

## Slide 38 — 2-Round Algorithm with Spark Partitions: Python

```python
def gather_pairs_partitions(pairs):
  pairs_dict = {}
  for p in pairs:
    word, occurrences = p[0], p[1]
    if word not in pairs_dict.keys():
        pairs_dict[word] = occurrences
    else:
        pairs_dict[word] += occurrences
  return [(key, pairs_dict[key]) for key in pairs_dict.keys()]


def word_count_with_partition(docs):
  word_count = (docs.flatMap(word_count_per_doc) # <-- MAP PHASE (R1)
    .mapPartitions(gather_pairs_partitions)       # <-- REDUCE PHASE (R1)
    .groupByKey()                                 # <-- SHUFFLE+GROUPING
    .mapValues(lambda vals: sum(vals)))            # <-- REDUCE PHASE (R2)
  return word_count
```

## Slide 40 — IMPORTANT OBSERVATIONs

IMPORTANT OBSERVATIONs. If an RDD is the result of a sequence of transformations:

- Its partitioning is inherited from the one produced by the last invocation of the `repartition` method, if any, or from the one initially created when data where loaded in memory.
- However, since data may have evolved substantially, the balancing is not guaranteed. To ensure it, the `repartition` method should be invoked, which, however, involves shuffling the data.
