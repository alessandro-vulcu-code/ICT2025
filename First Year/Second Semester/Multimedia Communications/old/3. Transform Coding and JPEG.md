# 3. Transform Coding and JPEG

> [!info] Course Context  
> This chapter covers **Transform Coding** - the paradigm of making signals sparse through linear transforms to achieve efficient compression. It builds upon block coding and quantization concepts, culminating in the JPEG standard implementation.

## Introduction: From Scalar to Block Coding

### Recall: SQ, PQ, EC

In **scalar quantization**, each sample is quantized independently, resulting in potentially large distortion:

| Quantizer Type | Distortion Formula |
|---|---|
| UQ for uniform RV | $D = \sigma_X^2 2^{-2R}$ |
| HR UQ for generic RV | $D = K_X \sigma_X^2 2^{-2R}$ |
| OQ for generic RV | $D = c_X \sigma_X^2 2^{-2R}$ |

When $L$ levels are equiprobable, the entropy of quantization indexes is $\log_2 L$, and an arithmetic encoder achieves rate $R \to H = \log_2 L$.

> [!tip] Key Insight  
> To improve performance, we must exploit **sample dependence** through:
> 1. **Predictive quantization** - reduces signal variance
> 2. **Block coding** - exploits signal sparsity
> 3. **Transform coding** - makes the signal sparse

While predictive quantization (PQ) reduces signal variance, we now focus on **block coding** and **transform coding**.

### Overview of Transform Coding

1. **Block coding**: jointly encode $M$ samples
2. **Huang-Schulteiss formula**: optimal rate allocation for block coding
3. **Coding gain**: quantifies improvement over sample-by-sample coding (only if data are sparse!)
4. **Orthogonal transforms**: enable data sparsification
5. **Frequency transforms**: convenient special cases (DFT, DCT)
6. **JPEG**: implements these ideas for efficient image compression

## Block Coding

### Problem Formulation

Consider a block of $M$ random variables $X = [X_1, X_2, \ldots, X_M]^T$ (column vector). The RVs need **not** be independent nor i.d.

Let:
- $\sigma_k^2 = \text{Var}(X_k)$ - variance of each component
- $c_k$ - shape factor of $X_k$

The distortion of $X_k$ with an optimal quantizer is:

$$D_k = c_k \sigma_k^2 2^{-2R_k}$$

where $R_k$ is the bit rate used for $X_k$.

### Global Distortion

When jointly deciding rates for all $M$ components to minimize global distortion under a total rate constraint:

$$D = \frac{1}{M} E\left[\|X - Q(X)\|^2\right] = \frac{1}{M} E\left[\sum_{k=1}^M (X_k - Q(X_k))^2\right]$$

Expanding this:

$$D = \frac{1}{M} \sum_{k=1}^M E\left[(X_k - Q(X_k))^2\right] = \frac{1}{M} \sum_{k=1}^M D_k = \frac{1}{M} \sum_{k=1}^M c_k \sigma_k^2 2^{-2R_k}$$

> [!info] Definition — Resource Allocation Problem  
> Find the rate vector $R = [R_1, \ldots, R_M]^T$ such that global distortion is minimized under the constraint:
> $$\sum_{k=1}^M R_k = R_{\text{Tot}}$$
> This is solved using **Lagrange multipliers**.

### Resource Allocation: Mathematical Formulation

**Minimize** $D$ under rate constraint:

$$\min_{R} D(R) = \frac{1}{M} \sum_{k=0}^{M-1} c_k \sigma_k^2 2^{-2R_k} \quad \text{subject to} \quad \sum_{k=0}^{M-1} R_k \leq R_{\text{Tot}}$$

Using the **Lagrange method**, we minimize:

$$J(R, \lambda) = \frac{1}{M} \sum_{k=0}^{M-1} c_k \sigma_k^2 2^{-2R_k} + \lambda \left(\sum_{k=0}^{M-1} R_k - R_{\text{Tot}}\right)$$

### Huang-Schulteiss Formula

> [!important] Theorem — Huang-Schulteiss Formula  
> The optimal rate allocation is:
> $$R_k^* = \frac{R_{\text{Tot}}}{M} + \frac{1}{2} \log_2 \left(\frac{c_k \sigma_k^2}{c_{\text{GM}} \sigma_{\text{GM}}^2}\right)$$
> 
> where:
> - $c_{\text{GM}} = \left(\prod_{k=1}^M c_k\right)^{1/M}$ is the geometric mean of shape factors
> - $\sigma_{\text{GM}}^2 = \left(\prod_{k=1}^M \sigma_k^2\right)^{1/M}$ is the geometric mean of variances

**Proof**: Setting $\nabla J(R^*, \lambda^*) = 0$:

$$\frac{\partial J}{\partial R_k} = -\frac{2\ln 2}{M} c_k \sigma_k^2 2^{-2R_k} + \lambda = 0$$

Solving and imposing the constraint $\sum_{k=1}^M R_k^* = R_{\text{Tot}}$ yields the formula.

### Interpretation of HS Formula

> [!tip] Interpretation  
> The optimal rate allocation **refines** a uniform allocation ($\bar{R} = R_{\text{Tot}}/M$) using variances:
> - Allocate **more bits** to components with **larger variance**
> - Allocate **fewer bits** to components with **smaller variance**

**Per-component distortion** with optimal allocation:

$$D_k^* = c_k \sigma_k^2 2^{-2R_k^*} = c_k \sigma_k^2 2^{-2\bar{R}} \frac{c_{\text{GM}} \sigma_{\text{GM}}^2}{c_k \sigma_k^2} = c_{\text{GM}} \sigma_{\text{GM}}^2 2^{-2\bar{R}}$$

**Total distortion**:

$$D^* = \frac{1}{M} \sum_{k=0}^{M-1} D_k^* = c_{\text{GM}} \sigma_{\text{GM}}^2 2^{-2\bar{R}}$$

> [!note] Gaussian Case  
> For Gaussian RVs ($c_k = c_N$ for all $k$):
> $$R_k^* = \bar{R} + \frac{1}{2} \log_2 \left(\frac{\sigma_k^2}{\sigma_{\text{GM}}^2}\right), \quad D_k^* = c_N \sigma_{\text{GM}}^2 2^{-2\bar{R}}$$

### Arithmetic and Geometric Means

For a set of $M$ positive real numbers $\{z_1, z_2, \ldots, z_M\}$:

| Mean Type | Formula |
|---|---|
| **Arithmetic Mean (AM)** | $z_{\text{AM}} = \frac{1}{M} \sum_{k=1}^M z_k = \frac{z_1 + z_2 + \cdots + z_M}{M}$ |
| **Geometric Mean (GM)** | $z_{\text{GM}} = \sqrt[M]{\prod_{k=1}^M z_k} = (z_1 \cdot z_2 \cdots z_M)^{1/M}$ |

> [!important] Key Property  
> $z_{\text{GM}} \leq z_{\text{AM}}$ (from Jensen's inequality)  
> Equality holds **if and only if** all $z_k$ are equal.  
> The geometric mean becomes smaller as values become more diverse.

### Case of i.d. Random Variables

For coding multimedia signals where samples are **identically distributed** (i.d.) but not independent:

$$\forall k \in \{1, \ldots, M\}: \sigma_k^2 = \sigma_X^2 \Rightarrow \sigma_{\text{GM}}^2 = \sigma_X^2$$

$$c_k = c_X \Rightarrow c_{\text{GM}} = c_X$$

$$R_k^* = \bar{R} + \frac{1}{2} \log_2 \left(\frac{c_k \sigma_k^2}{c_{\text{GM}} \sigma_{\text{GM}}^2}\right) = \bar{R}$$

$$D_k^* = c_{\text{GM}} \sigma_{\text{GM}}^2 2^{-2\bar{R}} = c_X \sigma_X^2 2^{-2\bar{R}}$$

> [!warning] Important  
> When samples are i.d., the signal is **not sparse** (all samples equally important). Thus, block coding brings **no improvement** unless we can reduce $\sigma_{\text{GM}}^2$ through transformation.

## Transform Coding

### Signal Sparsification

> [!info] Definition — Linear Transform for Sparsification  
> A linear transform is a **base change** aiming to make the signal **sparse**: a few large samples and many small (near-zero) samples.

**Goals of transform coding**:
- Use **high-resolution** (high bit-rate) quantizers on "important" coefficients
- Use **low-resolution** quantizers on irrelevant coefficients
- Apply Huang-Schulteiss formula to decide coding rates
- Transform i.d. RVs into a block where variances are as diverse as possible (minimizing $\sigma_{\text{GM}}^2$)

### Linear Transforms as Sparsifying Operators

We seek an operator $T$ such that:
- **Reversible**: $Y = T(X) \Leftrightarrow X = T^{-1}(Y)$
- **Input**: Vector in $\mathbb{R}^M$ (e.g., $M$ samples of voice, $M_1 \times M_2$ pixels)
- **Input is not sparse**: all samples potentially meaningful
- **Output is sparse**: few non-negligible, many negligible samples
- **Quantization error preserved**: error on $Y$ equals error on $X$

### Frequency Analysis as Sparsification
![[Pasted image 20260327171731.png]]
**Example**: A vector $x$ of $M$ samples from a sound signal (pure tone) is **non-sparse** - all samples equally important.

After transform $y = Ax$ with orthogonal matrix $A$ performing frequency analysis, the result is **sparse**: one non-negligible sample and $N-1$ negligible samples.

### Linear Transform Paradigm
![[Pasted image 20260327171923.png]]
```
x → y = T·x → [Q1, Q2, ..., QM] → yb → xb = T⁻¹·yb
        y1    yb1
        y2    yb2
        ...   ...
        yM    ybM
```

From $x$ to $y = Tx$: obtain an "easier" vector for coding (few large coefficients, many small ones).

### Orthogonal Transforms

> [!info] Definition — Orthogonal Transform (OT)  
> An orthogonal transform means matrix $T$ is orthogonal, thus:
> $$T^{-1} = T^T, \quad Y = TX, \quad X = T^T Y$$

**Properties**:
1. **Inversion is immediate** (just transpose)
2. **Isometry property**: preserves $L_2$ norm
   $$\|TX\|^2 = (TX)^T(TX) = X^T T^T T X = X^T X = \|X\|^2$$

> [!important] Isometry and Distortion Preservation  
> The isometry property ensures distortion on $Y$ equals distortion on $X$:
> $$D_Y = \frac{1}{M} E\left[\|Y - \hat{Y}\|^2\right] = \frac{1}{M} E\left[\|T(X - \hat{X})\|^2\right] = \frac{1}{M} E\left[\|X - \hat{X}\|^2\right] = D_X$$

Only with preserved distortion can minimization over $Y$ effectively minimize over $X$.

### Orthogonal Transforms and Coding Gain

Let $X$ be a random vector of $M$ components with:
- Components i.d. Gaussian: $\forall k, X_k \sim N(0, \sigma_X^2)$
- Not assumed independent

**Without transform** (direct block quantization):
$$D_{\text{PCM}} = c_N \sigma_X^2 2^{-2\bar{R}}$$

**With transform** $Y = TX$ and optimal resource allocation:
$$D_Y = c_{\text{GM},Y} \sigma_{\text{GM},Y}^2 2^{-2\bar{R}}$$

> [!important] Coding Gain  
> The **Coding Gain** of transform $T$ is:
> $$G_T = \frac{D_{\text{PCM}}}{D_T} = \frac{c_N \sigma_X^2 2^{-2\bar{R}}}{c_N \sigma_{\text{GM},Y}^2 2^{-2\bar{R}}} = \frac{\sigma_{\text{AM},Y}^2}{\sigma_{\text{GM},Y}^2}$$
> 
> Since $\sigma_{\text{AM},Y}^2 = \sigma_X^2$ is constant for any OT, we seek $T$ that **minimizes** $\sigma_{\text{GM},Y}^2$.

**Key insight**: The transform must **sparsify** the signal - make variances as diverse as possible.

## Transform Coding: Toy Example

### Problem Setup
![[Pasted image 20260327172511.png]]
Consider two **highly correlated** random variables $X_1, X_2$ with:
- Uniform joint PDF over region $S$: $f_{X_1,X_2}(x_1,x_2) = \frac{1}{\Delta_1 \Delta_2}$ for $(x_1, x_2) \in S$
- $\Delta_1 \gg \Delta_2$ (strong correlation)
- Marginal distributions: $X_1 \sim X_2 \sim U\left(-\frac{\Delta_1}{2\sqrt{2}}, \frac{\Delta_1}{2\sqrt{2}}\right)$
- Variances: $\sigma_1^2 = \sigma_2^2 = \sigma^2 = \frac{\Delta_1^2}{24}$

### Scalar Quantization in Original Domain

Using uniform quantization (optimal for uniform variables):

$$D_i(R_i) = \sigma^2 2^{-2R_i}$$

Total distortion: $D = D_1 + D_2$

| bits | R | $D_1$ | $D_2$ | $D$ |
|---|---|---|---|---|
| 0 | 0 | $\sigma^2$ | $\sigma^2$ | $2\sigma^2$ |
| 1 | 0.5 | $\sigma^2/4$ | $\sigma^2$ | $\frac{5}{4}\sigma^2$ |
| 1 | 0.5 | $\sigma^2$ | $\sigma^2/4$ | $\frac{5}{4}\sigma^2$ |
| 2 | 1 | $\sigma^2/4$ | $\sigma^2/4$ | $\frac{1}{2}\sigma^2$ |
| 2 | 1 | $\sigma^2/16$ | $\sigma^2$ | $\frac{17}{16}\sigma^2$ |
| 3 | 1.5 | $\sigma^2/16$ | $\sigma^2/4$ | $\frac{5}{16}\sigma^2$ |
| 4 | 2 | $\sigma^2/16$ | $\sigma^2/16$ | $\frac{1}{8}\sigma^2$ |

### Transform and Quantization

Apply the orthogonal transform:

$$\begin{bmatrix} Y_1 \\ Y_2 \end{bmatrix} = \frac{1}{\sqrt{2}} \begin{bmatrix} 1 & -1 \\ 1 & 1 \end{bmatrix} \begin{bmatrix} X_1 \\ X_2 \end{bmatrix}$$

After transform, $Y_1$ and $Y_2$ are **independent**:
- $Y_1 \sim U\left(-\frac{\Delta_1}{2}, \frac{\Delta_1}{2}\right)$ with $\sigma_1^2 = \frac{\Delta_1^2}{12} = 2\sigma^2$
- $Y_2 \sim U\left(-\frac{\Delta_2}{2}, \frac{\Delta_2}{2}\right)$ with $\sigma_2^2 = \frac{\Delta_2^2}{12} \ll \sigma^2$
![[Pasted image 20260327172613.png|500]]

| bits | R | $D_1$ | $D_2$ | $D$ |
|---|---|---|---|---|
| 0 | 0 | $2\sigma^2$ | $\ll \sigma^2$ | $2\sigma^2$ |
| 1 | 0.5 | $\sigma^2/2$ | $\ll \sigma^2$ | $\frac{1}{2}\sigma^2$ |
| 2 | 1 | $\sigma^2/8$ | $\ll \sigma^2$ | $\frac{1}{8}\sigma^2$ |
| 3 | 1.5 | $\sigma^2/32$ | $\ll \sigma^2$ | $\frac{1}{32}\sigma^2$ |

> [!success] Result  
> Transform coding achieves much better **Rate-Distortion performance** because:
> - One component ($Y_1$) carries most information and gets most bits
> - Other component ($Y_2$) requires negligible bits due to small variance

### Visualization: Scalar vs Vector Quantization

**Scalar quantization in original domain**:
- Grid aligned with axes
- Wastes bits on correlated dimensions

**Scalar quantization in transform domain**:
- Grid rotated to match data distribution
- Efficient allocation based on variance

**Vector quantization in original domain**:
- Optimal but computationally expensive
- Hexagonal cells for uniform distribution

## Practical Algorithms for Resource Allocation

The Huang-Schulteiss formula:
- May provide **negative values** (impossible rates)
- May provide **non-integer values** (practical constraint)

### Modified Huang-Schulteiss Algorithm

1. Compute $R_k^*$ with standard Huang-Schulteiss
2. If any $R_k^* < 0$, remove those variances and repeat with $M-1$ components
   - Removed variables get zero bits (not coded)
3. Repeat until all rates $\geq 0$
4. Floor the results to integers
5. Allocate residual bits to coefficients with largest fractional parts

**Example**:
- Gaussian vector ($c_k = c_N$), $M = 4$
- Variances: $\sigma_1^2 = 1000, \sigma_2^2 = 100, \sigma_3^2 = 50, \sigma_4^2 = 1$
- Total rate: $R_{\text{Tot}} = 10$ bits
- GM: $(1000 \cdot 100 \cdot 50 \cdot 1)^{1/4} \approx 47.29$

Initial calculation:
$$R(k) = \frac{10}{4} + 0.5 \log_2\left(\frac{\sigma_k^2}{47.29}\right) = 2.5 + 0.5 \log_2\left(\frac{\sigma_k^2}{47.29}\right)$$

Results:
- $R(1) \approx 4.70$
- $R(2) \approx 3.04$
- $R(3) \approx 2.54$
- $R(4) \approx -0.28$ ← Negative!

Remove $\sigma_4^2$, recalculate with $M = 3$:
- New GM: $(1000 \cdot 100 \cdot 50)^{1/3} \approx 171.00$
- $R(k) = \frac{10}{3} + 0.5 \log_2\left(\frac{\sigma_k^2}{171.00}\right)$

New results:
- $R(1) \approx 4.61$ → rounded: **4** (fractional part 0.61)
- $R(2) \approx 2.95$ → rounded: **2** (fractional part 0.95) ← Largest
- $R(3) \approx 2.45$ → rounded: **2** (fractional part 0.45)
- $R(4) = 0$

Total: $4 + 2 + 2 + 0 = 8$ bits used, 2 residual bits.

Allocate residuals to largest fractional parts ($R(2)$ and $R(1)$):
- **Final rates**: $R(1) = 5, R(2) = 3, R(3) = 2, R(4) = 0$

**Distortion calculation**:
- $D_1 = 1000 \cdot 2^{-10} \approx 0.98$
- $D_2 = 100 \cdot 2^{-6} \approx 1.56$
- $D_3 = 50 \cdot 2^{-4} \approx 3.13$
- $D_4 = 1 \cdot 2^0 = 1$
- $D_{\text{total}} \approx 6.67$

### Greedy Algorithm

An alternative that can be faster if $R_{\text{Tot}}$ is small:

1. **Initialization**:
   - $R_k = 0$ for all $k$
   - $D_k = \sigma_k^2$ for all $k$

2. **While** $\sum_k R_k \leq R_{\text{Tot}}$:
   - $\ell = \arg\max_k D_k$ (find component with largest distortion)
   - $R_\ell \leftarrow R_\ell + 1$ (add one bit)
   - $D_\ell \leftarrow D_\ell / 4$ (distortion reduces by factor 4 with 2 bits)

**Example iteration trace** (same variances: 1000, 100, 50, 1):

| Iter | $\ell$ | $R_1$ | $R_2$ | $R_3$ | $R_4$ | $D_1$ | $D_2$ | $D_3$ | $D_4$ |
|---|---|---|---|---|---|---|---|---|---|
| 0 | - | 0 | 0 | 0 | 0 | 1000 | 100 | 50 | 1 |
| 1 | 1 | 1 | 0 | 0 | 0 | 250 | 100 | 50 | 1 |
| 2 | 1 | 2 | 0 | 0 | 0 | 62.5 | 100 | 50 | 1 |
| 3 | 2 | 2 | 1 | 0 | 0 | 62.5 | 25 | 50 | 1 |
| 4 | 1 | 3 | 1 | 0 | 0 | 15.63 | 25 | 50 | 1 |
| 5 | 3 | 3 | 1 | 1 | 0 | 15.63 | 25 | 12.5 | 1 |
| 6 | 2 | 3 | 2 | 1 | 0 | 15.63 | 6.25 | 12.5 | 1 |
| 7 | 1 | 4 | 2 | 1 | 0 | 3.91 | 6.25 | 12.5 | 1 |
| 8 | 3 | 4 | 2 | 2 | 0 | 3.91 | 6.25 | 3.13 | 1 |
| 9 | 2 | 4 | 3 | 2 | 0 | 3.91 | 1.56 | 3.13 | 1 |
| 10 | 1 | 5 | 3 | 2 | 0 | 0.98 | 1.56 | 3.13 | 1 |

Same final allocation: $[5, 3, 2, 0]$

## Optimal and Frequency Transforms

### Towards the Optimal Transform

From the toy example, we saw that applying an orthogonal transform (rotation) to highly correlated variables:
- **Decorrelates** them
- Causes strong **sparsification**: energy packed into one main component
- Drastically reduces the GM of variances

> [!question] Fundamental Question  
> Given a random vector $X$ with known statistics, is there a mathematically optimal transform that guarantees complete decorrelation and maximizes energy compaction?

> [!success] Answer: Yes  
> The **Karhunen-Loève Transform (KLT)** finds a basis aligned with the principal directions of the signal's variance.

### The Karhunen-Loève Transform (KLT)

> [!info] Definition — KLT  
> Let $X$ be a zero-mean random vector of size $M$ with correlation matrix $R_X = E[XX^T]$.  
> Assume $R_X$ has $M$ orthogonal eigenvectors $u_1, \ldots, u_M$.  
> The KLT is defined as the orthonormal matrix $T_{\text{KLT}}$ whose rows are the eigenvectors:
> $$T_{\text{KLT}} = [u_1 \ u_2 \ \ldots \ u_M]^T$$
> The transform is: $Y = T_{\text{KLT}} X$

> [!important] Fundamental Property  
> The KLT is **data-dependent**: its basis functions are tailored to the statistical properties of the specific source $X$. We must know or estimate $R_X$ to apply the KLT.

### KLT Properties

1. **Orthogonality**: $T_{\text{KLT}}^{-1} = T_{\text{KLT}}^T$

2. **Decorrelating transform**: $E[Y_i Y_j] = \lambda_i \delta_{ij}$
   - Transformed components are uncorrelated
   - $\lambda_i$ are eigenvalues of $R_X$

3. **Best energy concentration (sparsity)**:
   For any other orthogonal transform $T$ with $Z = TX$:
   $$\forall N \in \{1, \ldots, M\}: \sum_{i=1}^N E[Y_i^2] \geq \sum_{i=1}^N E[Z_i^2]$$
   - KLT packs maximum energy into first $N$ components

4. **Optimality for Gaussian RV**:
   If $X$ is Gaussian, for any other transform $T$ with $Z = TX$:
   $$\sigma_{\text{GM},Y}^2 \leq \sigma_{\text{GM},Z}^2$$
   - KLT has the **largest coding gain** among all orthogonal transforms

### KLT: 3D Visual Intuition

**Original domain**: High 3D correlation - data points form an elongated cluster along diagonal.

**KLT domain**: 
- Coordinate system rotated to align with cluster's principal directions
- One axis captures most variance (elongated direction)
- Other axes capture minimal variance
- Knowing $Y_1$ provides zero linear information about $Y_2$

### Energy Compaction and Sparsity

**Sparsifying Property**: Most transformed coefficients $Y_i$ for large $i$ have near-zero variance.

**Dimension Reduction**: We can discard (or coarsely quantize) components with small eigenvalues with minimal impact on total MSE.

> [!success] Packing Efficiency  
> Among all linear orthogonal transforms, the KLT is optimal for energy compaction: for any $N < M$, the sum of the first $N$ variances is maximized by the KLT.

### Optimality and the Gaussian Case

The **Coding Gain** measures transform efficiency:

$$G_T = \frac{\frac{1}{M} \sum_{i=1}^M \sigma_i^2}{\left(\prod_{i=1}^M \sigma_i^2\right)^{1/M}} = \frac{\sigma_{\text{AM}}^2}{\sigma_{\text{GM}}^2}$$

> [!tip] Theoretical Optimality  
> - For Gaussian sources, KLT makes coefficients **statistically independent**
> - KLT **maximizes coding gain** for Gaussian distributions
> - Provides best possible MSE performance for fixed total bit-rate $R$ in high-bitrate regime

### Example: Multi/Hyperspectral Imaging

Multi/hyperspectral images have large correlation across spectral bands.

**Process**:
1. Consider pixel vector $X(m,n) = [X_1, X_2, \ldots, X_M]^T$ as spectral signature
2. Compute inter-band correlation $R_X$
3. Compute $T_{\text{KLT}}$ from eigenvectors
4. Apply transform: $Y(m,n) = T_{\text{KLT}} X(m,n)$
5. Generate "eigen-bands"

**Result**:
- First Principal Component: common structural information (luminance/topography)
- Subsequent bands: specific spectral innovations or noise

**Energy distribution after KLT**:

| Eigenband | % Energy |
|---|---|
| 1 | 86.37% |
| 2 | 7.65% |
| 3 | 4.16% |
| 4 | 1.67% |
| 5 | 0.12% |
| 6 | 0.03% |

> [!success] Compression Insight  
> 86.37% of energy in just one band! We can discard bands 3-6 with minimal quality loss.

### Limitations of the KLT

Despite theoretical optimality, KLT is rarely used in standard codecs:

1. **Computational Complexity**: $O(N^3)$ to find eigenvectors, $O(N^2)$ for matrix multiplication per block/image

2. **Signaling Overhead**: Data-dependent basis functions must be sent to decoder as metadata

3. **Model Correctness**: Assuming stationarity is often oversimplified (images are locally stationary)

> [!tip] Path to DCT  
> For a **Markov Process** (AR(1)) with correlation $\rho \to 1$, **frequency transforms** (DFT, DCT) offer:
> - Near-optimal performance
> - Fixed basis functions (no signaling overhead)
> - Fast algorithms ($O(N \log N)$)

## The Discrete Fourier Transform (DFT)

### 1D DFT Definition

> [!info] Definition — 1D DFT  
> Given signal $x[n]$ of length $M$, transform coefficients $y[k]$:
> $$y[k] = \frac{1}{\sqrt{M}} \sum_{n=1}^M x[n] e^{-j\frac{2\pi}{M} kn}, \quad k = 1, \ldots, M$$
> 
> The factor $\frac{1}{\sqrt{M}}$ ensures the transform is **orthonormal (unitary)**.

**Matrix Formulation**: $Y = T_{\text{DFT}} X$

### DFT Transformation Matrix

$$T_{\text{DFT}} = \frac{1}{\sqrt{M}} \begin{bmatrix}
1 & 1 & 1 & \cdots & 1 \\
1 & W_M & W_M^2 & \cdots & W_M^{M-1} \\
1 & W_M^2 & W_M^4 & \cdots & W_M^{2(M-1)} \\
\vdots & \vdots & \vdots & \ddots & \vdots \\
1 & W_M^{M-1} & W_M^{2(M-1)} & \cdots & W_M^{(M-1)(M-1)}
\end{bmatrix}$$

where $W_M = e^{-j 2\pi/M}$ is the $M$th primitive root of unity.

**Interpretation**:
- Each row is the conjugate of one basis vector
- Scalar product of $X$ with basis vector tells "how similar" $X$ is to that frequency component

### DFT Basis Functions

The DFT basis consists of complex exponentials:
- $B_k(n) = e^{j\frac{2\pi}{M} kn}$
- Real and imaginary parts are sinusoids
- $k$-th coefficient measures similarity to $k$-th basis vector
- Geometrically: rigid rotation in complex vector space $\mathbb{C}^N$
- Preserves $\ell_2$-norm (energy): $\|Y\| = \|X\|$

### 2D DFT: Theoretical Framework

The 2D DFT maps an $N \times N$ spatial image $X$ to frequency representation $Y$.

**Vectorized Perspective**: Treat image as vector $x \in \mathbb{C}^{N^2}$ by stacking columns:

$$y = Ax$$

- $A$ is unitary matrix of size $N^2 \times N^2$
- Represents rigid rotation in $\mathbb{C}^{N^2}$
- Total energy preserved: $\|y\|^2 = \|x\|^2$

**Practical Implementation: Separability**

Direct $N^2 \times N^2$ matrix is prohibitive. Fortunately, DFT is **separable**:

$$Y = T X T^T$$

where $T$ is the $N \times N$ 1D DFT matrix.

**Process**:
1. Transform each column: $T X$
2. Transform each row of result: $(TX)T^T$
3. Order doesn't matter (rows then columns or vice versa)
4. Achieves horizontal and vertical frequency analysis

**Complexity**: $O(N^2 \log N)$ with Fast Fourier Transform (FFT)

### 2D Basis Patterns

The transform decomposes image into weighted sum of $N^2$ orthogonal basis patterns:

$$B_{k,\ell}(n,m) = \frac{1}{N} e^{j\frac{2\pi}{N}(kn + \ell m)}$$

Each coefficient $Y[k,\ell]$ represents "strength" of specific horizontal and vertical frequency combination.

> [!tip] Compression Insight  
> For natural images, most energy concentrates in coefficients where $k$ and $\ell$ are small (**low frequencies**).

### DFT Spectral Leakage Problem

**Critical Issue**: DFT analyzes a **periodized** version $x_{\text{PER}}$ of the original signal.

- Periodization introduces high-frequency "jumps" at signal boundaries
- DFT generates high-frequency coefficients to represent these artificial discontinuities
- Energy "leaks" from low to high frequencies

**Result**: Even smooth signals have significant high-frequency content due to periodization, making representation less sparse.

> [!warning] Why DFT is Rarely Used for Compression  
> Spectral leakage reduces sparsity, making compression ineffective. DFT is the discrete-time analog of Fourier Series, and periodization creates boundary discontinuities.

---

## The Discrete Cosine Transform (DCT)

### Solving the Frequency Leakage

**Solution**: Create symmetric mirror $x_{\text{SYM}}$ of signal $x$ before periodization.

When symmetric signal is periodized, no jump occurs → no frequency leakage.

**Process**:
1. Create mirror-periodic version $x_{\text{SYM}}$ of $x$
2. Compute DFT of $x_{\text{SYM}}$
3. Apply frequency domain modulation (mathematical trick for real, symmetric coefficients)
4. Keep only $M$ coefficients (due to symmetry, only half needed)

This produces the **Discrete Cosine Transform**.

### DCT Transformation Matrix

$$[T_{\text{DCT}}]_{k,n} = \begin{cases}
\sqrt{\frac{1}{M}} & k = 0 \\
\sqrt{\frac{2}{M}} \cos\left(\frac{(2n+1)k\pi}{2M}\right) & k > 0
\end{cases}$$

for $k, n = 0, 1, \ldots, M-1$.

### DCT Basis Functions

- **Real-valued** (unlike complex DFT)
- DC component ($k=0$): constant function
- AC components ($k>0$): cosines with increasing frequency
- No negative-frequency coefficients needed (symmetry)

> [!tip] Key Advantage  
> DCT eliminates spectral leakage through symmetric periodization, providing better energy compaction than DFT.

### DFT vs DCT Comparison

| Aspect | DFT | DCT |
|---|---|---|
| Coefficients | Complex | Real |
| Periodization | Standard (creates jumps) | Symmetric (smooth) |
| Spectral leakage | Yes | No |
| Energy compaction | Poorer | Better |
| Used in compression | Never | Very common |

**Example comparison**: 
- Reconstructing with best 3 DCT coefficients: **99.89%** of energy retained
- Reconstructing with best 3 DFT coefficients: **90.33%** of energy retained

The DFT reconstruction struggles with boundary effects and has less effective energy compaction.

### 2D-DCT

Just as 2D-DFT, 2D-DCT is **separable**:

$$Y = T X T^T$$

**Process**:
1. Apply 1D DCT to each row of $X$
2. Apply 1D DCT to each column of result

**Properties**:
- DCT only has **positive frequencies**
- Top-left coefficient (0,0) is the **DC component** (average intensity)
- Other coefficients are **AC** (alternating current), representing:
  - Direction of spatial variations (angle)
  - Velocity of variations (frequency)

### DCT Examples

**Example 1**: Image with two dominant contour directions
- DCT shows two "traces" corresponding to directions
- DC component in top-left

**Example 2**: Image with many different contour directions
- Many "traces" in DCT
- "Impulses" represent periodic background pattern

**Example 3**: Removing diagonal patterns
- Diagonal traces disappear when pattern removed
- Periodic impulses remain if fabric texture unchanged

### 2D-DCT Sparsity

Natural images exhibit strong sparsity in DCT domain:
- Most coefficients are near zero
- Energy concentrated in low-frequency region (top-left)
- High-frequency coefficients (bottom-right) often negligible

### Block-Based DCT

Large, non-stationary images are divided into small blocks:
- Each block analyzed separately
- **8×8 block-based DCT** (JPEG standard)
- Each $8 \times 8$ block projected onto 64 basis vectors

**Block characteristics**:
- Detailed areas (e.g., strawberries): many non-negligible coefficients
- Strong contours: directional traces only
- Simple blocks: very few non-negligible coefficients

> [!tip] Adaptive Block Size  
> Variable block size could optimize sparsity, but JPEG uses fixed 8×8 blocks for simplicity.

### DCT: Summary of Sparsity Benefits

1. DCT **sparsifies** images
2. Transforms from "all samples equally important" to "few large, many small coefficients"
3. Enables **asymmetric bit allocation**:
   - Many bits to few large coefficients
   - Few bits to majority of small coefficients
4. Minimal quality degradation due to energy compaction

## JPEG Standard

### Overview

> [!info] JPEG Standard  
> - Image compression standard based on DCT
> - Specified in 1991, adopted in 1992
> - Describes only the **decoder** (ensures interoperability)
> - Works on multi-component (color) images
> - For our analysis: focus on single gray-scale component

### JPEG Processing Pipeline

```
Preprocessing → DCT → Quantization → Entropy Coding
```

1. **Preprocessing**: 
   - Color space transformation (RGB → YCbCr)
   - Chroma subsampling (4:2:0)
   - Block split into 8×8 blocks
   - Centering (subtract 128)

2. **DCT**: Transform each 8×8 block

3. **Quantization**: Uniform quantization with quantization matrix

4. **Entropy Coding**: 
   - Zig-zag scan
   - DC coefficient: prediction + Huffman
   - AC coefficients: run-length + Huffman

### JPEG Quantization

> [!info] Quantization Process  
> Uniform quantization (mid-tread):
> $$c_{i,j}^{\text{q}} = \text{round}\left(\frac{c_{i,j}}{q_{i,j}}\right)$$
> 
> where $q_{i,j}$ is the quantization step from quantization table $q$.

**Key points**:
- Quantization table drives rate-distortion trade-off
- Table is **not defined by standard** (must be encoded)
- Higher values = coarser quantization = lower rate, lower quality

**Example quantization table**:

### JPEG Quality Factor

Non-normative tool for easy quantization matrix selection:

$$Q \in [1, 100] \text{ (quality factor)}$$

**Scaling factor**:

$$SF = \begin{cases}
\frac{5000}{Q} & 1 \leq Q \leq 50 \\
200 - 2Q & 50 < Q \leq 99 \\
1 & Q = 100
\end{cases}$$

**Quantization matrix scaling**:
$$q \leftarrow \frac{SF \cdot q}{100}$$

| Quality Factor | Scaling Factor | Compression |
|---|---|---|
| 1 | 5000 | Maximum (very lossy) |
| 50 | 100 | Balanced |
| 75 | 50 | Good quality |
| 100 | 1 | Lossless (no quantization) |

### JPEG Entropy Coding

**Zig-zag scan**: Gathers zeros at end of scan for run-length efficiency.

```
DC, AC1, AC2, ..., AC63
 ↓
[-2, 17, 3, 1, 0, 0, 0, 0, 3, 4, 0, -1, 0, 0, 0, 0, ... 0, EOB]
```

#### DC Coefficient Coding

> [!info] DC Coefficient Encoding  
> DC coefficients are **differentially encoded** (prediction):
> - Difference: $\Delta DC_n = DC_n - DC_{n-1}$
> - Categories 0-11 coded with pseudo-Huffman code
> - Category $k$ defined as: $k = \lceil \log_2(|\Delta DC_P| + 1) \rceil$

**Category table**:

| Category | Values | Code |
|---|---|---|
| 0 | 0 | 00 |
| 1 | -1, +1 | 010 |
| 2 | -3,-2,+2,+3 | 011 |
| 3 | -7,...,+7 | 100 |
| 4 | -15,...,+15 | 101 |
| 5 | -31,...,+31 | 110 |
| 6 | -63,...,+63 | 1110 |
| 7 | -127,...,+127 | 11110 |
| 8 | -255,...,+255 | 111110 |
| 9 | -511,...,+511 | 1111110 |
| 10 | -1023,...,+1023 | 11111110 |
| 11 | -2047,...,+2047 | 111111110 |

**Amplitude encoding**:
- Positive: standard binary
- Negative: 2's complement (bitwise complement of positive)

**Example**: $\Delta DC_P = -5$
- Category: $k = \lceil \log_2(5 + 1) \rceil = 3$ → Code: **100**
- +5 in binary: **101**, complement for -5: **010**
- Final encoding: **100010**

#### AC Coefficient Coding

> [!info] AC Coefficient Encoding  
> AC coefficients use **run-length, category, amplitude**:
> - Run: number of zeros before non-zero coefficient
> - Category: bit-depth of non-zero value
> - Amplitude: actual value (encoded as in DC case)

**Special symbols**:
- **(15, 0)** - Zero-Run (ZR): at least 15 zeros before next non-zero
- **(0, 0)** - End of Block (EOB): all remaining coefficients are zero

**Run/Category encoding table** (excerpt):

| R/k | Code | R/k | Code |
|---|---|---|---|
| 0/0 (EOB) | 1010 | 2/1 | 11100 |
| 0/1 | 00 | 2/2 | 11111001 |
| 0/2 | 01 | ... | ... |
| 0/3 | 100 | 1/1 | 1100 |
| 0/4 | 1011 | 1/2 | 11011 |
| ... | ... | ... | ... |
| F/0 (ZR) | 11111111001 | F/1 | 1111111111110101 |

### Entropy Coding Example

**Sequence to encode** (assuming $DC_{n-1} = 1$):
$$\Delta DC_P = -3, \quad (0,17), (0,3), (1,4), (0,3), (0,1), (5,-1), (0,-1), (4,-1), (5,-1), \text{EOB}$$

**Encoding process**:

| Symbol | Category | Category Code | Value | Value Code | Full Code |
|---|---|---|---|---|---|
| $\Delta DC = -3$ | 2 | 011 | -3 → 00 | 00 | **01100** |
| (0, 17) | (0,5) | 11010 | 17 → 10001 | 10001 | **1101010001** |
| (0, 3) | (0,2) | 01 | 3 → 11 | 11 | **0111** |
| (1, 4) | (1,3) | 1111001 | 4 → 100 | 100 | **1111001100** |
| (0, 3) | (0,2) | 01 | 3 → 11 | 11 | **0111** |
| (0, 1) | (0,1) | 00 | 1 → 1 | 1 | **001** |
| (5, -1) | (5,1) | 1111010 | -1 → 0 | 0 | **11110100** |
| (0, -1) | (0,1) | 00 | -1 → 0 | 0 | **000** |
| (4, -1) | (4,1) | 111011 | -1 → 0 | 0 | **1110110** |
| (5, -1) | (5,1) | 1111010 | -1 → 0 | 0 | **11110100** |
| EOB | - | 1010 | - | - | **1010** |

**Final bitstream**:
```
01100 11010 10001 0111 1111001 100 0111 001 1111010 0 000 1110110 1111010 0 1010
```

Total: **66 bits** for 64 pixels ≈ **1.03 bpp**

> [!note] Rate Control  
> JPEG does **not** have built-in rate control. The number of bits per block depends on quantization table and image content, making exact bitrate targeting difficult.

### JPEG File Structure

**Frame**:
- Header: image size, components (RGB, YCbCr), digitization format (4:2:0, etc.)
- Contains one scan per component (baseline JPEG)

**Scan**:
- Header: identifies component, specifies quantization tables
- Typically: one table for luminance, another for chrominance
- Made up of segments (optionally separated by restart markers for parallel decoding)

**Segment**:
- Header: defines Huffman tables (DC vs AC, Y vs CbCr)
- Four different tables can be used
- Made up of blocks

**Block**:
- 8×8 pixels encoding
- No headers within block

### Metadata Formats

**JFIF (JPEG File Interchange Format)**:
- Standard format for metadata
- Ensures interoperability
- Contains: JFIF version, density units, X/Y resolution, optional thumbnail
- Does NOT include camera settings
- Widely supported for web images

**Exif (Exchangeable Image File Format)**:
- Rich metadata for digital cameras (JEIDA standard)
- Contains: camera make/model, date/time, settings (aperture, shutter, ISO), GPS, thumbnail, copyright
- Manufacturer-specific proprietary data possible
- Preferred by photographers

## Summary and Conclusions

### Transform Coding Conceptual Map

**Key Insights**:
1. **Block coding**: Joint rate allocation outperforms sample-by-sample coding
2. **Huang-Schulteiss formula**: Optimal rate allocation for vector components
3. **Coding gain**: Total distortion proportional to geometric mean of variances $\sigma_{\text{GM}}^2$
4. **Orthogonal transforms**: Modify variance distribution to reduce $\sigma_{\text{GM}}^2$
5. **Practical allocation**: Modified H.S., greedy, or fixed allocation
6. **Frequency transforms**: DFT and DCT provide convenient sparsification

### JPEG Conceptual Map

**Core pipeline**:
- Preprocessing (color transform, subsampling, centering)
- 8×8 block DCT
- Quantization (quality-factor controlled)
- Entropy coding (zig-zag, run-length, Huffman)
- File structure (JFIF/Exif metadata)

### Key Takeaways

> [!success] Main Points  
> 1. **Transform coding** converts correlated data into sparse representation
> 2. **Coding gain** quantifies improvement: $G_T = \frac{\sigma_{\text{AM}}^2}{\sigma_{\text{GM}}^2}$
> 3. **KLT** is theoretically optimal but computationally expensive
> 4. **DCT** provides near-optimal performance with fast algorithms ($O(N \log N)$)
> 5. **JPEG** combines DCT, quantization, and entropy coding for practical image compression
> 6. **Quality vs Rate** trade-off controlled by quantization matrix

## Appendix: Key Formulas Reference

### Distortion Formulas

| Case | Formula |
|---|---|
| Scalar quantization | $D = c \sigma^2 2^{-2R}$ |
| Block coding | $D = \frac{1}{M} \sum_{k=1}^M c_k \sigma_k^2 2^{-2R_k}$ |
| With optimal allocation | $D^* = c_{\text{GM}} \sigma_{\text{GM}}^2 2^{-2\bar{R}}$ |

### Huang-Schulteiss Formula

$$R_k^* = \frac{R_{\text{Tot}}}{M} + \frac{1}{2} \log_2 \left(\frac{c_k \sigma_k^2}{c_{\text{GM}} \sigma_{\text{GM}}^2}\right)$$

### Coding Gain

$$G_T = \frac{D_{\text{PCM}}}{D_T} = \frac{\sigma_{\text{AM},Y}^2}{\sigma_{\text{GM},Y}^2}$$

### Geometric and Arithmetic Means

$$\sigma_{\text{AM}}^2 = \frac{1}{M} \sum_{k=1}^M \sigma_k^2, \quad \sigma_{\text{GM}}^2 = \left(\prod_{k=1}^M \sigma_k^2\right)^{1/M}$$

### DFT and DCT

| Transform | Matrix Element | Type |
|---|---|---|
| DFT | $[T_{\text{DFT}}]_{k,n} = \frac{1}{\sqrt{M}} e^{-j\frac{2\pi}{M}kn}$ | Complex |
| DCT | $[T_{\text{DCT}}]_{k,n} = \sqrt{\frac{2}{M}} \cos\left(\frac{(2n+1)k\pi}{2M}\right)$ (for $k>0$) | Real |

### JPEG Quality Factor Scaling

$$SF = \begin{cases}
\frac{5000}{Q} & 1 \leq Q \leq 50 \\
200 - 2Q & 50 < Q \leq 99 \\
1 & Q = 100
\end{cases}$$
