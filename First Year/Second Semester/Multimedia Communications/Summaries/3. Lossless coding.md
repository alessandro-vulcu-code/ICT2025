## Introduction: From Samples to Bits

The encoding pipeline for multimedia signals:

1. **Spatial Prediction**: reduces variance using local correlation — $y(n) = x(n) - \hat{x}(n)$
2. **Quantization**: maps high-precision residuals to discrete indices $i(n)$
3. **Lossless Coding**: maps indices to a compact bitstream

A valid code must be:
- **Uniquely Decodable**: one-to-one mapping from bitstream back to symbol sequence
- **Compact**: smallest possible average codeword length
![[Pasted image 20260501174916.png]]
### Fixed-Length Coding (FLC)

All codewords have the same length $L = \lceil \log_2 M \rceil$ where $M$ = alphabet size.

| Index | 4-bit Code | Index | 4-bit Code |
| :--- | :--- | :--- | :--- |
| -7 | 1001 | 1 | 0001 |
| -6 | 1010 | 2 | 0010 |
| ... | ... | ... | ... |
| 0 | 0000 | 7 | 0111 |

- **Pros**: simple parsing (every $L$ bits = one symbol), robustness (1 bit error affects 1 symbol only)
- **Con**: fixed rate $R = \log_2 M$, ignores that symbols are not equally probable

> Example: French text with $M = 26$ letters → FLC needs 5 bpS, no compression.

### Variable-Length Coding (VLC)

Assign **shorter codewords to probable symbols**, longer codewords to rare symbols.

Key questions:
1. *Theoretical bound*: how much gain? → **Source Entropy** $H(X)$
2. *Practical implementation*: **Huffman coding** (optimal, but scalability issues) or **Arithmetic coding** (asymptotically optimal, scales easily)
3. *Unknown statistics*: **Universal coding** (LZW)

### Terminology

- **Alphabet**: $\mathcal{X} = \{x_1, x_2, \ldots, x_M\}$ — set of symbols to encode
- **Code**: $C : x_i \in \mathcal{X} \rightarrow c_i \in \{0, 1\}^*$ — maps symbols to finite-length bit strings
- $\ell_i$: length of codeword $c_i$

**Types of decodability**:
- *Instantaneous* (prefix code): no codeword is prefix of another → can decode symbol-by-symbol
- *Uniquely decodable*: every finite sequence decodes unambiguously (may require lookahead)

> [!Example] Code Examples
> | Symbol | Code 1 | Code 2 | Code 3 | Code 4 |
> | :--- | :--- | :--- | :--- | :--- |
> | A (p=1/2) | 0 | 0 | 0 | 0 |
> | B (p=1/4) | 0 | 1 | 10 | 01 |
> | C (p=1/8) | 1 | 00 | 110 | 011 |
> | D (p=1/8) | 10 | 11 | 111 | 0111 |
>
> - Code 1: **not** uniquely decodable (A and B share codeword 0; 10 = CA = CB = D)
> - Code 2: **not** uniquely decodable (00 = AA or C; 11 = BB or D)
> - Code 3: **instantaneously decodable** (prefix condition satisfied)
> - Code 4: decodable with delay of 1 bit

## Principles of Information Theory

### Information and Entropy

**Self-information** of symbol $x_i$ with probability $p_i$:

$$I(x_i) = -\log p_i$$

Properties:
- $I(x_i) \geq 0$
- $p_i = 1 \Rightarrow I = 0$ (certain event carries no information)
- Independent symbols: $I(x_i, x_j) = I(x_i) + I(x_j)$

> [!Important] Source Entropy
> $$H(X) = -\sum_i p_i \log p_i$$
>
> **Interpretation:** average uncertainty (information) of the random variable $X$. Measured in bits when $\log = \log_2$.

For a **binary RV** with alphabet $\{0,1\}$:
$$H(X) = -p \log p - (1-p)\log(1-p)$$
Maximum at $p = 0.5$ where $H = 1$ bit.
![[Pasted image 20260501175049.png]]
### Maximum Entropy Distribution

> [!Important] Maximum Entropy Theorem
> The distribution maximizing $H(X)$ for an $M$-ary discrete RV subject to $\sum p_i = 1$ is the **uniform distribution**:
> $$p_i^* = \frac{1}{M} \quad \Rightarrow \quad H_{\max} = \log_2 M$$
>
> **Proof (Lagrange multipliers):**
> $$J(p) = -\sum_{i} p_i \log p_i + \lambda\left(\sum_i p_i - 1\right)$$
> $$\frac{\partial J}{\partial p_i} = 0 \Rightarrow \log p_i^* = \lambda - \log e = \text{const} \Rightarrow p_i^* = \frac{1}{M}$$

### Joint and Conditional Entropy

**Joint entropy** of $(X, Y)$:
$$H(X, Y) = -\sum_{i,j} p_{i,j} \log p_{i,j}$$

**Conditional entropy** (average uncertainty about $X$ given $Y$):
$$H(X|Y) = \sum_j p_j \, H(X|Y = y_j)$$

**Chain rule**:
$$H(X, Y) = H(Y) + H(X|Y) = H(X) + H(Y|X)$$

- $H(X|Y) = H(X)$ if $X, Y$ independent
- $H(X|Y) = 0$ if $X$ is deterministic function of $Y$

### Properties

| Property | Formula | Equality condition |
| :--- | :--- | :--- |
| Non-negativity | $H(X) \geq 0$ | always |
| Chain rule | $H(X,Y) = H(Y) + H(X\|Y)$ | — |
| Sub-additivity | $H(X,Y) \leq H(X) + H(Y)$ | $X, Y$ independent |
| Conditioning reduces entropy | $H(X\|Y) \leq H(X)$ | $X, Y$ independent |
| Upper bound | $H(X) \leq \log_2 M$ | $X \sim \mathcal{U}$ (uniform) |

> [!Important] Conditioning Reduces Entropy
> $H(X|Y) \leq H(X)$ — "information never hurts": knowing $Y$ can only decrease (or leave unchanged) uncertainty about $X$.

## Optimal Coding

### McMillan's Theorem and Kraft's Inequality

> [!Important] McMillan's Theorem
> **Decodable codes do not improve performance with respect to instantaneous codes.**
> We can restrict attention to instantaneous (prefix) codes without loss of generality.

> [!Important] Kraft's Inequality
> A prefix code with codeword lengths $\{\ell_1, \ldots, \ell_M\}$ exists **if and only if**:
> $$\sum_{i=1}^{M} 2^{-\ell_i} \leq 1$$
>
> - Necessary and sufficient for existence of a prefix code
> - If $\sum = 1$: code is **complete** (maximal — no wasted tree branches)

### Proof of Kraft's Inequality

**Necessity**: Build a binary tree of depth $L_{\max} = \max(\ell_i)$. Each codeword $c_i$ of length $\ell_i$ "blocks" $2^{L_{\max} - \ell_i}$ leaves. By prefix property, blocked sets are disjoint:

$$\sum_{i=1}^{N} 2^{L_{\max} - \ell_i} \leq 2^{L_{\max}} \quad \Rightarrow \quad \sum_{i=1}^{N} 2^{-\ell_i} \leq 1$$

**Sufficiency** (Greedy Construction):
1. Sort lengths $\ell_1 \leq \ell_2 \leq \cdots \leq \ell_N$
2. At step $k$, pick an available node at depth $\ell_k$
3. Mark all descendants as forbidden

At each step, consumed capacity $= \sum_{i<k} 2^{-\ell_i} < 1$ guarantees a node is available.

> [!Example] Prefix Code Construction
> Lengths $\{1, 2, 3, 3\}$: $2^{-1} + 2^{-2} + 2^{-3} + 2^{-3} = 1$ (complete code)
>
> Result: $\{0,\ 10,\ 110,\ 111\}$
> 
[[3. Lossless coding.pdf#page=26|Example: building a prefix code]]
### Shannon's Source Coding Theorem

**Optimal code** minimizes average length:

$$\ell^* = \arg\min_\ell \sum_i p_i \ell_i \quad \text{subject to} \quad \sum_i 2^{-\ell_i} = 1$$

Lagrangian solution (relaxing $\ell_i \in \mathbb{N}$):

$$J(\ell) = \sum_i p_i \ell_i + \lambda\left(\sum_i 2^{-\ell_i} - 1\right)$$
$$\frac{\partial J}{\partial \ell_i} = 0 \Rightarrow \ell_i^* = -\log_2 p_i$$
$$\mathcal{L}^* = \sum_i p_i \ell_i^* = H(X)$$

> [!Important] Shannon's Source Coding Theorem
> The minimum average length of any lossless code satisfies:
> $$\mathcal{L}^* \geq H(X)$$
> with equality **if and only if** all probabilities are dyadic: $\forall i, \exists k \in \mathbb{N}: p_i = 2^{-k}$.
>
> **Consequence:** Optimal coding is called **entropy coding**. The bound $H(X)$ is the fundamental limit.

**Practical bound**: using $\ell_i = \lceil -\log_2 p_i \rceil$ (integer lengths) gives:

$$H(X) \leq \mathcal{L}^* < H(X) + 1$$

> [!Example] French Text Compression
> - Alphabet size: 26 letters
> - FLC: 5 bpS
> - Source entropy: $H = 3.999$ bpS
> - Any VLC: $\mathcal{L} \geq 3.999$ bpS, compression ratio $\leq 1.25$

## Huffman Coding

### Algorithm

Huffman coding achieves **optimal** performance for known probabilities.

**Steps**:
1. Create leaf nodes for each symbol, weighted by $p_i$
2. Repeat until one node remains:
   - Select two nodes with lowest weights
   - Create internal node as parent with weight = sum of children
3. Assign `0` to left edges, `1` to right edges
4. Read each codeword from root to leaf

> [!Example] Huffman Code — 6 Symbols
> | Symbol | Prob | Codeword | Length |
> | :--- | :--- | :--- | :--- |
> | A | 0.40 | 0 | 1 |
> | B | 0.20 | 100 | 3 |
> | C | 0.15 | 101 | 3 |
> | D | 0.15 | 110 | 3 |
> | E | 0.05 | 1110 | 4 |
> | F | 0.05 | 1111 | 4 |
>
> $$\mathcal{L} = 0.4 \cdot 1 + 0.2 \cdot 3 + 0.15 \cdot 3 + 0.15 \cdot 3 + 0.05 \cdot 4 + 0.05 \cdot 4 = 2.3 \text{ bpS}$$
> $$H \approx 2.2464 \text{ bpS}$$
>
> For French text with Huffman: $\mathcal{L} = 4.041$ bpS vs $H = 3.999$ bpS, ratio = 1.238.
[[3. Lossless coding.pdf#page=56|Huffman coding]]

**Problem case** — B/W scanned image with $p = \Pr(B) \ll 1$:
- $H(X) \ll 1$ (very small)
- Huffman assigns 1-bit codes: $B \to 0$, $W \to 1$
- $\mathcal{L} = 1 \gg H(X)$: **1-bit penalty** makes Huffman inefficient when $H < 1$
[[3. Lossless coding.pdf#page=62|Example: B/W image entropy vs Huffman rate]]

### Block Coding

Encode blocks of $K$ symbols instead of individual symbols.

**Motivation**: $H(X^K) \leq \sum_{i=1}^K H(X_i)$ (sub-additivity), with equality only if independent.

For iid symbols:
$$\frac{H(X^K)}{K} \leq H(X_i) + \frac{1}{K} \xrightarrow{K\to\infty} H(X)$$

As $K \to \infty$, the average length per symbol converges to the **entropic rate**:

$$\mathcal{L}_S^* \to \mathcal{H}(X) = \lim_{K\to\infty} \frac{H(X^K)}{K} \leq H(X)$$

> [!Example] Block Coding on B/W Image ($p(\square) = 86.7\%$)
> | Block size | Entropy | Huffman rate (bpp) |
> | :--- | :--- | :--- |
> | $K=1$ | $H=0.586$ | 1.000 |
> | $K=2$ | $H/2=0.511$ | 0.650 |
> | $K=4$ | $H/4=0.383$ | 0.433 |
>
> Block coding improves performance even for iid variables (removes the 1-bit penalty for non-dyadic distributions).

> [!Example] French Text Block Coding
> | $K$ | Unit | Entropy (bpS) |
> | :--- | :--- | :--- |
> | 1 (letters) | per symbol | 3.999 |
> | 2 (digrams) | per symbol | 3.720 |
> | 3 (trigrams) | per symbol | 3.151 |

### Limits of Huffman

- Complexity **exponential** in $K$ (alphabet size $M^K$)
- Joint probability estimation for large blocks is costly and unreliable
- Cannot handle the case $H(X) < 1$ efficiently symbol by symbol

→ **Arithmetic coding** solves at least the complexity problem.

## Arithmetic Coding

### Principle

Arithmetic coding performs **block coding with linear complexity** by encoding entire sequences as a single interval in $[0, 1)$.

**Encoding procedure**: each sequence of $n$ symbols determines a sub-interval according to its probability. For each new symbol, the interval is refined using 2 multiplications and 2 sums. The final codeword is the interval center, represented with sufficient precision.

> [!Example] Arithmetic Coding: Input ACFD
> Probabilities: A=0.4, B=0.2, C=0.15, D=0.15, E=0.05, F=0.05
>
> - Start: $[0, 1)$
> - A: $[0, 0.4)$, center $= 0.2$, precision $= p_1/2$
> - C: $[0.24, 0.30)$, center $= 0.275$, precision $= p_1 p_3/2$
> - F: $[0.297, 0.30)$, center $= 0.2985$
> - D: $[0.29925, 0.2997)$, center $= 0.299475$

[[3. Lossless coding.pdf#page=79|Example: arithmetic coding interval subdivision for ACFD]]

### Average Length

$$L(n) = -\left\lceil\sum_{i=1}^n \log_2 p(x_i)\right\rceil + 1 < -\sum_{i=1}^n \log_2 p(x_i) + 2$$

Taking expectation:
$$\mathcal{L} < H(X) + \frac{2}{n} \xrightarrow{n\to\infty} H(X)$$

Arithmetic coding is **asymptotically optimal**, with a penalty of only $+2$ bits per block (vs. Huffman's $+1$ per symbol).

### Adaptivity and Context-Based Coding

**Adaptivity**: symbol statistics are learned during encoding by maintaining occurrence counts, updated at both encoder and decoder by an agreed rule.

**Context-based coding**: instead of estimating $P(X^K)$ directly (hard for large $K$), use a **context** — the $N_S$ previous symbols that most influence the current one.

- Number of possible contexts: $N_C = M^{N_S}$
- Using $N_C$ contexts ≡ $N_C$ different arithmetic encoders switching between each other
- Reaches entropy rate $\mathcal{H}$ without massive block sizes

> [!Example] Context Coding on B/W Image
> Using previous pixel as context:
> - $P(\square|\square) = 94.1\%$, $P(\blacksquare|\square) = 5.9\%$
> - $P(\square|\blacksquare) = 33.3\%$, $P(\blacksquare|\blacksquare) = 66.7\%$
> - $H(X|\square) = 0.322$, $H(X|\blacksquare) = 0.918$
> - $H(X|Y) = 0.406$ bpp — better than block coding $K=4$ (0.383 limit, 0.433 practical)!

| Method               | Limit (bpp)  | Practical (bpp)       |                              |
| :------------------- | :----------- | :-------------------- | ---------------------------- |
| Symbol-wise ($K=1$)  | $H(X)=0.586$ | 1.000 (Huffman)       |                              |
| Block coding ($K=2$) | 0.511        | 0.650 (Huffman)       |                              |
| Block coding ($K=4$) | 0.383        | 0.433 (Huffman)       |                              |
| Context-based (1D)   | $H(X         | $X_\text{prev}=0.406$ | $\approx 0.406$ (Arithmetic) |
|                      |              |                       |                              |
|                      |              |                       |                              |
|                      |              |                       |                              |

**Design rule**: context must capture the "significant past". Too large → sparse data, unreliable estimation. Too small → fails to capture dependencies.

### Arithmetic Coding Conclusions

**Advantages**:
- Linear complexity encoding/decoding ($O(n)$ operations)
- Block coding: exploits high-order dependencies, removes non-dyadic penalty
- Context coding: simple model for high-order statistics
- Adaptivity: handles non-stationary sources

**Disadvantages**:
- Implementation tricky (precision, carry propagation)
- Needs initialization
- Context selection is non-trivial
- Adaptivity needs large training set for robust estimation

## Other Techniques

### Exponential-Golomb Coding

**Universal coding** — no initialization, no need to specify symbol range in advance.

**Unsigned integers** — encoder for $n \geq 0$:
1. $n = 0$: encode as `1`
2. $n \geq 1$: write $n+1$ in binary using $b = \lfloor\log_2(n+1)\rfloor + 1$ bits; prepend $b-1$ zeros

| $n$ | $n+1$ (binary) | Codeword $c_U(n)$ |
| :--- | :--- | :--- |
| 0 | 1 | `1` |
| 1 | 10 | `010` |
| 2 | 11 | `011` |
| 3 | 100 | `00100` |
| 7 | 1000 | `0001000` |

**Signed integers** — map $n \in \mathbb{Z}$ to $m \in \mathbb{N}$:
$$m(n) = \begin{cases} 2n - 1 & \text{if } n > 0 \\ -2n & \text{if } n \leq 0 \end{cases}$$
Then encode $m$ with unsigned Exp-Golomb. Decoding inverts the mapping.

**Use cases**: metadata encoding, sparse residuals (e.g., prediction errors in DPCM).

### Dictionary-Based Coding (LZW)

**Core idea**: give up pre-established probabilities; learn long-term dependencies during encoding via a **dynamic dictionary** of patterns.

> [!Important] Asymptotic Optimality Theorem
> For any stationary and ergodic source, dictionary-based coding is **asymptotically optimal**:
> $$L_n \xrightarrow{n\to\infty} \mathcal{H}(X)$$

**Key characteristics**:
- **Dynamic**: dictionary built on-the-fly — no prior statistics required
- **Universal**: works for any source
- **Adaptive**: tracks non-stationary signals
- **Practical**: basis of ZIP, GZIP, PNG (Deflate)

**LZW Encoding**:
1. Initialize dictionary with single-symbol entries
2. Read symbols; find longest prefix $W$ already in dictionary
3. If $W + K$ (current prefix + next symbol) is new: output index of $W$, add $W+K$ to dictionary
4. Continue with $K$ as new prefix

**LZW Decoding**: mirrors encoding; decoder builds the same dictionary in sync.
[[3. Lossless coding.pdf#page=71|Example: LZW encoding step-by-step example]]

**Family of algorithms**:

| Algorithm | Year | Key Feature |
| :--- | :--- | :--- |
| LZ77 | 1977 | Sliding window, (offset, length) pairs |
| LZ78 | 1978 | Explicit dictionary of encountered strings |
| LZSS | 1982 | LZ77 + flag bit for literals vs. pointers |
| LZW | 1984 | LZ78 + pre-filled dictionary (no char transmission) |
| LZMA | 1998 | Large dictionary + range coding (arithmetic) |

*(Note: GIF used LZW patented by Unisys; PNG was developed using LZ77/Deflate to bypass the patent. Brotli uses a static pre-trained dictionary for web traffic.)*

### Standards: JBIG-1 and JBIG-2

**JBIG-1** (ISO/IEC 11544, ITU-T T.82):
- Context-based arithmetic coding for bi-level images
- Template of 10 pixels with 1 variable position
- Progressive coding (resolution scalability)

**JBIG-2** (ISO/IEC 14492, ITU-T T.88):
- Image segmented into: text, halftones, other
- Text: symbol dictionary coding
- Halftone: dictionary of halftone patterns
- Other: context-based arithmetic coding
- Used in PDF (version 1.4+)

### Image Compression: JPEG-LS and PNG

**JPEG-LS** (based on LOCO-I algorithm) — low complexity lossless for natural images:

*MED Predictor* (Median Edge Detector) using causal neighborhood $(A, B, C)$ for pixel $X$:

$$\hat{x} = \begin{cases} \min(A, B) & \text{if } C \geq \max(A, B) \\ \max(A, B) & \text{if } C \leq \min(A, B) \\ A + B - C & \text{otherwise} \end{cases}$$

| C | B |
|---|---|
| A | X |

Designed to handle sharp edges without overshoot.

**Residual coding**: context modeling via local gradients → **Golomb-Rice coding** for residuals → run-length encoding for uniform regions.

**PNG**:
- Uses LZ77 (Deflate) + Huffman
- Optional pixel predictor similar to JPEG-LS
- Better for computer graphics, icons, text-heavy images

| Codec | Method | Best for |
| :--- | :--- | :--- |
| JPEG-LS | Predictive + Golomb-Rice | Natural photos, medical imaging |
| PNG | LZ77 + Huffman | Graphics, icons, text images |

## Neural Lossless Coding

### Density Estimation Perspective

Neural Lossless Coding (NLC) uses a **Neural Network (NN) as a probability distribution estimator** $Q$ for an arithmetic coder.

The NN minimizes the **Cross-Entropy** between true distribution $P$ and model $Q$:

$$H(P, Q) = H(P) + D_{KL}(P \parallel Q)$$

- $H(P)$: source entropy (physical limit, irreducible)
- $D_{KL}(P \parallel Q)$: penalty for model inaccuracy (redundancy to minimize)

**Advantage over classical context coding**:
- Classical: state space explodes exponentially ($M^{N_S}$ entries for $N_S$-pixel context at $M$ levels)
- Neural: maps contexts to continuous vector space, generalizes to unseen patterns
- Transformers/attention: capture **global dependencies** across the entire image

### Autoregressive Models

**Mathematical foundation** (Chain Rule of probability):

$$P(x_1, \ldots, x_n) = \prod_{i=1}^n P(x_i \mid x_1, \ldots, x_{i-1})$$

The NN estimates $P(x_i \mid x_1, \ldots, x_{i-1})$ for each pixel given all previous (causal) pixels. Bit-rate approaches entropy rate $\mathcal{H}$.

**Trade-off**: high compression, but $N$ forward passes for $N$-pixel image → very high decoding complexity.

### Latent Variable Models

Based on **Variational Inference**: image $x$ mapped to lower-dimensional latent $z$ (non-linear PCA).

**Two-stage coding**:
1. Encode latent features $z$ (summary)
2. Encode $x$ given $z$ (residuals/likelihood)

**Bits-back principle**: bits used to specify $z$ can be "recovered" from randomness of previous message (in a sequence of images).

Performance bounded by **ELBO** (Evidence Lower Bound).

### Neural Predictive Coding

Evolution of classical DPCM: replace linear predictor with a non-linear NN.

$$\hat{x}_i = f_{NN}(\text{Local Context})$$

Trained to minimize **cross-entropy of residual distribution** (not MSE).

**MLP architecture** for the house experiment:
- Input: causal neighborhood $S = \{A, B, C\}$
- Output: $\hat{Y} = f_{MLP}(S, W)$
- Final code: prediction rounded to integer residuals

**Results on house.pgm**:
- 2D linear predictor: residual entropy = 2.830 bpp
- Neural predictor (MLP): residual entropy = **2.704 bpp**

*The NN handles complex textures and non-linear transitions that the deterministic condition ($|C-B| < |C-A|$) misses.*

**Total rate accounting for model transmission cost**:

$$R_{\text{total}} = R_{\text{residuals}} + \frac{L_{\text{model}}}{N}$$

> [!Example] Model Cost
> Small MLP [10, 5] with 3 inputs ≈ 100 weights. Using 32-bit floats:
> $$L_{\text{model}} = 3200 \text{ bits}$$
> For $512 \times 512$ image:
> $$R = 2.704 + \frac{3200}{512^2} \approx 2.716 \text{ bpp}$$
>
> NLC more efficient for large datasets (weights shared) or high-resolution images.

### Current Limitations

| Limitation | Description |
| :--- | :--- |
| **Computational complexity** | AR models: $N$ forward passes per $N$-pixel image — real-time decoding nearly impossible |
| **Generalization gap** | Model trained on natural images may fail on medical/satellite imagery |
| **Hardware requirements** | Requires GPU or NPU at decoder side |
| **Determinism** | Lossless coding requires bit-exact reproducibility across hardware (floating-point issues) |

## Conclusions

### Comparison of All Lossless Coding Techniques

| Method | Efficiency | Complexity | Latency | Best Use Case |
| :--- | :--- | :--- | :--- | :--- |
| Neural (SOTA) | Highest | Ultra High | High | SOTA image/video |
| Arithmetic | High (→ $H$) | High (CPU) | Medium | Bi-level images, CABAC in H.264/H.265 |
| Dictionary (LZW) | Universal | Moderate | Low/Med | Repeating patterns, general files |
| Huffman | Good ($H \leq \mathcal{L} < H+1$) | Low/Med | Very Low | JPEG, general purpose |
| Exp-Golomb | Approximate | Very Low | Negligible | Metadata, sparse residuals |

**The 1-bit penalty**:
- Huffman fails when $H(X) < 1$ bpS (one symbol encodes as 1 bit minimum)
- Arithmetic coding efficient even below 1 bpS

### Lossless Design Matrix

| Source characteristic | Recommended method | Reason |
| :--- | :--- | :--- |
| Memoryless | Huffman / Arithmetic | Respects $H(X)$ bound |
| Stationary with memory | Context-Adaptive Arithmetic | Optimal for Markov statistics |
| Locally stationary | Adaptive Arithmetic | Tracks changing statistics |
| Highly complex dependencies | Neural Models | Captures non-linear, long-range dependencies |

**All methods aim for** $\mathcal{L} \approx \mathcal{H}$. Choice depends on complexity budget, latency requirements, and model cost (transmitting NN weights vs. compression gain).

> **Final rule of thumb:** Use Huffman/EG for speed, Arithmetic/Context for high compression, Dictionary for universal files, and Neural Models for ultimate SOTA performance.
