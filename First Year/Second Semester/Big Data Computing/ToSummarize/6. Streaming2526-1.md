## Dealing with volume and velocity

**Typical scenario:**

- The data to be processed arrive as a continuous stream
  - because they are generated by some evolving (possibly endless) process (e.g., tweets, buy/sell orders, sensor data);
  - or because their massive volume discourages random accesses (e.g., sequential secondary/tertiary data access).
  .
- Therefore: data analysis must happen on the fly using limited memory, without storing all data for subsequent offline processing.
- Many applications (some examples next)

---

## Some applications

**Network management:**
- Stream: packets routed through a router.
- Task: gather traffic statistics (e.g., average number of connections/second to same IP address)

**Online auctions:**
- Stream: online auctions generate data on objects on sale, bids, ...
- Tasks: statistical estimation of auction data (e.g., average selling price over the items sold by each seller, highest bid in a given period of time,...)

---

## Some applications

**Internet of Things:**
- Stream: data generated by thousands/millions of sensors.
- Tasks: learn from data, outlier detection, gather statistics,...

**Sequential disk accesses:**
- Stream: data from a massive file on secondary storage (sequential access rates are higher than random access),
- Tasks: data processing of data in the file. In this case it is also possible to sequentially scan the same file twice or even more times (**multi-pass**).

## Streaming Model

Let $\Sigma = x_1, x_2, \ldots x_n \ldots$ denote the **input stream** received sequentially, where $x_i$ is the i-th element received. Upon receiving $x_n$:

- Suitable data structures stored in the working memory are updated (**UPDATE task**)
- If required, a solution for the problem at hand, relative to the input set $x_1, x_2, \ldots, x_n$ is computed from the data stored in the working memory (**QUERY task**)

The following **Key Performance Indicators** are usually considered

- **KPI 1:** Size $s$ of the working memory (aim: $s \ll |\Sigma|$)
- **KPI 2:** Number $p$ of sequential passes over $\Sigma$ (aim: $p = 1$)
- **KPI 3:** Update time $T_u$ per item (aim: $T_u = O(1)$)
- **KPI 4:** Query time $T_q$ to return a solution to instance $\{x_1, \ldots, x_n\}$ (aim: $T_q$ independent of $n$)

---

## Streaming Model

> **Algorithm Design Techniques**
> - Approximate solutions (exact ones may require excessive space)
> - Maintain lossy summary of $\Sigma$ via a **synopsis** data structure (e.g., random sample, hash-based sketch)

**Typical data analysis tasks**
- Identification of frequent items (or frequent patterns).
- Useful statistics: e.g., frequency moments, quantiles, histograms
- Optimization and graph problems: e.g., clustering, triangle counting

**Goal:** suitable tradeoffs between accuracy, working memory, update/query time (i.e., *throughput*).

## Warm-up: finding the majority element

> **Majority problem**
> Given a stream $\Sigma = x_1, x_2, \ldots, x_n$, return the element $x$ (if any) that occurs $> n/2$ times in $\Sigma$.

**Examples:**
- In $\Sigma = A, B, A, C, A, D, A, A$, the majority element is $A$.
- In $\Sigma = A, B, C, D, D, E, E$, a majority element does not exist.

**Standard off-line setting.** Easily solved using linear space in $O(n \log n)$ time, through sorting, or $O(n)$ expected time, through hashing.

**Streaming setting.** Need 1 or 2 passes, depending on goals
- First pass (Boyer-Moore algorithm): find an element $x$ which is the majority element, if one exists.
- Second pass: check whether $x$ is indeed the majority element.

---

## Boyer-Moore algorithm

The Boyer-Moore algorithm maintains 2 integers *cand* and *count*:

- *cand* contains a candidate majority element (*the true majority element, if one exists*);
- *count* is a counter;

**Initialization:** $\text{cand} \leftarrow \text{null}$ and $\text{count} \leftarrow 0$.

```
For each x_t in Σ do
  if count = 0 then {cand ← x_t; count ← 1;}
  else {
    if cand = x_t then count ← count + 1
    else count ← count − 1
  }                                             } Update

At the end: return cand                         } Query
```

## Warm-up: finding the majority element

> **Theorem**
> The Boyer-Moore algorithm is *correct* (i.e., it returns the true majority, if one exists) and requires:
> - working memory of size $O(1)$;  } Straightforward
> - 1 pass;
> - $O(1)$ update and query times.

We need to prove only correctness

## Proof (handwritten)

Proof. To show correctness we must consider only the case when a true majority exists. Then, let $m$ be the true majority element in $\Sigma$, and let $\text{cand}_t$ and $\text{count}_t$ be the values of the 2 variables cand and count after processing $x_1 \ldots x_t$.
The proof is based on the following INVARIANT

For any $t \geq 0$, $x_1, x_2 \ldots x_t$ can be partitioned into:
- $\text{count}_t \geq 0$ occurrences of $\text{cand}_t$
- $(t - \text{count}_t)/2$ pairs $(e_1, e_2)$ with $e_1 \neq e_2$

We now show that, for an arbitrary stream $\Sigma$ of length $n$ with a true majority $m$, at the end of the algorithm $\text{cand}_n = m$

Therefore, $m$ can occur at most $(n - \text{count}_n)/2$ times, and since $\text{count}_n \geq 0$ we have that

$$(n - \text{count}_n)/2 \leq n/2$$

## Sampling

> **Definition**
> Given a set $X$ of $n$ elements and an integer $1 \leq m < n$, an $m$-sample of $X$ is a random subset $S \subset X$ of size $m$, such that for each $x \in X$, we have $\Pr(x \in S) = m/n$ (**uniform sampling**).

**In the off-line setting**, an $m$-sample $S$ of $X$ can be easily computed by selecting $m$ elements from $X$ (or, equivalently, their indices) with uniform probability and without replacement.

**In the streaming setting**, things get harder, especially in application scenarios where streams are potentially unbounded and at every time step a random sample of the elements seen so far is sought (e.g., *monitoring of sensor data*)

---

## Sampling

> **Sampling problem**
> Given a (possibly unbounded) stream $\Sigma = x_1, x_2, \ldots$ and an integer $m < |\Sigma|$, maintain, for every $t \geq m$, an $m$-sample $S$ of the prefix $\Sigma_t = x_1, x_2, \ldots, x_t$.

For a fixed $t$, the solution is easy
- Before the stream starts, compute an $m$-sample $\mathcal{I}$ of the set of integers $\{1, \ldots t\}$.
- For each entry $x_i \in \Sigma_t$ with $i \in \mathcal{I}$, add $x_i$ to $S$.

**How can we maintain $S$ for every $t$?**

---

## Reservoir Sampling: algorithm

The following algorithm, dubbed Reservoir Sampling was developed by J.S. Vitter in 1985.

**Initialization:** $S \leftarrow \emptyset$.

```
For each x_t in Σ do
  if t ≤ m then add x_t to S;
  else with probability m/t do the following: {
    evict an element x from S, chosen with uniform probability
    add x_t to S
  }
```

Remark: the stream size needs not be known, and, in fact, it can be unbounded.

## Reservoir Sampling: analysis

> **Theorem**
> Let $\Sigma = x_1, x_2, \ldots$ At any time $t \geq m$, the set $S$ maintained by the reservoir sampling algorithm is an $m$-sample of $\Sigma_t = x_1, x_2, \ldots, x_t$. Moreover, the algorithm features $O(1)$ update time.

---

## Proof (handwritten)

Proof: the only non trivial thing to prove is the fact that $S$ is indeed an $m$-sample of $x_1 \ldots x_t$

Let $S_t$ be $S$ after processing $x_1 \ldots x_t$. We show by induction on $t \geq m$ that for every $i \in [1,t]$ we have $P_t(x_i \in S_t) = m/t$

BASE for INDUCTION: $t=m$ (straightforward)

INDUCTION STEP: Suppose that the property holds at time $t-1$, that is
$$\forall i \in [1, t-1] \quad P_t(x_i \in S_{t-1}) = \frac{m}{t-1} \quad \text{(inductive Hp.)}$$

---

##  

We now prove that $P_t(x_i \in S_t) = m/t$ $\forall i \in [1,t]$

* $P_t(x_t \in S_t) = m/t$ by construction

* Consider an arbitrary $x_i$ with $i < t$, and define event $A =$ "$x_t$ is added to $S_t$ at time $t$"

CLEARLY: $P_t(A) = m/t$ and $P_t(\neg A) = 1 - m/t$

By the law of total probabilities we can write:
$$P_t(x_i \in S_t) = \underbrace{P_t((x_i \in S_t) \cap A)}_{(1)} + \underbrace{P_t((x_i \in S_t) \cap \neg A)}_{(2)}$$

---

## Proof continued (handwritten)

$(1)$: $P_t((x_i \in S_t) \cap A) = P_t(x_i \in S_t \mid A) \cdot \underbrace{P_t(A)}_{= m/t}$

$$P_t(x_i \in S_t \mid A) = \underbrace{P_t(x_i \in S_{t-1})}_{m/(t-1)\ \text{by inductive hp.}} \times \underbrace{P_t(x_i \text{ not evicted at time } t)}_{1 - 1/m}$$

$$\Rightarrow P_t((x_i \in S_t) \cap A) = \frac{m}{t-1} \cdot \left(1 - \frac{1}{m}\right) \cdot \frac{m}{t}$$

$(2)$ $P_t((x_i \in S_t) \cap \neg A) = P_t(x_i \in S(\neg A)) \cdot \underbrace{P_t(\neg A)}_{1 - m/t}$

---

## Proof continued (handwritten)

$$P_t(x_i \in S_t \mid \neg A) = P_t(x_i \in S_{t-1}) = \frac{m}{t-1} \quad \text{by inductive Hp.}$$
$$\Rightarrow P_t((x_i \in S_t) \cap \neg A) = \frac{m}{t-1} \cdot \left(1 - \frac{m}{t}\right)$$

By putting together all pieces, we conclude that:

$$P_t(x_i \in S_t) = (1) + (2)$$
$$= \frac{m}{t-1} \cdot \left(1 - \frac{1}{m}\right) \cdot \frac{m}{t} + \frac{m}{t-1} \cdot \left(1 - \frac{m}{t}\right)$$
$$= \frac{m}{t-1} \cdot \left(\frac{m}{t} - \frac{1}{t} + 1 - \frac{m}{t}\right)$$
$$= \frac{m}{t-1} \cdot \left(1 - \frac{1}{t}\right) = \frac{m}{t} \qquad \square$$

## Sampling-based applications: Frequent Items

> **Frequent Items problem**
> Given a stream $\Sigma = x_1, x_2, \ldots, x_n$ of $n$ items from a universe $U$ and a frequency threshold $\varphi \in (0,1)$, determine all distinct items that occur at least $\varphi \cdot n$ times in $\Sigma$ (we call them **frequent items**).

---

## Example (handwritten)

Example: $n = 100$ $\quad U = \{A,B,C,D,E\}$
* $A$: 30 occurrences
* $B$: 30  "$\quad\quad\quad\quad\quad\quad\quad\quad \varphi = 0.3 \Rightarrow$
* $C$: 20  "$\quad\quad\quad\quad\quad\quad\quad\quad\quad$ Frequent Items $= \{A,B\}$
* $D,E$: 10  "  each

---

## Observations (handwritten)

OBSERVATIONS

1: Number of frequent items is $\leq 1/\varphi$

2: EXACT STRATEGY
  - Use a Map (e.g. Hash Table) $T$ which maintains the # occurrences of all distinct items which have been arrived so far
  - At the end of the stream, return all items in $T$ with $\geq \varphi \cdot n$ occurrences

---

## Weaknesses of EXACT STRATEGY (handwritten)

Weaknesses of EXACT STRATEGY:
let $\bar{n}$ be the number of distinct items in $\Sigma$
If $\bar{n} \approx n$ but $1/\varphi \ll n$ the strategy becomes inefficient in terms of both space and time requirements

Unfortunately, to determine exactly the frequent items and their counts spending time and space proportional to the number of distinct items seems necessary

---

## Frequent Items with Reservoir sampling

Frequent items can be approximated through reservoir sampling:

1. Extract an $m$-sample $S$ from $\Sigma$ with reservoir sampling. Note that the same element may occur multiple times in the sample!
2. Return the subset $S' \subseteq S$ of distinct items in the sample

**How well does $S'$ approximate the set of frequent items?**

- If $m \geq 1/\varphi$, for any given frequent item $a$, we expect to find at least one copy of $a$ in $S$ (hence in $S'$).
- However, some frequent item may be missed, and $S'$ may contain items with very low frequency.

## Approximate Frequent Items

> **$\epsilon$-Approximate Frequent Items ($\epsilon$-AFI) problem**
> Given the stream $\Sigma = x_1, x_2, \ldots, x_n$ of $n$ items, a frequency threshold $\varphi \in (0,1)$, and an accuracy parameter $\epsilon \in (0, \varphi)$, return a set of distinct items that:
> - includes **all** items occurring at least $\varphi \cdot n$ times in $\Sigma$.
> - contains **no** item occurring less than $(\varphi - \epsilon) \cdot n$ times in $\Sigma$.

**Remark:** with this formulation, we avoid false negatives but tolerate high-frequency false positives.

_[Figura: linea numerica da 0 a 1 con tre zone: "forbidden frequencies" (da 0 a $\varphi-\varepsilon$), "tolerated frequencies" (da $\varphi-\varepsilon$ a $\varphi$), "target frequencies" (da $\varphi$ a 1)]_

## Sticky Sampling

Sticky Sampling provides a probabilistic solution to the $\epsilon$-AFI problem.

MAIN INGREDIENTS:
- Confidence parameter $\delta \in (0,1)$.
- Hash Table $S$, whose entries are pairs $(x, f_e(x))$ where
  - $x$ (the key) is an item
  - $f_e(x)$ (the value) is an lower bound to the number of occurrences of $x$ seen so far.
- Sampling rate chosen to ensure (with probability $\geq 1 - \delta$) the frequent items are in the sample.

---

## Sticky Sampling: algorithm

Consider stream $\Sigma = x_1, x_2, \ldots, x_n$, and **assume $n$ known!**

**Initialization:**
- $S \leftarrow$ empty Hash Table;
- $r = \lceil\ln(1/(\delta\varphi))\rceil/\varepsilon$; `// sampling rate = r/n.`

```
For each x_t in Σ do
  if (x_t, f_e(x_t)) ∈ S then f_e(x_t) ← f_e(x_t) + 1;
  else add (x_t, 1) to S with probability r/n; /* (start tracking x_t) */

At the end: return all items x in S with f_e(x) ≥ (φ − ε)n
```

---

## Sticky Sampling: analysis

> **Theorem**
> Sticky sampling solves the $\epsilon$-AFI problem correctly with probability at least $1 - \delta$ and requires:
> - working memory of size $O(r) = O(\ln(1/(\delta\varphi)))/\varepsilon)$, in expectation;
> - 1 pass;
> - $O(1)$ update time in expectation.
> - $O(r) = O(\ln(1/(\delta\varphi))/\varepsilon)$ query time in expectation.

**Remark:** The space is independent of the stream length.

For fixed $\delta$, $\varepsilon$ the sampling rate will be $o\!\left(\frac{1}{\varphi n}\right)$
$\Rightarrow$ smaller sampling rate than the one required by Reservoir sampling

---

## Proof (handwritten)

Proof:
* WORKING MEMORY SIZE: proportional to the number of entries in $S$ (assuming each entry taking $O(1)$ space). Now each $x_t$ contributes a new entry to $S$ with probability $p_t \leq r/n$

$$X_t = \begin{cases} 1 & \text{if } x_t \text{ contributes a new entry to } S \\ 0 & \text{otherwise} \end{cases}$$

at the end of the stream $|S| = \sum_{t=1}^{n} X_t$

$$\Rightarrow \mathbb{E}[|S|] = \mathbb{E}\!\left[\sum_{t=1}^{n} X_t\right] = \sum_{t=1}^{n} \mathbb{E}[X_t] = \sum_{t=1}^{n} p_t \leq n \cdot \frac{r}{n} = r$$

---

## Proof continued (handwritten)

$\Rightarrow$ working memory size $= O(r)$

* 1 PASS, $O(1)$ UPDATE TIME (in expectation): Straightforward

* QUERY TIME: $O(r)$ in expectation  immediate consequence of the fact that $\mathbb{E}[|S|] = O(r)$

* CORRECTNESS: we need to prove that with probability $\geq 1-\delta$ the returned output satisfies
(A) The output contains all true frequent items

---

## Proof continued (handwritten)

(B) The output contains no item that occurs less than $(\varphi-\varepsilon)n$ times

Property (B) is IMMEDIATE by construction, since the output contains only items that in $S$ have frequency value $\geq (\varphi-\varepsilon) \cdot n$, and frequency values in $S$ are always lower bounds to the true frequencies $\Rightarrow$ we need to prove only Property (A)

PROOF that (A) holds with probability $\geq 1-\delta$

let $a$ be an arbitrary true frequent item

---

## Proof continued (handwritten)

$$P_t(a \text{ is not returned in the output})$$
$$\leq P_t(\text{none of the first } \lceil\varepsilon n\rceil \text{ occurrences of } a \text{ are sampled})$$
$$= \left(1 - \frac{r}{n}\right)^{\lceil\varepsilon n\rceil} \leq \left(1 - \frac{r}{n}\right)^{\varepsilon n}$$
$$= \left(1 - \frac{r}{n}\right)^{\varepsilon n \cdot \frac{r}{n} \cdot \frac{n}{r}} = \left(\!\left(1 - \frac{1}{n/r}\right)^{n/r}\right)^{\varepsilon r}$$
$$\leq \left(\frac{1}{e}\right)^{\varepsilon r} \quad \text{when we use the fact that } \left(1 - \frac{1}{x}\right)^x \leq \frac{1}{e} \quad \forall x \geq 1$$

let $a_1, a_2, \ldots, a_k$ be all true frequent items
we know $k \leq 1/\varphi$

---

## Proof continued (handwritten)

Now
$$P_t(\exists \text{ some } a_i \text{ not returned in the output})$$
$$\leq \sum_{i=1}^{k} P_t(a_i \text{ is not returned in the output})$$
$$\leq k \cdot \left(\frac{1}{e}\right)^{\varepsilon r} \leq \frac{1}{\varphi} \cdot \left(\frac{1}{e}\right)^{\varepsilon \cdot \ln(1/(\delta\varphi))/\varepsilon} \qquad \text{UNION BOUND}$$
$$= \frac{1}{\varphi} \cdot \left(\frac{1}{e}\right)^{\ln(1/(\delta\varphi))} = \frac{1}{\varphi} \cdot \delta\varphi = \delta$$

$$\Rightarrow P_t(\text{all frequent items are returned}) \geq 1 - \delta$$
