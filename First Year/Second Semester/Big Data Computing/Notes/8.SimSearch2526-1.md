## Introduction to Similarity Search

### Motivating Applications

Similarity search starts from a collection of objects, a query object, and a distance
function. Its goal is to retrieve objects close to the query according to that distance.

#### Searching near Points of Interest

![[ToSummarize/8.SimSearch2526-1_images/page-004-map.png]]
*Figure 1 - Points of interest near a current location on a map.*

**Data:** points of interest (POIs), a distance function, and a threshold $r$.

**Goal:** find POIs near the current position, for example, those at distance at most $r$.

#### Searching Similar Images

![[ToSummarize/8.SimSearch2526-1_images/page-005-image-mosaic.png]]
*Figure 2 - A collection of images used in an image-similarity query.*

**Data:** a set of images, a distance function, and a threshold $r$.

**Goal:** find images similar to a given image, meaning images within distance at most $r$.

Images can be embedded into high-dimensional vectors using a machine-learning model. Their
similarity is then measured by a vector distance, such as Euclidean or angular distance. The
same idea applies to songs, for example, in Shazam.

### Similarity Search Model

The examples above are instances of **similarity search**: given a set of objects, retrieve
items that are similar, or near, to a query object.

A **distance function** quantifies similarity. Two objects are considered near when their
distance is below a chosen threshold.

The examples differ mainly in dimensionality:

| Example | Representation | Dimensionality |
|---|---|---|
| Points on a map | Points in $\mathbb{R}^2$ | Low |
| Images | Vectors in $\mathbb{R}^c$ | High, often $c\gg 100$ |

### Applications

- **Information retrieval:** search for similar documents, images, or other objects.
- **Recommendation systems:** suggest items using the behavior of similar users.
- **Entity resolution:** match equal or similar records.
- **Plagiarism detection:** find documents, papers, or exams with similar structure.
- **Outlier detection:** assign each element an outlier score based on its distance from its
  $k$-th nearest neighbor.

## Similarity Search Problems

### r-Near Neighbor Search

For a metric space $(M,d)$, a point $q\in M$, and a threshold $r>0$, the ball of radius $r$
centered at $q$ is

$$
B_r(q)=\{p\in M:d(p,q)\leq r\}.
$$

> [!Important] Definition - $r$-Near Neighbor Search ($r$-NNS)
> **Statement:** Given a set $P$ of $n$ points from a metric space $(M,d)$, construct a data
> structure that, given a query point $q\in M$ and a threshold $r>0$, returns:
>
> - a point $p\in B_r(q)\cap P$, if such a point exists;
> - `null` if $B_r(q)\cap P=\emptyset$.
>
> **Observations:**
>
> - The query is unknown when the data structure is constructed.
> - If $B_r(q)\cap P$ contains several points, any one of them is a valid answer.
> - The distance function and threshold depend on the application.
>
> **Intuition:** Preprocessing $P$ should make queries faster than scanning every point.

![[ToSummarize/8.SimSearch2526-1_images/page-009-r-nns-example.png]]
*Figure 3 - An $r$-NNS query in $(M=\mathbb{R}^2,d=\lVert\cdot\rVert)$; any input point inside the radius-$r$ ball is valid.*

### Related Problems

| Problem | Query input | Required output |
|---|---|---|
| **$r$-near neighbor reporting** | $P$, point $q$, threshold $r$ | Every point in $B_r(q)\cap P$ |
| **Nearest neighbor search** | $P$, point $q$ | Closest point to $q$ in $P$ |
| **$k$-nearest neighbor search** | $P$, point $q$, integer $k\geq1$ | The $k$ closest points to $q$ in $P$ |
| **Similarity join** | Sets $P,Q$, threshold $r$ | All pairs $(p,q)$ with $p\in P$, $q\in Q$, and $d(p,q)\leq r$ |

Nearest-neighbor and $k$-nearest-neighbor search do not require a threshold. They are commonly
reduced to multiple $r$-NNS instances using a suitable sequence of values for $r$.

### Computational Setting

The lecture first uses a sequential model and evaluates a data structure through three costs:

| Indicator | Meaning |
|---|---|
| **Construction time** | Time required to build the data structure |
| **Space** | Memory words required to store it |
| **Query time** | Time required to answer one query |

For points in $\mathbb{R}^D$, assume that computing $d(x,y)$ costs $O(D)$ time and storing one
point requires $O(D)$ words.

Very large inputs may instead require distributed or streaming solutions. This remains an active
research area.

### Brute-Force Baseline

> [!Important] Algorithm - Brute-Force $r$-NNS
> **Construction:** Store all points of $P$ in a list.
>
> **Query:** Given $q$, compute $d(q,p)$ for every $p\in P$. Return the first point
> $p'\in P$ satisfying $d(q,p')\leq r$, if one exists; otherwise, return `null`.
>
> For $P\subset\mathbb{R}^D$ with $|P|=n$:
>
> | Cost | Bound |
> |---|---|
> | Construction time | $O(n)$ |
> | Space | $O(Dn)$ |
> | Query time | $O(Dn)$ |
>
> **Reasoning:** A query performs $n$ distance computations, each costing $O(D)$.
>
> **Limitation:** Query time is linear in the input size and therefore too high for large $P$.

## Range Reporting

To improve exact similarity search in low dimensions under Euclidean distance, use a
**kd-tree**. A kd-tree recursively partitions space into rectangular regions and directly solves
the related **Range Reporting** problem.

> [!Important] Definition - Range Reporting (RR)
> **Statement:** Given a set $P\subset\mathbb{R}^D$ of $n$ points, construct a data structure
> that, given an axis-aligned rectangular region $R$, returns every point of $P$ contained in
> $R$.
>
> A rectangle in $D$ dimensions has the form
>
> $$
> R=[x_{1,1},x_{1,2}]\times\cdots\times[x_{D,1},x_{D,2}]
> \subset\mathbb{R}^D.
> $$
>
> It contains exactly the points $p=(p_1,\ldots,p_D)$ satisfying
> $p_i\in[x_{i,1},x_{i,2}]$ for every $i\in\{1,\ldots,D\}$.

### Range Reporting in R2

*Figure 4 - A two-dimensional range query returns all points inside rectangle $R$.*

### Range Reporting versus r-NNS

| Problem | Query | Task |
|---|---|---|
| Range Reporting | Rectangle $R$ | Return all points in $R\cap P$ |
| $r$-NNS | Point $q$ and distance $r$ | Return any point in $B_r(q)\cap P$, if one exists |

## kd-Trees

![[ToSummarize/8.SimSearch2526-1_images/page-017-kd-tree.png]]
*Figure 6 - A spatial partition and its corresponding binary kd-tree.*

### Definition

The lecture first defines kd-trees for $D=2$; the definition extends to $D>2$.

Let $P$ contain $n$ points in $\mathbb{R}^2$, and let
$R(P)\subset\mathbb{R}^2$ be a rectangle containing all points of $P$.

> [!Important] Definition - kd-tree
> A **kd-tree** $T$ for $P$ is a binary tree defining a hierarchical decomposition of $R(P)$
> into nested rectangular subregions.
>
> - Every internal node $v$ is associated with a rectangle
>   $\operatorname{region}(v)$ and represents
>   $P_v=P\cap\operatorname{region}(v)$.
> - For root $r$, $\operatorname{region}(r)=R(P)$ and $P_r=P$.
> - Every external node, or leaf, $v$ is associated with a region containing one point
>   $p_v\in P$; therefore, $P_v=\{p_v\}$.
>
> **Intuition:** Descending the tree repeatedly refines the current rectangle until one point
> remains at each leaf.

### Splitting Rule

Every internal node $v$ with $|P_v|\geq2$ has two children $u$ and $w$. Their regions are
obtained by splitting $\operatorname{region}(v)$ through a vertical or horizontal line
$\ell_v$, according to the depth of $v$.

If $v$ has even depth, $\ell_v$ is vertical at abscissa $x_v$:

$$
\begin{aligned}
\operatorname{region}(u)
&=\operatorname{region}(v)\cap\mathbb{R}^2_{x\leq x_v},\\
\operatorname{region}(w)
&=\operatorname{region}(v)\cap\mathbb{R}^2_{x>x_v}.
\end{aligned}
$$

If $v$ has odd depth, $\ell_v$ is horizontal at ordinate $y_v$:

$$
\begin{aligned}
\operatorname{region}(u)
&=\operatorname{region}(v)\cap\mathbb{R}^2_{y\leq y_v},\\
\operatorname{region}(w)
&=\operatorname{region}(v)\cap\mathbb{R}^2_{y>y_v}.
\end{aligned}
$$

Line $\ell_v$ is chosen so that

$$
|P_u|=\left\lfloor\frac{|P_v|}{2}\right\rfloor,
\qquad
|P_w|=\left\lceil\frac{|P_v|}{2}\right\rceil.
$$

For convenience, assume that no two points have the same abscissa or ordinate.

![[ToSummarize/8.SimSearch2526-1_images/page-020-splitting-rule.png]]
*Figure 7 - Vertical and horizontal splits used at alternating kd-tree depths.*

For every node $v\in T$, $\operatorname{region}(v)$ is determined by split lines stored at the
ancestors of $v$.

![[ToSummarize/8.SimSearch2526-1_images/page-021-ancestor-regions.png]]
*Figure 8 - Ancestor split lines determine the rectangular region associated with node $v$.*

### Storage and Construction

> [!Important] kd-tree Storage and Construction
> Let $T$ be a kd-tree for $P\subset\mathbb{R}^2$ with $|P|=n$.
>
> **Storage:** $T$ requires $O(n)$ space. It contains at most $2n$ nodes.
>
> - Every internal node $v$ stores $\operatorname{region}(v)$, requiring four coordinates,
>   and split line $\ell_v$.
> - Every leaf $v$ stores point $p_v$.
>
> **Construction:** $T$ can be built in $O(n\log n)$ time. Construction details are omitted
> in the source.
>
> **Intuition:** Median splits keep the tree balanced, while its leaves correspond one-to-one
> with input points.

### Range Query Algorithm

Given kd-tree $T$ and rectangle $R=[x_1,x_2]\times[y_1,y_2]$, start at the root and recursively
visit nodes whose regions intersect $R$.

- At leaf $v$, return $p_v$ if $p_v\in R$.
- At internal node $v$, recurse on every child whose region intersects $R$.
- If $\operatorname{region}(v)\cap R=\emptyset$, return $\emptyset$ without visiting its
  descendants.

Recursion may continue through both subtrees.

> [!Important] Algorithm - `SearchKdTree`
> **Input:** Node $v$ of a kd-tree and query rectangle $R$.
>
> **Output:** Points in $R$ stored in the subtree rooted at $v$.
>
> ```text
> SearchKdTree(v, R)                // first invocation: v = root
>
> if v is a leaf then
>     if p_v is in R then
>         out <- {p_v}
>     else
>         out <- empty set
> else
>     out <- empty set
>     let u and w be the left and right children of v
>     let R_u <- region(u) intersect R
>     let R_w <- region(w) intersect R
>     if R_u is not empty then
>         out <- out union SearchKdTree(u, R_u)
>     if R_w is not empty then
>         out <- out union SearchKdTree(w, R_w)
> return out
> ```
>
> **Correctness:** A subtree is skipped only when its region has empty intersection with $R$;
> therefore, it cannot contain a reportable point. Every intersecting leaf is tested directly.

### Performance in R2

> [!Important] Theorem - Range Reporting with kd-trees in $\mathbb{R}^2$
> Range Reporting for $n$ points in $\mathbb{R}^2$ can be solved with:
>
> | Quantity | Bound |
> |---|---|
> | Construction time | $O(n\log n)$ |
> | Space | $O(n)$ |
> | Query time | $O(\sqrt{n}+k)$ |
>
> Here, $k$ is the number of reported points.

#### Proof

Construction time and space follow from the results above. Query time is proportional to the
number of tree nodes visited by `SearchKdTree`. Define

$$
Q_1(R)=\left\{v\in T:
\operatorname{region}(v)\cap R\neq\emptyset
\text{ and }
\operatorname{region}(v)\nsubseteq R
\right\},
$$

and

$$
Q_2(R)=\left\{v\in T:
\operatorname{region}(v)\cap R\neq\emptyset
\text{ and }
\operatorname{region}(v)\subseteq R
\right\}.
$$

> [!Important] Observation - Nodes Visited by `SearchKdTree`
> Except possibly for its first call on the root, `SearchKdTree` is called only on nodes in
> $Q_1(R)\cup Q_2(R)$.

![[ToSummarize/8.SimSearch2526-1_images/page-032-proof-1.png]]
*Figure 15 - First part of the handwritten query-time proof and definitions of $Q_1(R)$ and $Q_2(R)$.*

Each call performs $O(1)$ work besides recursive calls. Thus, query time is

$$
O\left(1+|Q_1(R)|+|Q_2(R)|\right).
$$

The source then states

$$
|Q_1(R)|=O(\sqrt{n})
$$

and

$$
|Q_2(R)|=O(k).
$$

The first bound limits the number of nodes whose regions cross the boundary of $R$. The second
charges fully contained visited nodes to reported output points. Therefore,

$$
O\left(1+|Q_1(R)|+|Q_2(R)|\right)=O(\sqrt{n}+k).
$$

![[ToSummarize/8.SimSearch2526-1_images/page-033-proof-2.png]]
*Figure 16 - Completion of the handwritten $O(\sqrt{n}+k)$ query-time proof.*

## Using kd-Trees for r-NNS

Let $T$ be a kd-tree for $P\subset\mathbb{R}^2$. To answer an $r$-NNS query centered at
$q\in\mathbb{R}^2$:

1. Let $R_q$ be the smallest square enclosing ball $B_r(q)$.
2. Compute

   $$
   S=\operatorname{SearchKdTree}(T.\operatorname{root}(),R_q).
   $$

3. Return a point $p\in S\cap B_r(q)$, if one exists; otherwise, return `null`.

![[ToSummarize/8.SimSearch2526-1_images/page-036-enclosing-square.png]]
*Figure 17 - Smallest square $R_q$ enclosing the circular query ball $B_r(q)$.*

This reduction works efficiently in practice. Let

$$
k_s=|S|
\qquad\text{and}\qquad
k_q=|S\cap B_r(q)|.
$$

The range query costs

$$
O(\sqrt{n}+k_s),
$$

not $O(\sqrt{n}+k_q)$. Pathological inputs may have $k_s\gg k_q$ because corners of the
enclosing square fall outside the ball. The source leaves open how to close this theoretical gap.

## Generalization to D Dimensions

The kd-tree construction generalizes to $D$ dimensions:

- At each level, binary splits use a different coordinate in cyclic order:

  $$
  1,2,\ldots,D,1,2,\ldots
  $$

- `SearchKdTree` remains unchanged.

> [!Important] Theorem - Range Reporting with kd-trees in $\mathbb{R}^D$
> Range Reporting for $n$ points in $\mathbb{R}^D$ can be solved with:
>
> | Quantity | Bound |
> |---|---|
> | Construction time | $O(Dn\log n)$ |
> | Space | $O(Dn)$ |
> | Query time | $O(Dn^{1-1/D}+k)$ |
>
> Here, $k$ is the number of reported points.
>
> **Intuition:** As $D$ grows, exponent $1-1/D$ approaches $1$, so the query bound approaches
> linear dependence on $n$.

## Curse of Dimensionality

> [!Important] Curse of Dimensionality
> **Statement:** kd-tree query cost converges to linear-scanning time as dimension $D$
> increases.
>
> A strong conjecture states that exact $r$-NNS cannot be solved in truly sublinear query time
> for large $D$: no query bound $O(n^\varepsilon)$ is expected for a constant
> $\varepsilon<1$.
>
> **Intuition:** Exact spatial partitioning loses its pruning power in high dimensions. This
> motivates Approximate Near Neighbor search and Locality Sensitive Hashing in Part 2.

## Final Summary

| Concept / Technique | Definition or bound | Conditions / exam note |
|---|---|---|
| Similarity search | Retrieve objects near a query under distance $d$ | Requires representation, metric, and usually threshold |
| Query ball | $B_r(q)=\{p\in M:d(p,q)\leq r\}$ | Defined in metric space $(M,d)$ |
| $r$-NNS | Return any point in $B_r(q)\cap P$, or `null` | One valid neighbor is sufficient |
| Range Reporting | Return every point in axis-aligned rectangle $R$ | Related problem directly solved by kd-trees |
| Brute-force $r$-NNS | Query time $O(Dn)$ | $n$ distance tests, each costing $O(D)$ |
| kd-tree | Balanced binary decomposition into rectangles | Alternates split coordinates; leaves store points |
| kd-tree in $\mathbb{R}^2$ | Construction $O(n\log n)$, space $O(n)$ | At most $2n$ nodes |
| Range query in $\mathbb{R}^2$ | $O(\sqrt{n}+k)$ | $k$ is number of reported points |
| Proof partition | $Q_1(R)$ boundary-crossing, $Q_2(R)$ contained | $|Q_1|=O(\sqrt n)$ and $|Q_2|=O(k)$ |
| kd-tree reduction for $r$-NNS | Query enclosing square $R_q$, then filter by $B_r(q)$ | Costs $O(\sqrt n+k_s)$, where $k_s=|S|$ |
| kd-tree in $\mathbb{R}^D$ | Query $O(Dn^{1-1/D}+k)$ | Bound degrades as $D$ grows |
| Curse of dimensionality | Query cost approaches linear scan | Motivates approximate high-dimensional methods |
