## Introduction to Similarity Search

![[Pics/SimSearch1/SimSearch1-03.png]]

### Motivating Examples

The lecture starts from two concrete applications where the same abstract task appears:
given a collection of objects, a query object, and a distance function, find objects that
are close to the query.

#### Searching near POIs

![[Pics/SimSearch1/SimSearch1-04.png]]
*Figure 4 - Points of interest on a map. The task is to find POIs close to the current position.*

**Data:** points of interest (POIs) in a map, a distance function, and a threshold $r$.

**Goal:** find POIs near the current position, for example all POIs at distance $\leq r$.

#### Searching similar images

![[Pics/SimSearch1/SimSearch1-05.png]]
*Figure 5 - Image similarity search. Images are represented by high-dimensional vectors and compared by distance.*

**Data:** a set of images, a distance function, and a threshold $r$.

**Goal:** find images similar to a given image, meaning images within distance $\leq r$.

Similarity can be computed by embedding images into high-dimensional vectors with a
machine learning model, then computing the distance between the respective vectors.
Examples include Euclidean distance and angular distance. Similar ideas are used for
songs, for example in Shazam.

### Similarity Search Problem Family

![[Pics/SimSearch1/SimSearch1-06.png]]
*Figure 6 - Similarity search abstracts both map search and image search.*

The two case studies above are examples of **similarity search**: given a set of
objects, find items that are similar, or near, to a query.

A **distance function** is required to evaluate the similarity of two objects. Two
objects are considered similar, or near, if their distance is below a given threshold.

The main difference between the two examples is dimensionality:

| Example | Representation | Dimension |
|---|---|---|
| Points in a map | Points in $\mathbb{R}^2$ | Low-dimensional |
| Images | Vectors in $\mathbb{R}^c$ | High-dimensional, e.g. $c >> 100$ |

![[Pics/SimSearch1/SimSearch1-07.png]]
*Figure 7 - Typical applications of similarity search.*

Some applications:

- **Information retrieval:** search similar documents, images, and related objects.
- **Recommendation systems:** provide suggestions based on behaviors of similar users.
- **Entity resolution:** match equal or similar records.
- **Plagiarism detection:** match documents, such as papers or exams, with similar structure.
- **Outlier detection:** assign to each element an outlier score based on the distance
  from its $k$-th nearest neighbor.

## Formal Similarity Search Problems

### $r$-Near Neighbor Search

![[Pics/SimSearch1/SimSearch1-08.png]]
*Figure 8 - Formal definition of the $r$-Near Neighbor Search problem.*

For a metric space $(M, d)$, a query point $q \in M$, and a distance threshold
$r > 0$, define the ball of radius $r$ around $q$ as:

$$
B_r(q) = \{p \in M : d(p, q) \leq r\}.
$$

> [!Important] Definition - $r$-Near Neighbor Search ($r$-NNS)
> **Statement:** Given a set $P$ of $n$ points from the metric space $(M, d)$,
> construct a data structure that, given a query point $q \in M$ and a distance
> threshold $r > 0$, returns:
>
> - a point $p \in B_r(q) \cap P$, if any such point exists;
> - null if $B_r(q) \cap P = \emptyset$.
>
> **Observations:**
>
> - The query is unknown when the data structure is constructed.
> - If there are multiple points in $B_r(q) \cap P$, an arbitrary one is returned.
> - The distance function and the threshold $r$ depend on the application.
>
> **Intuition:** The data structure should avoid scanning all of $P$ at query time,
> while still being able to find one point close enough to $q$.

![[Pics/SimSearch1/SimSearch1-09.png]]
*Figure 9 - Example of $r$-NNS in $(M = \mathbb{R}^2, d = ||\cdot||)$.*

### Other Similarity Search Problems

![[Pics/SimSearch1/SimSearch1-10.png]]
*Figure 10 - Variants of similarity search.*

Several other variants of similarity search are common:

| Problem | Input | Output |
|---|---|---|
| $r$-near neighbor reporting | Set $P$, query point $q$, threshold $r$ | All points in $B_r(q) \cap P$ |
| Nearest neighbor search | Set $P$, query point $q$ | The closest point to $q$ in $P$ |
| $k$-nearest neighbor search | Set $P$, query point $q$, integer $k \geq 1$ | The $k$ closest points to $q$ in $P$ |
| Similarity join | Sets $P$ and $Q$, threshold $r$ | Pairs $p \in P$, $q \in Q$ with $d(p, q) \leq r$ |

Searching for the nearest neighbor, or the $k$-nearest neighbors, does not require a
threshold $r$. However, it is usually performed by reducing it to instances of $r$-NNS,
using a suitable sequence of values of $r$.

### Computational Setting

![[Pics/SimSearch1/SimSearch1-11.png]]
*Figure 11 - Sequential computational setting and performance indicators.*

To introduce the main techniques, the lecture considers the sequential setting and uses
the following performance indicators:

| Indicator | Meaning |
|---|---|
| Construction time | Time to construct the initial data structure |
| Space | Memory words needed to store the data structure |
| Query time | Time to execute one query |

For points in $\mathbb{R}^D$, assume that $d(x, y)$ can be computed in $O(D)$ time
and that a point is stored in $O(D)$ space.

For very large inputs, distributed or streaming solutions are often necessary. This is
an active research area.

#### Brute Force Baseline

![[Pics/SimSearch1/SimSearch1-12.png]]
*Figure 12 - Brute force solution for $r$-NNS.*

> [!Important] Baseline - Brute Force Solution
> **Construction:** Store points of $P$ in a list.
>
> **Query:** Given $q$, compute $d(q, p)$ for all $p \in P$, return the first
> point $p' \in P$ with $d(q, p') \leq r$ if one exists, and return null otherwise.
>
> If $P \subset \mathbb{R}^D$ and $|P| = n$, the brute force approach requires:
>
> | Cost | Bound |
> |---|---|
> | Construction time | $O(n)$ |
> | Space | $O(Dn)$ |
> | Query time | $O(Dn)$ |
>
> **Reasoning:** Every query compares $q$ against all $n$ points, and each distance
> computation costs $O(D)$.
>
> **Key limitation:** The query time is too high.

### Range Reporting

![[Pics/SimSearch1/SimSearch1-14.png]]
*Figure 14 - Relationship between $r$-NNS and Range Reporting in $\mathbb{R}^D$.*

To solve the $r$-NNS problem more efficiently in $\mathbb{R}^D$ under Euclidean
distance, the lecture uses the **kd-tree**.

- A **kd-tree** is a binary tree that recursively partitions the space into
  rectangular regions.
- A kd-tree solves a slightly different problem called **Range Reporting**.

> [!Important] Definition - Range Reporting (RR)
> **Statement:** Given a set $P \subset \mathbb{R}^D$ of $n$ points, construct a
> data structure that, given a rectangular region $R$, returns all points of
> $P$ contained in $R$.
>
> A rectangular region
>
> $$
> R = [x_{1,1}:x_{1,2}] \times \ldots \times [x_{D,1}:x_{D,2}]
> \subset \mathbb{R}^D
> $$
>
> is the region containing all points $p = (p_1, \ldots, p_D)$ with
> $p_i \in [x_{i,1}:x_{i,2}]$ for every $i \in \{1, \ldots, D\}$.
>
> **Intuition:** Range Reporting asks for points in an axis-aligned rectangle,
> while $r$-NNS asks for a point in a metric ball.

![[Pics/SimSearch1/SimSearch1-15.png]]
*Figure 15 - Range Reporting in $\mathbb{R}^2$: return all points inside rectangle $R$.*

### Range Reporting vs $r$-NNS

![[Pics/SimSearch1/SimSearch1-16.png]]
*Figure 16 - Handwritten comparison between RR and $r$-NNS.*

| Problem | Query | Task |
|---|---|---|
| RR | Rectangle $R$ | Return all points in $R \cap P$ |
| $r$-NNS | Point $q$ and distance $r$ | Return an arbitrary point in $B_r(q) \cap P$, if any |

## kd-Trees

![[Pics/SimSearch1/SimSearch1-17.png]]
*Figure 17 - Introductory kd-tree slide showing spatial partition lines and tree structure.*

### Definition

![[Pics/SimSearch1/SimSearch1-18.png]]
*Figure 18 - Formal definition of a kd-tree in $\mathbb{R}^2$.*

For simplicity, the lecture defines kd-trees for $D = 2$. The definition can be
extended to $D > 2$.

Let $P$ be a set of $n$ points in $\mathbb{R}^2$, and let
$R(P) \subset \mathbb{R}^2$ be a rectangular region containing all points in $P$.

> [!Important] Definition - kd-tree
> **Statement:** A **kd-tree** $T$ for $P$ is a binary tree that defines a
> hierarchical decomposition of $R(P)$ into nested rectangular subregions.
>
> - Each internal node $v$ is associated with a rectangular region denoted
>   $\operatorname{region}(v)$, and represents the subset of points
>   $P_v = P \cap \operatorname{region}(v)$.
> - For the root $r$, $\operatorname{region}(r) = R(P)$ and $P_r = P$.
> - Each external node, or leaf, $v$ is associated with a region containing a
>   single point, denoted $p_v \in P$. Hence $P_v = \{p_v\}$.
>
> **Intuition:** Each node stores a region of the plane. Descending the tree
> means refining that region until each leaf contains one input point.

### Splitting Rule

![[Pics/SimSearch1/SimSearch1-19.png]]
*Figure 19 - kd-tree splitting rule, with handwritten correction showing floor and ceiling split sizes.*

The regions associated with nodes are defined by the following splitting rule.
Each internal node $v$ with $|P_v| \geq 2$ has two children, $u$ and $w$, whose
regions are obtained by splitting $\operatorname{region}(v)$ through a vertical
or horizontal line $\ell_v$, depending on the depth of $v$.

If $v$ is at even depth, $\ell_v$ is vertical at abscissa $x_v$:

$$
\operatorname{region}(u)
= \operatorname{region}(v) \cap \mathbb{R}^2_{x \leq x_v}
$$

$$
\operatorname{region}(w)
= \operatorname{region}(v) \cap \mathbb{R}^2_{x > x_v}
$$

If $v$ is at odd depth, $\ell_v$ is horizontal at ordinate $y_v$:

$$
\operatorname{region}(u)
= \operatorname{region}(v) \cap \mathbb{R}^2_{y \leq y_v}
$$

$$
\operatorname{region}(w)
= \operatorname{region}(v) \cap \mathbb{R}^2_{y > y_v}
$$

The line $\ell_v$ is chosen so that the points in $P_v$ are split into the two
sets $P_u$ and $P_w$ of sizes

$$
\left\lfloor \frac{|P_v|}{2} \right\rfloor
\quad \text{and} \quad
\left\lceil \frac{|P_v|}{2} \right\rceil,
$$

respectively. For convenience, assume no two points have the same abscissa or
ordinate.

![[Pics/SimSearch1/SimSearch1-20.png]]
*Figure 20 - Vertical and horizontal splits used by the kd-tree construction.*

![[Pics/SimSearch1/SimSearch1-21.png]]
*Figure 21 - A node region is determined by the split lines stored at its ancestors.*

A consequence of the definition is that, for every $v \in T$,
$\operatorname{region}(v)$ is defined by the lines stored at the ancestors of
$v$.

### Construction and Storage

![[Pics/SimSearch1/SimSearch1-26.png]]
*Figure 26 - Storage requirements and construction time for kd-trees, with handwritten note that $T$ contains $\leq 2n$ nodes.*

Let $T$ be a kd-tree for a set $P \subset \mathbb{R}^2$ of $n$ points.

> [!Important] Storage and Construction of kd-trees
> **Storage:** A kd-tree $T$ for $P$, with $|P| = n$, can be stored using
> $O(n)$ space. The handwritten note states that $T$ contains $\leq 2n$ nodes.
>
> Specifically:
>
> - Each internal node $v$ stores a representation of $\operatorname{region}(v)$
>   (4 coordinates suffice) and the line $\ell_v$.
> - Each external node $v$ stores the point $p_v$.
>
> **Construction:** Given $P$, $T$ can be constructed in $O(n \log n)$ time.
> The details are skipped in the source.
>
> **Intuition:** The tree is balanced because every split divides the current
> point set into two parts of roughly equal size.

### Range Query Algorithm

![[Pics/SimSearch1/SimSearch1-27.png]]
*Figure 27 - Range query description for a kd-tree.*

Given a kd-tree $T$ and a query rectangle
$R = [x_1, x_2] \times [y_1, y_2]$, the query algorithm starts from the root and
recursively visits all nodes whose regions intersect $R$.

- At a leaf node $v$, return $p_v$ if $p_v \in R$.
- At an internal node $v$, recurse on each child whose associated region
  intersects $R$.
- If $\operatorname{region}(v) \cap R = \emptyset$, none of the children regions
  intersects $R$, so return $\emptyset$.

The recursion may proceed on both subtrees.

![[Pics/SimSearch1/SimSearch1-28.png]]
*Figure 28 - Pseudocode for SearchKdTree.*

> [!Important] Algorithm - SearchKdTree
> **Input:** A node $v$ in the kd-tree, and a rectangle $R$.
>
> **Output:** The set of points $p \in R$ from the subtree of $v$.
>
> ```text
> SearchKdTree(v, R)        // first invocation: v = root
>
> if (v is a leaf) then
>     if (p_v in R) then out <- {p_v}
>     else out <- empty
> else
>     out <- empty
>     Let u, w be the left and right child of v, respectively
>     Let R_u = region(u) intersect R
>     Let R_w = region(w) intersect R
>     if (R_u != empty) then out <- out union SearchKdTree(u, R_u)
>     if (R_w != empty) then out <- out union SearchKdTree(w, R_w)
> return out
> ```
>
> **Reasoning:** A subtree is explored only when its associated region intersects
> the query rectangle. If there is no intersection, no point in that subtree can
> be reported.

### Performance in $\mathbb{R}^2$

![[Pics/SimSearch1/SimSearch1-31.png]]
*Figure 31 - Range Reporting performance theorem for kd-trees in $\mathbb{R}^2$.*

> [!Important] Theorem - Range Reporting with kd-trees in $\mathbb{R}^2$
> **Statement:** The Range Reporting problem for a set $P$ of $n$ points in
> $\mathbb{R}^2$ can be solved using a kd-tree $T$ for $P$ with:
>
> | Quantity | Bound |
> |---|---|
> | Construction time | $O(n \log n)$ |
> | Space | $O(n)$ |
> | Query time | $O(\sqrt{n} + k)$ |
>
> Here $k$ is the number of reported points.

![[Pics/SimSearch1/SimSearch1-32.png]]
*Figure 32 - Handwritten proof setup for the $\mathbb{R}^2$ kd-tree query bound.*

The proof notes that construction time and space are as claimed before. Query time is
proportional to the number of nodes of $T$ visited by SearchKdTree.

Define:

$$
Q_1(R) =
\{v \in T :
\operatorname{region}(v) \cap R \neq \emptyset
\text{ and }
\operatorname{region}(v) \not\subset R
\}
$$

$$
Q_2(R) =
\{v \in T :
\operatorname{region}(v) \cap R \neq \emptyset
\text{ and }
\operatorname{region}(v) \subseteq R
\}
$$

> [!Important] Observation - Visited nodes in SearchKdTree
> SearchKdTree is called only on nodes in
> $Q_1(R) \cup Q_2(R)$, except possibly for the first call on the root of $T$.

![[Pics/SimSearch1/SimSearch1-33.png]]
*Figure 33 - Handwritten completion of the proof of the $O(\sqrt{n} + k)$ query bound.*

Each call of SearchKdTree executes $O(1)$ operations besides the recursive calls.
Therefore the running time of SearchKdTree, i.e. the query time, is:

$$
O(1 + |Q_1(R)| + |Q_2(R)|).
$$

It can be shown that:

$$
|Q_1(R)| = O(\sqrt{n})
$$

and

$$
|Q_2(R)| = O(k).
$$

Hence the running time of SearchKdTree is:

$$
O(\sqrt{n} + k).
$$

## Using kd-Trees for $r$-NNS

![[Pics/SimSearch1/SimSearch1-36.png]]
*Figure 36 - Reduction from $r$-NNS to a kd-tree range query using the smallest enclosing square $R_q$.*

Let $T$ be a kd-tree for a point set $P \subset \mathbb{R}^2$. We can answer an
$r$-NNS query with center $q \in \mathbb{R}^2$ as follows:

1. Let $R_q$ be the smallest square enclosing the ball $B_r(q)$.
2. Compute

   $$
   S = \operatorname{SearchKdTree}(T.\operatorname{root}(), R_q).
   $$

3. Return a point $p \in S \cap B_r(q)$ if one exists, otherwise return null.

![[Pics/SimSearch1/SimSearch1-37.png]]
*Figure 37 - Practical efficiency and theoretical limitation of using kd-trees for $r$-NNS.*

The solution works efficiently from a practical point of view. Let

$$
k_s = |S|
$$

and

$$
k_q = |S \cap B_r(q)|.
$$

The solution requires:

$$
O(\sqrt{n} + k_s)
$$

not:

$$
O(\sqrt{n} + k_q).
$$

In some pathological cases, $k_s >> k_q$. It is unclear how to close this gap
theoretically.

## Generalization to $D$ Dimensions

![[Pics/SimSearch1/SimSearch1-39.png]]
*Figure 39 - Generalization of kd-trees and Range Reporting bounds to $\mathbb{R}^D$.*

The kd-tree approach generalizes to $D$ dimensions:

- The kd-tree is defined in a similar fashion, but at each level the binary
  splits are defined by a distinct coordinate in cycling order:

  $$
  1, 2, \ldots, D, 1, 2, \ldots
  $$

- SearchKdTree remains unchanged.

> [!Important] Theorem - Range Reporting with kd-trees in $\mathbb{R}^D$
> **Statement:** The Range Reporting problem for a set $P$ of $n$ points in
> $\mathbb{R}^D$ can be solved using a kd-tree $T$ for $P$ with:
>
> | Quantity | Bound |
> |---|---|
> | Construction time | $O(Dn \log n)$ |
> | Space | $O(Dn)$ |
> | Query time | $O(Dn^{1 - 1/D} + k)$ |
>
> Here $k$ is the number of reported points.
>
> **Intuition:** The dependence on $D$ becomes problematic when $D$ grows,
> because the exponent $1 - 1/D$ approaches 1.

## Curse of Dimensionality

![[Pics/SimSearch1/SimSearch1-40.png]]
*Figure 40 - Curse of dimensionality: kd-tree query cost approaches linear scanning as $D$ increases.*

> [!Important] Curse of Dimensionality
> **Statement:** The query cost of kd-trees converges to linear scanning time
> when $D$ increases.
>
> There is a strong conjecture that the exact $r$-NNS problem cannot be solved
> in truly sublinear query time when $D$ is large, i.e. with query time
> $O(n^\epsilon)$ for a constant $\epsilon < 1$.
>
> **Intuition:** kd-trees work well in low dimensions, but exact similarity
> search becomes much harder in high-dimensional spaces. This motivates the
> approximate methods introduced in Part 2.

## Final Summary

| Concept | Definition / Formula | Conditions / Notes |
|---|---|---|
| Similarity search | Find objects similar or near to a query object | Requires a distance function and usually a threshold |
| $r$-NNS | Return one point in $B_r(q) \cap P$, or null if none exists | Multiple valid points allowed; return arbitrary one |
| Ball around query | $B_r(q) = \{p \in M : d(p, q) \leq r\}$ | Metric space $(M, d)$ |
| Range Reporting | Return all points of $P$ inside rectangle $R$ | Solved by kd-trees in low dimensions |
| Brute force $r$-NNS | Scan all $p \in P$ and test $d(q,p) \leq r$ | Query time $O(Dn)$ for $P \subset \mathbb{R}^D$ |
| kd-tree | Binary tree recursively partitioning space into rectangular regions | Alternates split coordinates; leaves store points |
| kd-tree storage in $\mathbb{R}^2$ | $O(n)$ | Handwritten note: $T$ contains $\leq 2n$ nodes |
| kd-tree construction in $\mathbb{R}^2$ | $O(n \log n)$ | Details skipped in source |
| SearchKdTree in $\mathbb{R}^2$ | Query time $O(\sqrt{n} + k)$ | $k$ is number of reported points |
| kd-tree in $\mathbb{R}^D$ | Query time $O(Dn^{1 - 1/D} + k)$ | Degrades as $D$ increases |
| kd-tree for $r$-NNS | Query square $R_q$, then filter $S \cap B_r(q)$ | Practical, but bound depends on $k_s = |S|$, not only $k_q$ |
| Curse of dimensionality | Exact high-dimensional $r$-NNS is conjectured not to have truly sublinear query time | Motivates approximate near neighbor search and LSH |
