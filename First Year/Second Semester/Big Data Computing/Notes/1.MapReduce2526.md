## Motivating Scenario & Fault Tolerance

MapReduce was introduced by Google in **2004** to address the growing need to analyze large amounts of data. Supercomputers were unsuitable because:

- Prohibitive cost (millions/billions €)
- Required low-level hardware expertise (fault tolerance, task allocation, data distribution)
- Fast obsolescence
- Extreme performance not needed for typical big data applications

### Mean-Time Between Failures (MTBF)
When we talk about fault-tolerance we mean the ability of a system to continue functioning properly in the event of the failure of some of its components.
Consider a system with $N$ components $C_1, \ldots, C_N$, each failing independently with probability $p$ per unit of time:

$$\Pr(\exists C_i \text{ that fails at time } t) = 1 - (1-p)^N$$

Let $X$ = number of time units before the next failure. $X$ follows a **geometric distribution**:

$$E[X] = \frac{1}{1-(1-p)^N} \xrightarrow{N \to +\infty} 1$$

> [!Important] Observation on Fault Tolerance
> For large $N$, failures become virtually certain at every instant. In big data systems — which comprise many components — **fault tolerance** is an essential requirement, not optional.

## MapReduce Overview

**Main features:**
- Moderate-cost platforms (commodity clusters, cloud)
- Simple programming environment inspired by *functional programming* (map/reduce functions)
- The runtime transparently manages: task allocation, data distribution, fault-tolerance, load balancing
- **Data-centric view**: focus on data transformations

**In this course:**
- MapReduce → **conceptual model** for high-level algorithm design and analysis
- Spark → **programming model** to implement and optimize MapReduce computations

### Platforms

- **On-premises:** clusters of commodity processors
- **Cloud:**
  - *IaaS (Infrastructure as a Service)*: physical/virtual computing infrastructure (e.g., CloudVeneto)
  - *PaaS (Platform as a Service)*: platform with OS and execution environments

### Cluster Architecture & DFS

Racks of 16–64 commodity nodes connected by fast switches (e.g., 10 Gbps Ethernet).

- **Local Main Memories:** process data chunks at individual compute nodes
- **Overall Disk Space:** stores massive inputs with fault-tolerance

**Distributed File System (DFS):**
It allows the system to efficiently distribute the workload across multiple nodes by ensuring that the necessary data is available locally where the tasks are executed, reducing network traffic and speeding up processing times.
- Files divided into *chunks* (e.g., 64 MB)
- Each chunk replicated (2×–3×) on different nodes for fault-tolerance
- Examples: *Google File System* (GFS), *Hadoop Distributed File System* (HDFS)

## MapReduce Computation Model

A MapReduce computation is a **sequence of rounds**.

### Structure of a Round

> [!Important] Structure of a Round
> A round transforms a set of **key-value pairs** into another set of key-value pairs, through:
>
> 1. **Map phase:** for each input pair separately, the map function produces $\geq 0$ **intermediate pairs**
> 2. **Shuffle:** intermediate pairs are grouped by key → for each key $k$, a list $L_k$ of values is created
> 3. **Reduce phase:** for each key $k$ separately, the reduce function is applied to $(k, L_k)$ and produces $\geq 0$ output pairs
>
> The application of the reduce function to a pair $(k, L_k)$ is called a **reducer**.

![[Mapreduce--005.jpg]]

**Distributed execution:**
- The user program forks into a **master process** and several **executor processes**
- The master assigns map/reduce tasks to executors and monitors their status (idle, in-progress, completed)
- Input data: from DFS or master's disk; intermediate data: local memories/disks of executors

![[Mapreduce--007.jpg]]

### Multi-Round & Shared Variables

- Complex computations require **multiple rounds**; typically the input of round $i$ is the output of round $i-1$
- **Shared variables** can be defined, available to all executors, maintaining global information across rounds
![[Mapreduce--008.jpg]]
### Key-Value Pairs: Justification

Keys serve two roles:
- **Addresses** to reach objects (independent of where they reside)
- **Labels** to define groups in reduce phases

The domains of key and value may change from one round to another.

**Practical consideration:** frameworks such as Spark allow managing data without explicit keys. In this case, internal addresses/labels — not visible to the programmer — are used.

### Algorithm Specification (Pseudocode Style)

```
Input:  description of input as set of (key, value) pairs
Output: description of output as set of (key, value) pairs
Round 1:
  Map phase:    description of function applied to each pair
  Reduce phase: description of function applied to each group (key, list-of-values)
Round 2, ..., R: similarly
```

## Performance Analysis

### Key Performance Indicators

> [!Important] Key Performance Indicators (KPI)
>
> - **$R$** (number of rounds): rough estimate of **running time** (assumption: all rounds have approximately the same complexity, dominated by the shuffle)
> - **$M_L$** (local space): **maximum amount of main memory** required by a single invocation of a map or reduce function (maximum over all rounds and all invocations). Indicates the RAM needed at each executor.
> - **$M_A$** (aggregate space): **maximum amount of disk space** occupied by stored data at the beginning/end of a map or reduce phase (maximum over all rounds). Indicates the total disk space in the system.

### Design Goals

> [!Important] Design Goals for MapReduce Algorithms
>
> 1. **Few rounds:** $R = O(1)$ → low communication/synchronization cost
> 2. **Sublinear local space:** $M_L = O(|\text{input}|^\epsilon)$ with $\epsilon < 1$ → low main memory usage
> 3. **Linear aggregate space:** $M_A = O(|\text{input}|)$ → low disk usage (little replication)
> 4. **Low complexity** of each map/reduce function → low computational cost
>
> Goals 1 and 4 aim at **time efficiency**; goals 2 and 3 aim at **space efficiency** and **feasibility** on commodity hardware.
>
> ⚠️ These goals are somewhat **conflicting**: suitable tradeoffs must be sought.

**Key observation:** For every problem solvable sequentially in space $S$, there exists a 1-round MR algorithm with $M_L, M_A \propto S$ (simply assign key 0 to all elements and use the sequential algorithm as reduce function). However, this trivial solution is impractical: requires large RAM, exploits no parallelism.

### Pros and Cons

**Advantages:**
- **Data-centric view:** focus on data transformations
- **Usability:** the programmer is relieved from task allocation, data management, and fault handling
- **Portability/adaptability:** applications run on different platforms
- **Cost:** moderate platforms, cloud support

**Disadvantages:**
- $R$ only coarsely captures running time
- **Curse of the last reducer:** a slow reducer delays the entire round → load must be balanced
- Not suitable for applications requiring extreme performance or tight coupling with the architecture

## Partitioning

**Partitioning** is the main technique to reduce $M_L$:
- Splits the computation into small tasks, each processing a chunk of data
- Maximizes independence among tasks to exploit parallelism
- May increase the number of rounds (rarely increases $M_A$)

### Deterministic Partitioning

Uses a deterministic hash function based on explicit data features (e.g., integer key $i$) to evenly subdivide the pairs.

**Standard technique:** $\ell$ partitions with key = $i \bmod \ell$

**Optimal choice:** $\ell = \sqrt{N}$ → $M_L = O(\sqrt{N})$

> [!Important] Deterministic Partitioning Tradeoff
> With $\ell$ partitions and keys $i \bmod \ell$:
> $$M_L = O\!\left(\frac{N}{\ell} + \ell\right)$$
> Setting $\ell = \sqrt{N}$: $M_L = O(\sqrt{N})$, $M_A = O(N)$, $R$ increases by 1.

### Random Partitioning

Assigns a uniform random key in $[0, \ell)$ to each intermediate pair. Always applicable (requires no explicit keys).

**Analysis:**

Let $m_x$ = # intermediate pairs in Round 1 with key $x$, and $m = \max_x m_x$ (size of largest partition).

$R = 2$

$M_L$:
- Round 1, Map Phase: $O(1)$
- Round 1, Reduce Phase: $O(m)$
- Round 2, Reduce Phase: $O(\ell)$

$$\Rightarrow M_L = O(m + \ell)$$

$M_A = O(N)$ (same argument: $O(N)$ pairs in each round, each $O(1)$ space).

The maximum partition size $m$ is a random variable → probabilistic analysis required.

> [!Important] Theorem: Balanced Random Partitioning
> Fix $\ell = \sqrt{N}$. If keys are assigned independently with uniform distribution in $[0, \sqrt{N})$, then with probability at least $1 - 1/N^5$:
> $$m = O\!\left(\frac{N}{\ell}\right) = O(\sqrt{N})$$
> and therefore $M_L = O(\sqrt{N})$.
>
> **Proof:** Assume $N \geq 16$ (otherwise the theorem is straightforward). Fix an arbitrary $x \in [0, \sqrt{N})$ and let $m_x$ be the number of intermediate pairs that receive key $x$ in Round 1.
>
> For $0 \leq i < N$ define:
> $$Y_i = \begin{cases} 1 & \text{if pair } i \text{ receives key } x \\ 0 & \text{otherwise} \end{cases}$$
> $Y_i$ is a Bernoulli r.v. with $\Pr(Y_i = 1) = \dfrac{1}{\sqrt{N}}$.
>
> $$\Rightarrow m_x = \sum_{i=0}^{N-1} Y_i \sim \mathrm{Binom}\!\left(N,\,\frac{1}{\sqrt{N}}\right), \quad E[m_x] = \sqrt{N}$$
>
> By the **Chernoff bound** (a) with $\delta_1 = 6$:
> $$\Pr(m_x \geq 6\sqrt{N}) \leq 2^{-6\sqrt{N}}$$
>
> Since for $N \geq 16$ we have $\sqrt{N} \geq \log_2 N$:
> $$2^{-6\sqrt{N}} \leq 2^{-6\log_2 N} = \left(\tfrac{1}{2}\right)^{\log_2(N^6)} = \frac{1}{N^6}$$
>
> $$\Rightarrow \Pr(m_x \geq 6\sqrt{N}) \leq \frac{1}{N^6}$$
>
> Define event $E_x =$ "$m_x \geq 6\sqrt{N}$". Then:
> $$\Pr(m \geq 6\sqrt{N}) = \Pr(E_0 \cup E_1 \cup \cdots \cup E_{\sqrt{N}-1})$$
>
> By the **union bound** over all $\sqrt{N}$ partitions:
> $$\Pr(m \geq 6\sqrt{N}) \leq \sqrt{N} \cdot \Pr(E_x) \leq \sqrt{N} \cdot \frac{1}{N^6} \leq \frac{1}{N^5}$$
>
> Therefore:
> $$\Pr(m \leq 6\sqrt{N}) \geq 1 - \frac{1}{N^5}$$
>
> i.e., with very high probability $m \leq 6\sqrt{N}$, so $m = O(\sqrt{N})$. $\square$
>
> **Conclusion:** If $N$ objects are distributed at random among $\ell$ partitions, and $N/\ell$ is sufficiently large, then with high probability no partition receives an excessive number of objects.

**Practical note:** in practice, the number of partitions is fixed as a multiple of the number of available workers, as long as local space is not an issue.

| Type | $M_L$ | Applicability |
|------|-------|---------------|
| Deterministic | $O(N/\ell + \ell)$ | Only when a suitable integer key exists |
| Random | $O(m + \ell)$ → $O(\sqrt{N})$ w.h.p. | Always applicable; requires expected partition size not too small + good PRNG |

## Case Studies

### Word Count

**Problem:** count occurrences of each word across $k$ documents.

**Input:** $\{(D_i\text{.name},\ D_i\text{.words}) : 1 \leq i \leq k\}$

**Output:** $\{(w, c(w)) : w \text{ word},\ c(w) = \#\text{total occurrences}\}$

> [!Example] Word Count — 1 Round
> **Round 1:**
> - *Map phase:* $D_i \to \{(w, c_i(w)) : w \in D_i\}$ (local count per document)
> - *Reduce phase:* $(w, L_w) \to (w,\ \sum_{c_i(w) \in L_w} c_i(w))$
>
> **Analysis** (1 word = $O(1)$ space):
> - $R = 1$
> - $M_L = O(N_{\max} + k)$ where $N_{\max} = \max_i(\#\text{words in }D_i)$, $k = $ \#documents
> - $M_A = O(N)$ where $N = \sum_i N_i$ = total occurrences

![[Mapreduce--006.jpg]]
### Class Count (1 round, naive)

> [!Example] Class Count (1 round, naive)
> **Problem:** given $S$ of $N$ objects with class labels, count objects per class.
> 
> **Input:** $\{(i, (\gamma_i, o_i)) : 0 \leq i < N\}$
> 
> **1 round (no partitioning):**
> - *Map:* $(i, (\gamma_i, o_i)) \to (\gamma_i, 1)$
> - *Reduce:* $(\gamma, L_\gamma) \to (\gamma, |L_\gamma|)$
> 
> **Analysis:** $R=1$, $M_L = O(N)$ in the worst case, $M_A = O(N)$.
> ⚠️ Does not meet the design goal $M_L = O(N^\epsilon)$ with $\epsilon < 1$.


### Class Count (2 rounds, deterministic)

> [!Example] Class Count — 2 rounds, deterministic partitioning ($\ell$ partitions)
>
> **Round 1:**
> - *Map:* $(i, (\gamma_i, o_i)) \to (i \bmod \ell,\ \gamma_i)$
> - *Reduce:* for each $j \in [0, \ell)$: $(j, L_j) \to \{(\gamma, c(j,\gamma)) : \gamma \in L_j\}$
>
> **Round 2:**
> - *Map:* empty
> - *Reduce:* $(\gamma, L_\gamma) \to \left(\gamma,\ \sum_{c(j,\gamma) \in L_\gamma} c(j,\gamma)\right)$
>
> **Analysis with $\ell = \sqrt{N}$:**
> - $R = 2$
> - $M_L = O\!\left(\max\{N/\ell, \ell\}\right) = O(\sqrt{N})$
> - $M_A = O(N)$
>
> ✅ **Meets all design goals.**

![[Mapreduce--009.jpg]]
![[Mapreduce--010.jpg]]
### Class Count (2 rounds, random)

> [!Example] Class Count (2 rounds, random)
> Same algorithm as the deterministic case, but without an integer key available:
> 
> - *Round 1, Map:* $(\gamma_i, o_i) \to (x, \gamma_i)$ with $x \sim \text{Unif}[0, \ell)$ chosen at random
> 
> **Analysis:** $M_L = O(m + \ell) = O(\sqrt{N})$ w.h.p. with $\ell = \sqrt{N}$.

## Probabilistic Tools

### Union Bound

> [!Important] Union Bound
> For a countable set of events $E_1, E_2, \ldots, E_r$:
> $$\Pr\!\left(\bigcup_{i=1}^{r} E_i\right) \leq \sum_{i=1}^{r} \Pr(E_i)$$

### Markov's Inequality

> [!Important] Markov's Inequality
> Let $X$ be a nonnegative random variable. For any $a > 0$:
> $$\Pr(X \geq a) \leq \frac{E[X]}{a}$$

### Chernoff Bound

> [!Important] Chernoff Bound
> Let $X_1, \ldots, X_n$ be i.i.d. Bernoulli random variables with $\Pr(X_i = 1) = p$. Let $X = \sum X_i \sim \text{Binom}(n,p)$, $\mu = np$. For $\delta_1 \geq 6$ and $\delta_2 \in (0,1)$:
>
> **(a)** $\Pr(X \geq \delta_1 \mu) \leq 2^{-\delta_1 \mu}$ ← right tail
>
> **(b)** $\Pr(X \leq (1-\delta_2)\mu) \leq 2^{-\delta_2^2 \mu/2}$ ← left tail

## Exercises

1. **(Arithmetic mean)** Design a 2-round MR algorithm to compute the mean of $N$ integers with $M_L = O(\sqrt{N})$, $M_A = O(N)$. How to reduce $M_L$ to $O(N^{1/4})$? Generalize to $M_L = O(M)$ for any $M < \sqrt{N}$.

2. **(Distinct elements)** Design an $O(1)$-round MR algorithm to count distinct elements of $S$ with $M_L = O(\sqrt{N})$, $M_A = O(N)$.

3. **(Top-K per sensor)** Given $P$ of temperature measurements, return at least $K$ measurements per sensor (or all of them if $< K$). $o(N)$ local space, $O(N)$ aggregate space.

4. **(Matrix-vector product)** Design an $O(1)$-round MR algorithm for $W = A \cdot V$, where $A$ is $m \times n$ with $m \leq \sqrt{n}$, using $o(n)$ local space and $O(mn)$ aggregate space.

5. **(Theory — Written Exam 22/23)** A MapReduce algorithm receives in input $N$ web documents, each represented by a pair (url, $D$), where $D$ is the document and url is its address. Assume each pair occupies $O(1)$ space. Describe a map phase that splits the input into $\sqrt{N}$ small partitions, and state the theoretical guarantees of your partitioning.
