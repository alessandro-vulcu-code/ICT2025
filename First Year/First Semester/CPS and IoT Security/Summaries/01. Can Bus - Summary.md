### 2.1 The In-Vehicle Network Ecosystem

### 2.2 The CAN Bus Protocol
The Controller Area Network (CAN) is a robust, bus-based vehicle network standard originally developed by Bosch in 1986 to facilitate communication between microcontrollers and devices without a host computer. It is officially standardized as ISO 11898.
📸 [INSERIRE IMMAGINE: High-level CAN Bus architecture showing multiple ECUs connected to a shared bus with 120 Ohm termination resistors.]

The protocol was designed with four key advantages in mind:
* **Robustness:** CAN was designed to be highly reliable and durable, with a primary objective of reducing errors in safety-critical applications. Its reliability is ensured through mechanisms like bit stuffing, bit monitoring, frame check, ACK, and CRC checks.
* **Low cost:** A primary goal of CAN was to reduce the amount of wiring required in a vehicle, which in turn reduces weight, complexity, and cost compared to older point-to-point communication methods.
* **Flexibility:** As a message-based protocol, nodes (ECUs) can be added to or removed from the network without requiring software or hardware updates to the other nodes.
* **Efficiency:** The protocol uses a message prioritization system where messages with higher priority (determined by a lower message ID) gain preferential access to the bus, ensuring that critical data is transmitted without delay.

### 2.3 CAN Communication Principles
CAN bus uses differential wired-AND signals for communication, which involves two physical lines: CAN-H (high) and CAN-L (low). This differential signaling provides high resistance to electromagnetic interference.
📸 [INSERIRE IMMAGINE: Diagram of differential signaling, showing a transmitter sending non-inverted and inverted signals to a receiver.]

The bus has two logical states, defined by the voltage difference between the two lines:
* **Dominant state:** This corresponds to a logical 0 bit. In this state, there is a voltage differential where CAN-H > CAN-L. The dominant state will always override a recessive state if both are transmitted simultaneously.
* **Recessive state:** This corresponds to a logical 1 bit. In this state, there is no significant voltage differential between the lines (both are typically around 2.5V).

### 2.4 CAN Frame Structure
The standard CAN frame is composed of 8 primary message fields, each serving a distinct purpose in the communication process.
📸 [INSERIRE IMMAGINE: Structure of a standard CAN frame, showing the sequence and bit-length of the SoF, ID, RTR, Control, Data, CRC, ACK, and EoF fields.]

1.  **Start of Frame (SoF):** A single dominant 0 bit that signals the beginning of a message transmission, allowing other nodes to synchronize.
2.  **ID:** The frame identifier. This field does not identify the sender but rather determines the message's priority. A lower numerical ID corresponds to a higher priority on the bus.
3.  **Remote Transmission Request (RTR):** A single bit that indicates whether the frame is a data frame (transmitting data) or a remote frame (requesting data from another node).
4.  **Control:** A 6-bit field that includes the Identifier Extension Bit (IEB) and the 4-bit Data Length Code (DLC). The DLC specifies the size of the data payload, which can range from 0 to 8 bytes.
5.  **Data:** The message payload itself, containing the actual information being transmitted between ECUs.
6.  **CRC (Cyclic Redundancy Check):** A 16-bit field used for error detection to ensure the integrity of the transmitted data.
7.  **ACK (Acknowledge):** A 2-bit field used by receiving nodes to confirm that they have received the frame without errors.
8.  **End of Frame (EoF):** A sequence of 7 recessive bits that marks the end of the CAN frame.

### 2.5 Error Handling and Fault Confinement
The CAN protocol includes a sophisticated, built-in mechanism for error detection and fault confinement to ensure network stability. Each node maintains two error counters: the Transmit Error Counter (TEC) and the Receive Error Counter (REC). Based on the values of these counters, a node can be in one of three states:
* **Error Active:** The default, fully functional state. A node remains in this state as long as both its TEC and REC are less than or equal to 127.
* **Error Passive:** A node enters this state if either its TEC or REC exceeds 127. In this state, the node can still participate in network communication but can only transmit passive error flags (composed of recessive bits), which do not disrupt other communications.
* **Bus Off:** If a node's TEC exceeds 255, it enters the Bus Off state. In this state, the node is completely disconnected from the bus and ceases all transmission and reception.
📸 [INSERIRE IMMAGINE: State transition diagram for CAN error handling, showing the paths between Error Active, Error Passive, and Bus Off states based on TEC/REC values.]

**Limp home mode** is a reduced-functionality state that an ECU enters when it goes into Bus Off mode. This allows the vehicle to operate with predefined parameters so the driver can reach a safe location.
📸 [INSERIRE IMMAGINE: Diagram of a Passive Error Flag from CAN node 1 triggering Active Error Flags from other nodes on the bus.]

Bit stuffing is a key synchronization mechanism. After five consecutive bits of the same polarity are transmitted, the sender automatically inserts a bit of the opposite polarity. This ensures regular signal transitions.

### 2.6 Core Attack Vectors and Models
An attacker's ability to manipulate the CAN bus depends on the level of control they have over a compromised ECU:
* **Weakly Compromised ECU:** The attacker can only stop or suspend the legitimate message transmissions originating from this specific ECU.
* **Strongly Compromised ECU:** The attacker has full control and can inject fabricated messages onto the bus with arbitrary IDs, data, and timing.

These capabilities enable several distinct types of attacks:
* **Fabrication Attack:** A strong attacker injects messages with a forged ID to cause unintended behavior.
📸 [INSERIRE IMMAGINE: Diagram of a Fabrication Attack, showing a malicious ECU A flooding the bus with messages to override legitimate traffic.]
* **Suspension Attack:** A weak attacker stops a compromised ECU from transmitting, preventing critical information from propagating.
📸 [INSERIRE IMMAGINE: Diagram of a Suspension Attack, showing a weakly compromised ECU B being silenced, preventing its data from reaching other ECUs.]
* **Masquerade Attack:** A combination where an attacker silences a weakly compromised ECU and then transmits malicious messages using that silenced ECU's ID.
📸 [INSERIRE IMMAGINE: Diagram of a Masquerade Attack, where a strong ECU A spoofs the messages of a silenced, weak ECU B.]
* **Bus-Off Attack:** A powerful DoS attack that exploits the protocol's error-handling mechanism to force healthy ECUs into the Bus Off state.
* **WeepingCAN:** A more advanced and stealthier variant of the Bus-Off attack designed to evade common detection signatures.

## 3.0 ⚙️ Logic of Formulas: Quantifying the Bus-Off Attack
Success requires an adversary to mathematically model and overcome the network's inherent non-determinism, primarily its jitter.

### 3.1 Predicting Victim Transmission Time
$$t_{n+1}^{vic} = t_n^{adv} + T - D + J^*$$
**Concept:** This formula is used by the attacker to calculate the expected arrival time of the victim's next periodic message.
* $t_{n+1}^{vic}$: Predicted time of the victim's next transmission.
* $t_n^{adv}$: Timestamp when the attacker's node received the current message.
* $T$: Expected period of the victim's messages.
* $D$: Transmission delay.
* $J^*$: Network jitter (variation in message timing).

### 3.2 Calculating Required Bus Holding Time
$$t_{fab} < \min(t_{n+1}^{vic})$$
$$t_{fab} + H > \max(t_{n+1}^{vic})$$
$$H = \kappa * F^* > \max(J^*) - \min(J^*)$$
**Concept:** These constraints define the precise timing window to ensure the attacker's fabricated transmission will overlap with the victim's transmission, regardless of jitter. This creates a "trap" for the victim's message.

### 3.3 Determining the Number of Fabricated Messages ($\kappa$)
$$\kappa = \lceil (\max(J^*) - \min(J^*)) / F^* \rceil$$
**Concept:** This formula calculates $\kappa$, the minimum number of fabricated messages the attacker must inject back-to-back to occupy the bus for the required holding time $H$, minimizing the risk of detection.

### 4.1 Vehicle Network Architecture and Access
A modern vehicle's network is layered, with external interfaces (Cellular, Wi-Fi, Bluetooth, OBD-II) providing entry points. The internal architecture of an individual ECU comprises three key components:
1.  **Microcontroller:** Runs the application software and makes decisions.

2.  **CAN Controller:** Handles the data link layer and serializes/deserializes messages.
3.  **CAN Transceiver:** Physical layer interface that converts digital logic levels into differential voltage levels.

### 4.2 Data Flow and Bus Arbitration
CAN arbitration is priority-based (lower ID wins) and non-preemptive (transmissions cannot be interrupted).
This process works because a dominant (0) bit physically overrides a recessive (1) bit. When multiple nodes start transmitting simultaneously, they monitor the bus bit by bit; as soon as a node detects a dominant bit while it tried to send a recessive one, it drops out.

### 4.3 Reverse Engineering Workflow for Project Development
Two common practical strategies for the 'black box' problem:
* **Method 1: Replay and Isolate:** Effective for identifying discrete commands (e.g., unlocking a door) by systematically replaying halves of a captured trace.

### 4.4 The Bus-Off Attack: A Step-by-Step Mechanical Breakdown
To succeed, the adversary must satisfy three conditions: Same ID (C1), Simultaneous Transmission (C2), and Dominant Bit Collision (C3).

* **Phase 1 (Error-Active to Error-Passive):** Collision causes the victim to detect a Bit Error, increasing its TEC by 8. The cycle repeats until the victim enters Error-Passive state (>127).

* **Phase 2 (Error-Passive to Bus-Off):** Victim transmits passive error flags which don't disrupt the bus. The attacker's frame completes successfully, allowing the attacker's TEC to recover while the victim's TEC continues to climb past 255.

### 4.5 WeepingCAN: Evolving for Stealth
WeepingCAN evades IDS detection by:
1.  **Disabled Retransmission:** Prevents a rapid sequence of error frames (Signature F1).
2.  **Recessive Bit Errors:** Forces the error on the attacker's node so the victim's message eventually transmits normally, appearing as a natural glitch (Signature F2).
3.  **Randomized Bit Positions:** Makes the attack pattern less uniform and harder to fingerprint.
