## Study Notes

### C++ Types

#### Fundamental Types

**Fundamental types** are built into C++. They can be used without any additional declaration. Examples include `int` and `bool`.

Fundamental types give C++ its basic vocabulary for values: logical values, characters, integers, floating-point numbers, and the special type `void`.

#### User-Defined Types

**User-defined types** are introduced by the programmer or by a library header. `std::vector` is an example from the C++ standard library. It is not a fundamental type, because it must be provided by including the proper library declaration.

This distinction matters because C++ programs are built by combining the language's fundamental types with abstractions defined by libraries and user code.

### Fundamental Type Details

#### Boolean

`bool` represents one logical value: `true` or `false`. It is used for conditions and for the result of logical operations.

```cpp
bool b1 {1 = 0};
```

This source example is malformed C++. Assignment with `=` cannot appear between two integer literals. The likely intended expression is `bool b1 {1 == 0};`, which initializes `b1` to `false`. For an oral exam, the key point is the difference between **assignment** (`=`) and **comparison** (`==`).

#### Character Types

C++ provides several character-related types: `char`, `signed char`, `unsigned char`, and `wchar_t`. A `char` is almost always 8 bits, while 7 bits are enough to represent ASCII characters.

Plain `char` can be signed or unsigned depending on the implementation. This is **implementation-defined behavior**, so it may differ across Windows and Linux, 32-bit and 64-bit systems, ARM and x86, or different compilers. If signedness matters, use `signed char` or `unsigned char` explicitly.

Character literals use **single quotes**, for example `'a'` and `'0'`. Special characters use the escape character `\`, for example `'\n'`. The ASCII value can also be written in hexadecimal with `'\x'` followed by the number.

```cpp
char c1 = 'a';
char c2 = '\x61';
char c3 = 97;
std::cout << c1 << std::endl; // print a
std::cout << c2 << std::endl; // print a
std::cout << c3 << std::endl; // print a
```

On an ASCII-compatible system, all three variables print `a`: the literal `'a'`, the hexadecimal code `'\x61'`, and the decimal code `97` represent the same character value. The important idea is that characters are stored as numeric codes, but literal notation is usually clearer than raw numbers.

#### Integers, Floating Point, and void

**Integer types** include `int`, `signed int`, `unsigned int`, `short int`, `long int`, and `long long int`. Signed integer types represent negative and positive values. Unsigned integer types represent only non-negative values.

**Floating-point types** include `float`, `double`, and `long double`. They provide different precision levels: single precision, double precision, and extended precision. Their exact precision is implementation-defined.

`void` has two main uses:

- It indicates that a function does not return a value.
- In `void*`, it represents a pointer to an object whose exact type is unknown at that point.

### Sizes

#### Implementation-Defined Sizes

The size of fundamental types is **implementation-defined**. The C++ standard leaves exact sizes to the implementation. For one compiler and platform, the sizes are well-defined, but portable code must not assume the same sizes everywhere.

```text
Language != what the compiler implements
```

This slide warning means that the C++ language standard and a specific compiler implementation are not identical. A compiler must respect the standard, but the standard intentionally leaves some properties, such as many type sizes, to the implementation.

`sizeof` returns a size measured in units of `char`, so `sizeof(char)` is always `1`. The standard guarantees ordering relationships such as:

```text
1 == sizeof(char) <= sizeof(short) <= sizeof(int) <= sizeof(long) <= sizeof(long long)
sizeof(float) <= sizeof(double) <= sizeof(long double)
```

These are relative guarantees, not exact byte counts. For example, the standard does not require `int` to be exactly 32 bits.

#### Portable Size Types

The `<cstdint>` header defines integer types with precise or size-related properties, such as `int16_t`, `uint32_t`, and `uint_fast32_t`.

Exact-width types such as `int16_t` exist only when the implementation supports exactly that width. `uint_fast32_t` is often more portable because it asks for a fast unsigned integer type with at least 32 bits.

The `<cstddef>` header defines `size_t`, the unsigned type able to hold the size in bytes of any object. `sizeof` returns a value of type `size_t`.

### Declarations

#### Declarations and Definitions

A **declaration** introduces a name with a type into a program. A name is a sequence of characters, starting with a letter, that identifies an entity.

Use naming conventions consistently. The source mentions `camelCase` and `snake_case`, and says that course code will use camelCase for classes and functions, with a capital letter for class names, and snake_case for variables.

The source also references this C++ style guide:

```text
https://gist.github.com/lefticus/10191322#c-coding-standards-part-1-style
```

A **definition** gives the program all information needed to use the entity. For an object, this means storage. For a function, this means the function body. For a class, this means fields and methods.

C++ requires **one and only one definition** for each name that needs a definition in a program. This is the practical idea behind the **One Definition Rule**.

#### Declaration Structure

A declaration can contain:

- an optional prefix such as `static` or `virtual`;
- a base type;
- a declarator, which contains the name and optional operators;
- an optional suffix such as `const` or `noexcept`;
- an optional initializer or function body.

```cpp
static const char* universities[] {"Padova", "Venezia"};
```

This declares `universities` as a static array of pointers to constant characters. The base type cannot be omitted. In this declaration, `*` and `[]` are **declarator operators**.

```cpp
int a_number {10};
const char* str_c {"example of declaration"};
std::vector<double> double_vec {0.1, 0.4, 0.5};
```

`a_number` is an `int`, `str_c` is a pointer to constant `char`, and `double_vec` is a `std::vector<double>` initialized with three values.

#### Declarator Operators

Declarator operators describe how the declared name relates to the base type.

| Declarator operator | Meaning |
| --- | --- |
| prefix `*` | pointer |
| prefix `*const` | constant pointer |
| prefix `*volatile` | volatile pointer |
| prefix `&` | lvalue reference |
| prefix `&&` | rvalue reference |
| prefix `auto` | function using suffix return type |
| postfix `[]` | array |
| postfix `()` | function |
| postfix `->` | return type from function |

The source cites: Stroustrup, Bjarne. *The C++ Programming Language*. Pearson Education, 2013, page 154.

Prefix and postfix matter because **postfix declarator operators bind more tightly** than prefix operators.

```cpp
char* universities[];
char (*universities)[];
```

The first declaration is an array of pointers to `char`. The second declaration is a pointer to an array of `char`. Parentheses change the declaration structure. Spacing can make declarations easier to read, for example `char* universities[]`, but spacing does not change the type.

### Scope

**Scope** defines where a name can be used. It is fundamental for C++ resource management because automatic objects are destroyed when their scope ends.

#### Kinds of Scope

A **local scope** is introduced inside a function or block. A local name is valid from its declaration to the end of the block.

```cpp
f()
{
    Block: from { to }
    int a {10};
    std::cout << a << std::endl;
}
// a does not exist here

Class
Member name if defined in class `but` outside functions
The scope extends to the class block (from { after the declaration to the end })
```

This source block mixes code and slide text, so it is not valid C++. The likely intended meaning is that `a` exists only inside the function block. The class-scope note says that a class member declared in a class, but outside member functions, is in class scope and remains visible inside the class body.

Other scopes in the lesson are:

- **Class scope**: a member name defined in a class and outside member functions.
- **Namespace scope**: a namespace member name defined in a namespace, outside functions, enums, classes, and other local contexts.
- **Global scope**: a name defined outside functions, enums, classes, and namespaces.
- **Statement scope**: a name declared in the control part of `for`, `while`, `if`, or `switch`.

Namespace-scope names are visible from their declaration to the end of the namespace. Global names are visible from their declaration to the end of the file and can be accessed from other files through external linkage.

```cpp
for(int index = 0; index < 10; ++index)
{
    Scope of index
    std::cout << index << std::endl;
}
// index does not exist here
```

This block also contains slide text. `index` is declared in the `for` statement and exists only inside that statement. The line `Scope of index` is not valid C++; it labels the region where the name is visible.

```cpp
int global_var {10}; // global index

namespace Example {
int namespace_scope_var {5}; // namespace scope

class ExampleClass {
    int class_scope_var;
    void f() {
        int local_scope_var {2};
        for (int statement_scope_idx = 0;
             statement_scope_idx < local_scope;
             ++statement_scope_idx) {
            std::cout << statement_scope_idx;
        }
    }
} // end of class ExampleClass scope
} // end of namespace Example scope
```

This example shows nested global, namespace, class, local, and statement scopes. The condition uses `local_scope`, which is not declared in the snippet; it is likely a transcription error for a real loop bound. The scoping idea remains clear: each declaration is visible only in its own allowed region.

#### Hiding and Shadowing

**Hiding**, also called **shadowing**, happens when a nested scope declares a name already used by an outer scope. C++ permits this, but the lesson recommends minimizing or avoiding it because it makes name lookup harder.

```cpp
int index = 10; // global x

void f()
{
    char index = 'a'; // local index 1
    std::cout << index << std::endl;
    for(int index = 0; index < 10; ++index)
    {
        // statement index
        std::cout << index << std::endl;
    }

    {
        double index = 0.2; // local index 2 hides 1
        std::cout << index << std::endl;
    }
    index = 'b'; // assign to local index 1
}
```

The global `index` is hidden by the local `char index`. The loop introduces another `index`, visible only inside the loop. The nested block introduces a `double index`, visible only inside that block. After that block ends, `index = 'b';` refers again to the local `char index`.

### Initialization

#### Initialization Forms

C++ supports several initialization syntaxes.

```text
T a1 {v}; -> Introduced in C++11
- Does not allow narrowing
  int a1 {0.2}; //compilation error
- Strongly recommended except with auto
- {} indicates initialization with default value
(if present)

T a2 = {v};

T a3 = v;

T a4(v);
```

Brace initialization, `T a1 {v};`, was introduced in C++11 and is strongly recommended in many ordinary declarations because it prevents **narrowing conversions**. For example, `int a1 {0.2};` is a compilation error because converting `0.2` to `int` would lose information.

Empty braces, as in `T a {};`, initialize with the default value when one exists. The course warning says to avoid combining this style carelessly with `auto`.

#### auto Type Specifier

`auto` makes the compiler infer the variable type from its initializer.

```cpp
int a1 = 2292;
auto a2 = 2292; // a2 is int
```

Here `a2` is deduced as `int`. `auto` is useful when the explicit type is long or noisy.

```cpp
std::vector<T>::iterator a1 = vec.begin();
auto a1 = vec.begin();
```

Both declarations express the same intended iterator type, but the `auto` version is shorter. In real code the same variable name could not be declared twice in the same scope; the slide is comparing two alternatives.

The lesson warns not to use `{}` initialization with `auto`, because it can deduce `std::initializer_list<T>` instead of the type expected from one value. Use `auto` mainly in small scopes, where the initializer is close and the deduced type is easy to understand.

#### Consistent Initialization

If a name is declared and not initialized, the behavior can be complex and hard to debug.

```cpp
int globalVariable; // means globalVariable{}; -> 0
Valid for static, global, namespace names

void f()
{
    int localVariable; // no well-defined value!
}
```

The line `Valid for static, global, namespace names` is slide text, not valid C++. Static, global, and namespace-scope objects are zero-initialized. A local fundamental variable such as `int localVariable;` has an indeterminate value until it is initialized or assigned. This also applies to local variables and heap objects unless they are user-defined types with a default constructor that initializes them.

### Objects

#### C++ Objects

A C++ **object** is a contiguous region of storage in memory.

In the lesson, an object:

1. Has **identity**, meaning the program has a name, pointer, or reference to it.
2. Is described as not movable in the sense that the storage location itself is not moved by the program.
3. Is referred to by an **lvalue**.

The second point needs exam-level precision. C++ move operations can transfer resources from one object to another, but the original object still remains alive at its original storage location. It may be left in a valid but unspecified state.

#### lvalues and rvalues

| Expression category | Has identity | Is movable |
| --- | --- | --- |
| lvalue | Yes | No |
| rvalue | It depends | Yes |

An **lvalue** has identity and usually names an object that persists beyond one expression. An **rvalue** is movable and may or may not have identity. Temporary values returned by functions are common rvalues.

```cpp
std::vector<int> vec1 {1, 2, 3};
auto vec2 = someFunction(vec1);
lvalue rvalue
auto vec3 = vec1;
lvalue
```

The labels `lvalue rvalue` and `lvalue` are slide annotations, not valid C++. `vec1` is an lvalue because it is named. If `someFunction(vec1)` returns by value, that returned temporary is an rvalue used to initialize `vec2`. `auto vec3 = vec1;` initializes `vec3` from an lvalue, normally by copying unless move semantics or compiler optimizations apply.

#### Object Lifetime

An object's valid lifetime goes from the end of its constructor to the beginning of its destructor.

Main lifetime categories:

- **Automatic objects**: live from explicit initialization until they go out of scope.
- **Static objects**: live until the program terminates.
- **Free-store objects**: have lifetime explicitly controlled with `new` and `delete`.
- **`thread_local` objects**: are created within a thread and destroyed with that thread.
- **Temporary objects**: are used in specific cases and are generally destroyed at the end of the full expression that uses them.

```cpp
std::cout << std::string("tmp").size() << std::endl;
```

`std::string("tmp")` creates a temporary `std::string` object. The temporary lives long enough for `.size()` to be called, then it is destroyed at the end of the full expression. This is another example of an rvalue.

### Type Aliases

A **type alias** is a synonym for an existing type. It can be used as an alternative name for that type.

```cpp
using viter = std::vector<int>::iterator;
typedef std::vector<int>::iterator viter;

std::vector<int> vec = {1,2,3};
std::vector<int>::iterator a = vec.begin();
viter b = a;
```

Both `using` and `typedef` define `viter` as an alias for `std::vector<int>::iterator`. The variable `a` uses the full iterator type, while `b` uses the alias. Modern C++ generally prefers `using` because it is easier to read and works better with alias templates.

### Const and constexpr

`const` declares that an object cannot be modified through that name after initialization. A `const` object must be initialized when declared, except for class member variables, which can be initialized by constructors or in-class member initializers.

Function arguments can be declared `const` when the function only reads from them and must not modify them through that parameter.

The source writes `const exp`, but the C++ keyword is **`constexpr`**. `constexpr` declares that an expression or object can be evaluated at compile time when its inputs are known at compile time. Constant expressions are based on known values such as integers, floating-point values, enums, operators, and other constant expressions.

## Final Summary

This lesson introduces the vocabulary needed to read and explain basic C++ programs. **Types** describe what values mean, while **declarations** introduce names and **definitions** provide usable program entities. Fundamental type sizes are implementation-defined, so portable code should rely on standard guarantees and headers such as `<cstdint>` and `<cstddef>`.

**Scope** determines where names can be used and when automatic objects are destroyed. **Initialization** should be explicit and consistent, with brace initialization preferred in many cases because it prevents narrowing. `auto` is useful when the initializer makes the deduced type clear. Objects, lifetimes, lvalues, rvalues, aliases, `const`, and `constexpr` form the base for later topics such as references, classes, constructors, move semantics, and resource management.
