## Study Notes

This lesson follows **[c++pl] Chapter 18** and explains how C++ operators can be overloaded for user-defined types.

### Operator Overloading

#### Basic Idea

C++ lets a programmer redefine operators for a user-defined type. This makes expressions involving that type more natural, as long as the overloaded operators preserve clear and expected semantics.

```cpp
class Complex { // very simplified complex

    double re, im;

public:
    Complex(double r, double i) :re{r}, im{i} { }
    Complex operator+(const Complex&);
    Complex operator*(const Complex&);
};

The name of an operator is "operator" followed by the symbol a * b = a.operator*(b)

// so that you can write
Complex c = Complex{2, 3} + Complex{5, 6};
Complex d = c * Complex{0, 1};
```

The explanatory line inside the block is slide text. The C++ idea is that `a * b` can call `a.operator*(b)` when `operator*` is a member function. This allows `Complex` objects to use `+` and `*` with mathematical-looking syntax.

#### Operators That Can and Cannot Be Overloaded

Many operators can be overloaded, including arithmetic operators, comparison operators, assignment-like operators, shift operators, logical operators, increment/decrement, `[]`, `()`, `new`, `delete`, and their array forms.

The source references Stroustrup, *The C++ Programming Language*, Pearson Education, 2013, page 529.

It is not possible to define entirely new operator symbols. It is also not possible to overload:

- `::` scope resolution;
- `.` member selection;
- `.*` member selection through pointer-to-member;
- `sizeof`;
- `alignof`;
- `typeid`;
- the ternary conditional operator `?:`.

### Binary and Unary Operators

A **binary operator** has two arguments. It can be overloaded as:

- a non-static member: `aa.operator@(bb)`;
- a non-member function: `operator@(aa, bb)`.

A **unary operator** has one argument, in prefix or postfix form. It can be overloaded as:

- a non-static member: `aa.operator@()`;
- a non-member function: `operator@(aa)`.

Non-member operators are necessary when the left-hand operand is not under our control, such as a built-in type or a user-defined type from another library.

### Overloading Rules

Every operator that should be supported must be overloaded explicitly. The compiler does not infer `operator+=()` from `operator+()` and `operator=()`.

Normal argument-passing rules apply:

- pass built-in types by value;
- pass user-defined types by const lvalue reference when copying should be avoided.

For non-static member operators, it is common to return `*this` by reference, with return type `X&`, when the operator modifies the current object and should support chaining.

### Output Operator

`operator<<` is usually overloaded to support output streaming with `std::cout` or other streams.

For built-in types, `<<` is already overloaded in the standard stream library. For user-defined types, it is normally overloaded as a **non-member function**, because the first operand is an `std::ostream`, and we cannot add members to `std::ostream`.

If the output operator needs private data from the user-defined type, there are two common options:

- call a public member function;
- declare the non-member operator as a `friend`.

#### Calling a Member Function

```cpp
std::ostream& operator<< (std::ostream& out, const Y& y)
{
    return y.someFunction(out);
}

class Y
{
private:
    int j;
public:
    std::ostream& someFunction(std::ostream& out)
    {
        out << j;
        return out;
    }
}
```

The class is missing a final semicolon. The non-member `operator<<` delegates to a public member function, so it does not need direct access to private member `j`. Returning `std::ostream&` enables chained output such as `std::cout << a << b`.

#### Using friend

```cpp
friend keyword

class Y
{
private:
    int j;
    friend std::ostream& operator<<
        (std::ostream& out, const Y& y);

public:
    ...
}    j is private in Y!

std::ostream& operator<<(std::ostream& out, const Y& y)
{
    out << y.j;    the overloaded operator is defined as non-
    member in the innermost enclosing scope
    (e.g., the namespace for a class)
}
```

This block mixes code and slide text. `friend` allows the non-member `operator<<` to access `y.j` even though `j` is private. The operator itself should still be defined as a non-member in the innermost enclosing namespace.

`friend` is powerful and must be used carefully because it can weaken encapsulation.

### Special Operators

#### Subscript and Call Operators

`operator[]` is the **subscript operator**. It provides subscript access for user-defined types, similar to how `std::vector<T>` supports element access with `[]`.

`operator()` is the **function call operator**. It is used to create **function objects**, also called **functors**: objects that can be called like functions.

#### Functors

```cpp
class CalculateAverageOfPowers {
public:
    CalculateAverageOfPowers(float p) :
        acc(0), n(0), p(p) {}
    void operator() (float x) {
        acc += pow(x, p); n++;
    }
    float getAverage() const { return acc / n; }

private:
    float acc; int n; float p;
};

we can call
CalculateAverageOfPowers functor{1};
functor(10); // this is a function call using the operator
// () on the object!
```

The source tagged this as Java, but it is C++. The class stores state: accumulated value `acc`, count `n`, and exponent `p`. Calling `functor(10)` invokes `operator()(10)`, updates the state, and makes the object behave like a function with memory.

#### Functors with std::for_each

Functors are useful with algorithms such as `std::for_each`.

```cpp
CalculateAverageOfPowers avg{2};
std::vector<float> dataA {0.1, 0.2, 10};
std::vector<float> dataB {1, 2, 3};
std::vector<float> dataC {0.5, 8, 99};

avg = std::for_each(dataA.begin(), dataA.end(), avg);
avg = std::for_each(dataB.begin(), dataB.end(), avg);
avg = std::for_each(dataC.begin(), dataC.end(), avg);
```

`std::for_each` calls `avg` for each element of each vector. Because `avg` stores `acc` and `n`, it maintains state across calls and across the three uses of `std::for_each`.

```cpp
CalculateAverageOfPowers avg{2};
std::vector<float> dataA {0.1, 0.2, 10};

avg = std::for_each(dataA.begin(), dataA.end(), avg);

1. Initialize avg: it will have p = 2 as exponent for the pow operation, n = 0, acc = 0
2. Call the overloaded operator () for avg on the first element of dataA
   - acc += pow(0.1, 2) -> acc = 0.01
   - n++ -> n = 1
3. Call the overloaded operator () for avg on the second element of dataA
   - acc += pow(0.2, 2) -> acc = 0.05
   - n++ -> n = 2
4. Call the overloaded operator () for avg on the third element of dataA
   - acc += pow(10, 2) -> acc = 100.05
   - n++ -> n = 3
5. What if we call getAverage() now?
```

The source tagged this as Python, but it is C++ plus slide explanation. After processing `dataA`, `acc` is `100.05` and `n` is `3`, so `getAverage()` returns `100.05 / 3`, approximately `33.35`.

## Final Summary

Operator overloading lets user-defined types integrate with C++ expression syntax. Operators must be overloaded explicitly and should preserve intuitive meaning. Binary and unary operators can be implemented as members or non-members; non-members are required when the left operand is not under the class author's control.

`operator<<` is usually a non-member returning `std::ostream&`, often implemented through a public member function or, when necessary, a `friend`. Special operators such as `operator[]` and `operator()` enable container-like access and callable objects. Functors are objects with state that behave like functions, which makes them useful with algorithms such as `std::for_each`.
