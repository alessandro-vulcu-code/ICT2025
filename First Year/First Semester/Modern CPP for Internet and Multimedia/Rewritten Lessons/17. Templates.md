## Study Notes

This lesson follows **[c++pl] Chapter 23** and section **28.6**. Templates are the main C++ mechanism for generic programming and compile-time polymorphism.

### Templates and Generic Programming

Templates represent general concepts that can apply to different types. For example, a vector can hold integers, strings, or user-defined objects. In a template, the type is a **parameter**, and type checking happens at compile time.

Templates are widely used in the standard library. They provide **compile-time polymorphism**, in contrast with runtime polymorphism based on base classes and virtual functions.

#### Template Example

```cpp
template<typename C>
class MyString {
public:
    String();
    explicit String(const C*) { // impl }
    String(const String&) { // impl }
    String operator=(const String&) { // impl }
    // ...
    C& operator[](int n) {
        return ptr[n];
    }
    String& operator+=(C c) { // impl }
    // ...
private:
    static const int short_max = 15;
    int sz;
    C* ptr; // ptr points to sz Cs
};
```

This declares a class template. `C` is a type parameter and is used inside the template as if it were an ordinary type name. The source likely intended constructors named `MyString`, not `String`; the slide preserves the original wording, but in valid C++ constructor names must match the class name.

#### Template Parameters and Concepts

```cpp
template<typename C>
class MyString {
public:
...
```

`template<typename C>` is similar to the mathematical idea "for all `C`". In older C++, there was no direct language mechanism to express constraints such as "for all `C` such that `C` supports operation X". C++20 introduced **concepts**, which express requirements on template parameters.

### Class Templates

C++ supports both **class templates** and **function templates**. Once template arguments are known at compile time, a class or function template specialization behaves like an ordinary class or function. There is no runtime overhead just because templates are used.

For example, `MyString<char>` and `MyString<wchar_t>` are distinct classes generated from the same template.

#### Implementation Guidelines

The source suggests this workflow:

1. Start from a particular case, such as a non-template `MyString` using `char`.
2. Debug it and make sure it works.
3. Generalize the implementation into a template with a type parameter such as `C`.

This keeps the initial design concrete and reduces the risk of debugging both the algorithm and the template abstraction at the same time.

#### Definition Placement

Class templates are declared like the `MyString` example. Their members must be declared and defined in a way visible to the compiler at instantiation time. In practice, template definitions are usually placed in header files; otherwise, linker errors may occur because the compiler cannot instantiate the needed code.

```cpp
// my-string.h
template<typename C>
class MyString {
public:
    MyString() { // do something }
    ...

- It is not possible to overload the name of a class template
    template<typename C> class MyString { ... };
    class MyString { ... }; // compilation error
```

The source block is incomplete and mixes C++ with slide text. The key rule is that a class template name cannot also be used for a non-template class in the same scope.

#### Template Instantiation

**Instantiation** is the process of generating a class from a template plus type arguments. The generated class is a **specialization** of the template.

During instantiation:

- the compiler generates only the members that are actually used;
- type checking is applied;
- requirements on the type are not checked independently unless mechanisms such as concepts are used.

Template type equivalence follows the actual type: templates instantiated with aliases that refer to the same type are the same type.

#### Class Template Members

Class templates can have the same kinds of members as ordinary classes:

- data members;
- member functions;
- type aliases;
- member types and member templates;
- friends.

For friend function templates, the source notes that `<>` may be needed after the function name to refer to a template.

#### Type Aliases

Type aliases are especially useful in templates. A template parameter such as `T` is available only inside the template, but an alias can expose associated types to outside code.

Common examples are `iterator` and `value_type`.

```cpp
template<typename T>
class Vector {
public:
    using value_type = T;
    using iterator = Vector_iter<T>;  // Vector_iter
    // is another class
};
```

Generic algorithms can refer to these associated types without knowing the exact container implementation.

### Member Templates

Members of class templates can themselves be templates.

```cpp
template<typename S>
class complex {

S re, im;

public:
    complex() :re{}, im{} {}

    complex(S rr, S ii =0) : re{rr}, im{ii} { }

    complex(const complex&) = default;

    template<typename T>
    complex(const complex<T>& c) :
        re{c.real()}, im{c.imag()} { }

// ... };
```

The member template constructor accepts a `complex<T>` and constructs a `complex<S>` from it. This enables conversions between complex numbers with different internal representation types.

#### Conversion Between Template Types

```cpp
template<typename S>
class complex {

S re, im;

public:
    template<typename T>
    complex(const complex<T>& c) :
        re{c.real()}, im{c.imag()} { }

// ... };
```

By using different template parameters for the class (`S`) and constructor argument (`T`), the class can define controlled conversions.

```cpp
complex<float> cf1 {};
complex<double> cd1 {cf1}; // ok - float to double
complex<float> cf2 {cd1}; // error - narrowing
```

Converting `float` to `double` is safe, while converting `double` to `float` may narrow and is rejected in this example.

#### Limitations of Member Templates

Member templates cannot be virtual. Also, template constructors are not used to generate default copy or move constructors.

```cpp
complex(const complex&) = default;

template<typename T>
complex(const complex<T>& c) :
  re{c.real()}, im{c.imag()} { }
```

The ordinary copy constructor for the same type is generated or defaulted separately. The templated constructor handles conversions from different `complex<T>` instantiations, but it does not replace the normal copy constructor.

### Function Templates

Function templates are needed when generic functions operate on template types. For example:

```cpp
template<typename T> void sort(std::vector<T>&);
```

The template type argument is usually deduced from function arguments. Function templates are fundamental for generic programming and can be overloaded. The compiler selects the specialization that best matches the actual arguments.

#### make_pair Example

```cpp
template<typename T1, typename T2>
std::pair<T1,T2> make_pair(T1 a, T2 b)
{
    return {a,b};
}

// .....
auto x = make_pair(1,2);
// x is a std::pair<int,int>

auto y = make_pair(string("New York"),7.7);
// y is a std::pair<string,double>
```

The compiler deduces `T1` and `T2` from the arguments. For `make_pair(1,2)`, both are `int`. For `make_pair(string("New York"),7.7)`, they are `string` and `double`.

#### Explicit Template Arguments

If template parameters cannot be deduced automatically, they must be specified with `<>`.

```cpp
template<typename T>
T* create();

void f()
{
    int* p = create<int>();
    int* q = create(); //ERROR
}
```

`create()` has no argument from which the compiler can deduce `T`, so `create<int>()` is required.

#### lvalue and rvalue Arguments

Function templates can distinguish lvalue and rvalue arguments.

```cpp
template<typename T>
class Xref {
public:
    Xref(int i, T* p); // pointer
    Xref(int i, T& lvref); // lvalue ref
    Xref(int i, T&& rvref); // rvalue ref

private:
    T* elem;
}
```

The class is missing a final semicolon. The overload set distinguishes pointers, lvalue references, and rvalue references. This is important for generic code that must preserve value category.

### Variadic Templates

Variadic templates are a type-safe C++ mechanism for accepting an arbitrary number of parameters with arbitrary types.

```cpp
template<typename T, typename ... Args>
void f(T value, Args ... args)
{
    // do something
    // with value
    f(args ... );
}
```

`Args ...` is a **parameter pack**: a sequence of type and value pairs. At each recursive call, the first argument is handled as `T value`, and the remaining arguments are forwarded as `args ...`.

The implementation must account for the empty-argument case, otherwise recursion has no valid stopping point.

## Final Summary

Templates support generic programming by making types parameters checked at compile time. Class templates and function templates generate concrete specializations when used, with no inherent runtime overhead. Template definitions usually need to be visible in headers because instantiation happens during compilation.

Member templates, function templates, type aliases, and variadic templates allow generic code to express reusable abstractions while keeping type safety. C++20 concepts add a way to state requirements on template parameters explicitly, addressing a limitation of older template code.
