## Study Notes

### Pointers

The lesson follows **[c++pl] Chapter 7** and introduces the low-level relationship between addresses, arrays, and references.

#### Pointer Basics

Given a type `T`, the type `T*` means **pointer to `T`**. A pointer stores the address of an object of type `T`.

```cpp
char c = 'a';
char* p = &c;

labels for memory addresses
p: &c
c: 'a'

char c2 = *p; // c2 is 'a'
dereferencing or indirection returns the value at the address in the pointer
```

This source block mixes C++ and slide annotations. The valid C++ idea is that `&c` produces the address of `c`, `p` stores that address, and `*p` **dereferences** the pointer to access the object stored there. If `p` points to `c`, then `*p` is the value `'a'`.

#### void Pointers and nullptr

`void*` is a pointer to an object of **unknown type**. It is very low-level because the compiler does not know the pointed object's size or operations.

```markdown

void* and nullptr

- Void* is the type "pointer to object of unknown type"
  - Limited set of operations are allowed:
    - Assign to other void*
    - Compare with other void*
    - Explicitly convert to another type using `static_cast<T>()` (unsafe)
  - Generally used to pass (or return) pointers to (from) functions without assumptions on the type
  - Very low-level

- nullptr is the value of a pointer that does not point to any object
```

The slide text means that a `void*` can be copied, compared with another `void*`, and explicitly cast to another pointer type. It cannot be safely dereferenced without first recovering the correct type. `nullptr` is the standard null pointer value: it means the pointer does not point to an object.

```cpp
void* and nullptr

void f(int* pi)
{
    void* pv {pi}; // allowed
    *pv; // compilation error, cannot dereference *void
    // because the type is not implicitly known
    ++pv; // compilation error, cannot increment *void
    // because it does not know the size of the type

    void* pv2 {pi};
    bool pointToSameAddress {pv == pv2};

    int* pi2 {static_cast<int*>(pv)};
    double* pi3 {static_cast<double*>(pv)};
    //allowed but leads to logical errors!

    pi3 = nullptr; // does not point to anything
}
```

The first line, `void* and nullptr`, is slide text and not valid C++. The key point is that `pv` can hold the same address as `pi`, but `*pv` and `++pv` are illegal because `void` has no object size. `static_cast<int*>(pv)` is meaningful only if the original object really is an `int`; casting to `double*` compiles but is logically wrong and can lead to undefined behavior if used.

#### Pointers and Ownership

A **resource** is something acquired and later released, such as memory or a file. A pointer is often used as a handle to a resource, but a raw pointer does not say whether it owns that resource.

```cpp
int i2 = 7;
int* i = &i2; // i does not own resources

int* i3 = new int{7}; // i3 owns object on the free storage
```

`i` only points to an existing automatic object, so it must not delete it. `i3` points to an object allocated with `new`, so some code must eventually release it with `delete`. The slide's rule of thumb is important: put owning pointers inside a **handle class** that manages acquisition and release through constructors and destructors. In modern C++, this idea is represented by RAII types such as smart pointers.

#### Pointers and const

`const` can apply to the pointed object, to the pointer itself, or to both.

```cpp
const char* p = "unipd"; -> the object is const, not the pointer!

const char* const p2 = "unipd"; -> both const

- An object which is const with a pointer may be accessed in other ways
  - Useful to have pointers to const objects as function arguments
  - The function cannot modify the object!
```

In `const char* p`, the characters are const through `p`, but `p` may be reassigned to another address. In `const char* const p2`, both the pointed characters and the pointer variable are const. The bullet text is slide annotation: passing pointers to const objects is useful when a function should read an object without modifying it.

### Arrays

#### Array Basics

Given a type `T`, `T[size]` is an **array** of `size` elements of type `T`. Arrays are low-level sequences of objects laid out contiguously in memory.

Array elements can be accessed with the subscript operator `[]`. Indexes go from `0` to `size - 1`, and raw arrays perform **no runtime bounds checks**. Access outside the valid range is undefined behavior.

Arrays may be allocated with static storage duration, on the stack as automatic objects, or on the free store.

#### Array Initialization

Arrays can be initialized from a list of values.

```cpp
int v1[] = {1,2,3,4}; // the size is automatic
int v2[8] = {1,2,3,4}; // -> 1,2,3,4,0,0,0,0
int v3[2] = {1,2,3,4}; // compilation error
```

If the size is omitted, the compiler deduces it from the initializer list. If the declared array is larger than the list, remaining elements are zero-initialized. If the list has too many elements, compilation fails.

Arrays cannot be copied with ordinary assignment-style initialization.

```cpp
int v1[] = {1,2,3,4};
int v4[4] = v1; // error
```

Raw arrays do not behave like value objects with copy semantics. Prefer standard containers such as `std::array` or `std::vector` when copying, size tracking, and safer interfaces are needed.

#### String Literals

A **string literal** is a character sequence in double quotes. It is represented as an array of characters terminated by `'\0'`. String literals are statically allocated, so returning a pointer to a string literal is safe with respect to lifetime. Their characters must not be modified.

```cpp
const char stringExample[] = "Unipd";
std::cout << sizeof(stringExample) << std::endl; // 6
```

`"Unipd"` has five visible characters plus the terminating null character `'\0'`, so `sizeof(stringExample)` is `6`. `sizeof` returns the size of an expression or type measured in bytes.

### Pointers and Arrays

#### Array Names as Pointers

The name of an array can be used as a pointer to its first element in many expressions.

```cpp
int v[] = {1,2,3,4};
int* p1 = v;
int* p2 = &v[0];
bool pointToSameAddress {p1 == p2}; //this is true
```

`v` and `&v[0]` produce the same address in this context, so `p1 == p2` is true.

```cpp
int* pOneBeyondLast = v + 4;
int* pOther = v + 7;
```

For an array of size 4, `v + 4` is the **one-past-the-end** pointer. It is valid to form and compare in limited ways, but it must not be dereferenced. `v + 7` is outside the valid range and produces undefined behavior if used. Out-of-range pointer arithmetic risks overwriting other variables or causing a segmentation fault.

#### Pointer Traversal

Pointers can be used to traverse arrays.

```cpp
const int size = 4;
int v[size] = {1,2,3,4};

for(int * p1 = v; p1 < v + size; ++p1)
{
    std::cout << *p1 << std::endl;
}

// equivalent to

for(int index = 0; index < size; ++index)
{
    std::cout << v[index] << std::endl;
}

const char* strLit = "unipd";

for(; (*strLit != '\0'); ++strLit)
{
    std::cout << *strLit << std::endl;
}
```

The source used a non-ASCII not-equal sign in the last loop; the valid C++ operator is `!=`. The first loop walks from the first element to the one-past-the-end address. The second loop is the equivalent index-based traversal. Arrays do **not** carry implicit size information, so when passing an array to a function as a pointer, the size must also be passed. C-style strings are a special case because `'\0'` marks the end.

#### Pointer Operators

Pointer operators work on **addresses**, not on the values stored at those addresses. Increment and decrement depend on the pointed type.

```cpp
T arrayt[4];
T* pt = arrayt;
pt++; // the numeric value is pt + sizeof(T)
```

`pt++` advances to the next `T` object, not necessarily to the next byte. Subtracting two pointers, `q - p`, is valid only when both point into the same array range, and it returns the number of elements in `[p, q)`. Adding two pointers is not allowed; only adding or subtracting integers from pointers is meaningful.

### References

A pointer differs from a name because it uses different syntax, can point to different objects at different times, and may be `nullptr`.

A **reference** is an alias for an object. It has pointer-like performance, but it is used with ordinary name syntax. A reference always refers to the object with which it was initialized and is not null.

#### lvalue References

An **lvalue reference** refers to an object whose value can be changed.

```cpp
int var {1};
int &ref {var};
int var2 = ref + 4;
int* pointer = &ref;
++ref;
++pointer;
```

`ref` is an alias for `var`, so `++ref` increments `var`. `&ref` gives the address of `var`, because a reference is not a separate object in ordinary use. `++pointer` increments the pointer value so it points to the next `int` position; it does not increment `var`.

An lvalue reference must always be initialized and cannot later be rebound to another object.

#### rvalue References

An **rvalue reference** refers to a temporary object that can be modified and then not used again. This enables optimizations such as turning expensive copies into moves.

```cpp
int && ref {1};
```

The declared type of `ref` is rvalue reference to `int`, but the expression `ref` itself is an lvalue because it has a name. This distinction is central to move semantics.

#### Move-Based Optimizations

A classic old-style swap copies values.

```cpp
template<class T>
swap(T& a, T& b) // "old-style swap"
{
    T tmp {a}; // two copies of a
    a = b; // two copies of b
    b = tmp; // two copies of tmp (aka a)
}

3 copy operations + destructors + memory consumption
```

The final line is slide text, not C++. The point is that this swap performs three copy operations, plus the related destructor calls and temporary memory use.

A move-based swap casts the objects to rvalue references so that move construction and move assignment can be used when available.

```cpp
template<class T>
swap(T& a, T& b)
{
    T tmp {static_cast<T&&>(a)};
    a = static_cast<T&&>(b);
    b = static_cast<T&&>(tmp);
}
```

The casts are equivalent in intent to using `std::move`.

```cpp
T tmp {std::move(a)};
a = std::move(b);
b = std::move(tmp);
```

`std::move()` does not move by itself. It casts its argument to an rvalue reference, allowing a type with a move constructor or move assignment operator to move resources instead of copying them. If `T` supports move operations, this avoids unnecessary copies.

## Final Summary

This lesson explains the low-level tools behind many C++ abstractions. **Pointers** store addresses and may or may not own resources, so raw owning pointers should be wrapped in resource-managing classes. `void*` is useful only for very low-level code because it loses type information, and `nullptr` represents a pointer to no object.

**Arrays** are contiguous sequences with no implicit runtime bounds checks and no stored size information when passed as pointers. Pointer arithmetic is valid only inside carefully defined array ranges. **References** provide aliasing with safer syntax than pointers: lvalue references bind to existing objects, while rvalue references enable move semantics and avoid unnecessary copies when types support moving.
