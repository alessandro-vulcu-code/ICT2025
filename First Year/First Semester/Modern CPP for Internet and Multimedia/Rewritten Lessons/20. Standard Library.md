## Study Notes

### Standard Library Design

The **C++ Standard Library** is part of the ISO C++ standard and is provided by each C++ implementation. It is not an optional add-on: it defines common facilities used by almost every real C++ program.

The library supports several areas:

- **language support**, such as RTTI, memory management, and range-based `for`;
- **implementation information**, such as numeric limits;
- **concurrency** facilities;
- **programming primitives**, such as containers and algorithms;
- **mathematical functions**.

Its main design goals are **portability**, **efficiency**, and providing a reliable foundation for other libraries. Standard Library facilities are declared in headers and live in the `std` namespace.

### Containers

A **container** is an object that stores multiple objects. Containers can organize elements as a sequence or through keys, and they are designed as **resource handles** with well-defined copy and move behavior.

Standard containers are implemented as **templates**. Their template parameters usually include the element type, and sometimes an allocator, a key type, a comparison function, a hash function, or an equality predicate.

The default allocator is generally `std::allocator<T>`, which uses `new` and `delete` to allocate and deallocate objects of type `T`. Common container operations include `c.size()`, `c.empty()`, `begin()`, and `end()`.

#### Sequence Containers

Sequence containers keep elements in a linear order:

- `std::vector<T, A>` stores elements contiguously and is the usual default choice.
- `std::deque<T, A>` supports efficient insertion and removal at both ends.
- `std::list<T, A>` is a doubly linked list with non-contiguous storage.
- `std::forward_list<T, A>` is a singly linked list.

In general, use **`std::vector<T>`** unless a specific operation pattern makes another container more appropriate.

```cpp
std::vector<int> vec {1, 2, 3, 4};

std::list<int> ls {1, 2, 3, 4};
```

This example creates two sequence containers with the same values. The important difference is their storage model: `vector` stores elements contiguously, while `list` stores nodes separately and links them.

#### Associative Containers

**Ordered associative containers** store elements ordered by key:

- `std::map<K, V, C, A>` maps each key to one value.
- `std::multimap<K, V, C, A>` allows multiple entries with the same key.
- `std::set<K, C, A>` stores unique keys.
- `std::multiset<K, C, A>` allows repeated keys.

`K` is the key type, `V` is the mapped value type for maps, `C` is the comparison type, and `A` is the allocator.

```cpp
std::map<int, std::string> map_int_s;

map_int_s.insert(std::make_pair(4, "four"));
map_int_s[5] = "five";
// this updates the value associated with
// the key, if present, or it performs the
// insertion otherwise.

auto entry_it = map_int_s.find(4);
```

`insert()` adds a key-value pair. `operator[]` either accesses an existing value or inserts a default-constructed value if the key is absent. `find()` returns an iterator to the entry or `end()` if the key is not present.

```cpp
// SOL1: use []
std::string s1 = map_int_s[7]; // if k = 7
// is not present, it adds map_int_s[7] =
// std::string{} and returns it

// SOL2: use find() -> best option
auto entry_it = map_int_s.find(4);
if (entry_it != map_int_s.end()) {
    std::string s2 = entry_it->second;
} // it uses iterators: if k = 4 is not
// present, it returns map_int_s.end()
```

The source slide is slightly corrupted here: it uses a non-C++ not-equal symbol and writes `entry_it.second()`. The intended C++ form is `entry_it != map_int_s.end()` and `entry_it->second`. For lookup without insertion, **`find()` is safer than `operator[]`**.

**Unordered associative containers** use hashing instead of ordering:

- `std::unordered_map<K, V, H, E, A>`;
- `std::unordered_multimap<K, V, H, E, A>`;
- `std::unordered_set<K, H, E, A>`;
- `std::unordered_multiset<K, H, E, A>`.

`H` is usually `std::hash<K>`, `E` is usually `std::equal_to<K>`, and `A` is the allocator. These containers are useful when key order is not needed and average constant-time lookup is desired.

#### Container Adaptors and Almost Containers

**Container adaptors** are not full containers. They provide a restricted interface on top of another container:

- `std::priority_queue<T, C, Cmp>` gives priority-based access; the default underlying container is `std::vector<T>`.
- `std::queue<T, C>` gives FIFO access; the default underlying container is `std::deque<T>`.
- `std::stack<T, C>` gives LIFO access; the default underlying container is commonly `std::deque<T>` in the standard library.

The slides also mention two *almost containers*:

- `std::array<T, N>` represents a fixed-size array. It has container-like operations but cannot grow or shrink.
- `std::basic_string<C, Tr, A>` represents strings and has many container-like properties.

#### Container Operations

Containers expose common member types and operations so generic code can work across different container classes.

Important **member types** include:

- `value_type`, `size_type`, and `difference_type`;
- `pointer`, `const_pointer`, `reference`, and `const_reference`;
- `iterator`, `const_iterator`, and possibly reverse iterators;
- `allocator_type`;
- associative-container types such as `key_type`, `mapped_type`, `key_compare`, `hasher`, `key_equal`, `local_iterator`, and `const_local_iterator`.

Common **generic operations** include:

- `begin()`, `end()`, `cbegin()`, `cend()`;
- reverse iteration functions when supported;
- assignment, comparison, `swap()`;
- `size()`, `max_size()`, `empty()`, and `clear()` where available;
- `get_allocator()`;
- `insert()`, `emplace()`, and `erase()`.

Sequence containers add operations such as `assign()`, `front()`, `resize()`, and sometimes `back()`, `push_back()`, `pop_back()`, and `emplace_back()`.

Associative containers add operations such as `find()`, `count()`, `lower_bound()`, `upper_bound()`, `equal_range()`, `emplace_hint()`, and sometimes `operator[]` and `at()`.

Lists also provide operations tied to node-based storage: `remove()`, `remove_if()`, `unique()`, `merge()`, `sort()`, `reverse()`, and `splice()`. `forward_list` has related `*_after` operations, such as `insert_after()` and `erase_after()`.

### Iterators

An **iterator** is an object that behaves similarly to a pointer into a container. It is the mechanism that separates **containers** from **algorithms**: algorithms can work on iterator ranges without knowing the concrete container type.

The basic model is:

- `begin()` returns an iterator to the first element;
- `end()` returns an iterator one position after the last valid element;
- `++it` moves to the next element;
- `*it` accesses the element.

```cpp
std::vector<int> vec {1,2,3,4};
std::vector<int>::iterator vec_iter = vec.begin();
std::vector<int>::iterator vec_end = vec.end();

while (vec_iter != vec_end)
{
    // this increases the value in the vector,
    // e.g., 1++ -> 2
    ++(*vec_iter);
    // this increases the value of the iterator,
    // i.e., the entry to which the iterator points
    ++vec_iter;
}
```

This loop modifies the vector elements in place. `++(*vec_iter)` increments the integer stored in the vector, while `++vec_iter` moves the iterator to the next position. The source slide used a non-C++ not-equal symbol; the intended operator is `!=`.

Use a **`const_iterator`** when the elements must be read but not modified.

#### Iterator Categories

C++ defines iterator categories by the operations they support:

- **Input iterators** and **output iterators** are used for one-pass input and output, often with streams. They mainly support `++` and `*`.
- **Forward iterators** move forward through a sequence and support `++`, `*`, `==`, `!=`, and `->`.
- **Bidirectional iterators** add `--`, so they can move backward.
- **Random access iterators** support arbitrary jumps and indexing, with operations such as `+=`, `[]`, and relational comparisons.

Iterator category matters because algorithms require different capabilities. For example, `std::sort()` needs random access iterators, so it works on `vector` but not directly on `list`.

### Algorithms

The header `<algorithm>` provides around eighty **generic algorithms**. They operate on iterator ranges rather than directly on container types. Typical operations include searching, finding, transforming, sorting, copying, replacing, and merging.

Algorithms can use ordinary comparison operators or custom functions, predicates, and comparators.

#### Ranges and Complexity

Most algorithms operate on a sequence defined by a half-open range: **`[b, e)`**. The iterator `b` points to the first element, and `e` points one past the last element.

When an algorithm takes an output iterator, it usually assumes enough output space exists. For example, an output range may need to hold `e - b` elements. The programmer must ensure that the destination is valid.

The slides classify algorithm complexity as follows:

- **O(1)**: `swap`, `iter_swap`.
- **O(log n)**: `lower_bound`, `upper_bound`, `equal_range`, `binary_search`, `push_heap`, `pop_heap`.
- **O(n log n)**: `inplace_merge` in the worst case, `stable_partition` in the worst case, `sort`, `stable_sort`, `partial_sort`, `partial_sort_copy`, `sort_heap`.
- **O(n*n)**: `find_end`, `find_first_of`, `search`, `search_n`.
- **O(n)**: most remaining algorithms.

The source has the typo `upper_bund`; the intended algorithm is `upper_bound`.

#### Algorithm Families

**Non-modifying algorithms** inspect a range without changing it:

- `all_of(begin, end, fun)`, `any_of(begin, end, fun)`, and `none_of(begin, end, fun)` check Boolean conditions.
- `count(begin, end, v)` counts occurrences.
- `find(begin, end, v)` returns an iterator to the matching value.
- `equal(begin, end, begin2)`, `mismatch(begin, end, begin2)`, and `search(begin, end, begin2, end2)` compare or search ranges.

**Algorithms that may modify output** include:

- `for_each(begin, end, fun)`, which may modify elements depending on `fun`;
- `transform(begin, end, out, fun)`, which writes transformed elements to `out`.

`transform()` does not modify the original range unless `out` points into that same range, such as `out == begin`.

**Modifying algorithms** include `copy`, `unique`, `remove`, `replace`, `rotate(begin, m, end)`, `random_shuffle(begin, end)`, `next_permutation(begin, end)`, and `swap(x, y)`.

Sorting and ordered-search facilities include `std::sort(begin, end)`, binary search on ordered ranges, merge of ordered ranges, and functions to find minimum and maximum elements.

### Strings

The C++ string type is based on the template `std::basic_string`. It supports different character types and stores characters contiguously.

```cpp
template<typename C,
typename Tr = char_traits<C>,
typename A = allocator<C>>
class basic_string {
public:
    using traits_type = Tr;
    using value_type = typename Tr::char_type;
    using allocator_type = A;
    using size_type = typename allocator_traits<A>::size_type;
    using difference_type = typename allocator_traits<A>::difference_type;
    using reference = value_type&;
    using const_reference = const value_type&;
    using pointer = typename allocator_traits<A>::pointer;
    using const_pointer = typename allocator_traits<A>::const_pointer;
    using iterator = /* implementation-defined */;
    using const_iterator = /* implementation-defined */;
    using reverse_iterator = std::reverse_iterator<iterator>;
    using const_reverse_iterator = std::reverse_iterator<const_iterator>;

    static const size_type npos = -1; // integer representing end-of-string
};
```

This simplified interface shows that a string behaves like a specialized container of characters. `npos` is used by search operations to mean "not found" or an invalid string position.

Common specializations are:

- `std::string`, equivalent to `std::basic_string<char>`;
- `std::wstring`, equivalent to `std::basic_string<wchar_t>`.

The source writes `wchar`; the standard character type is `wchar_t`.

```cpp
std::string empty {}; // default
std::string c_style {"this is a C-style string"};
std::string another {c_style}; // copy
```

These examples show default construction, construction from a C-style string literal, and copy construction.

String operations include comparisons, `size()`, `length()`, `resize()`, character access, numeric conversions, search and replace operations, and substring extraction.

### I/O Streams

C++ **I/O streams** convert typed values to and from byte sequences. The main stream categories are:

- `ostream` for output;
- `istream` for input;
- `fstream` for file input/output.

Streams are **type-safe**, extensible, locale-sensitive, and designed to be efficient enough for general use.

When `<iostream>` is included, the standard streams are available:

- `std::cout` for normal output;
- `std::cerr` for errors;
- `std::clog` for logging;
- `std::cin` for input.

The source summarizes the stream hierarchy as:

```text
ios_base
basic_ios
basic_istream
basic_ostream
basic_istringstream
basic_iostream
basic_ostringstream
basic_ifstream
basic_ofstream
basic_fstream
basic_stringstream
```

The exact library hierarchy is more detailed, but the key idea is that input streams, output streams, file streams, and string streams share a common stream abstraction.

#### File Streams

The header `<fstream>` provides file stream classes:

- `std::ifstream` for reading from files;
- `std::ofstream` for writing to files;
- `std::fstream` for both reading and writing.

```cpp
#include <fstream>
string filename = "test.txt";
// open the file, multiple options available
// (e.g., append, replace, etc)
std::ofstream fout(filename.c_str());
if (!fout) // check if opened correctly
{
    std::cout << "error: open file for output failed!"
              << std::endl;
    exit(127);
}
```

This code opens an output file stream and checks whether the file was opened successfully. In modern C++, `std::ofstream fout(filename);` is usually enough when `filename` is a `std::string`, but the slide uses `filename.c_str()`.

```cpp
fout << "a line" << std::endl;
fout << "another line" << std::endl;
fout.close();
```

This writes two lines and closes the file explicitly. The stream destructor would also close it, but explicit `close()` can be useful when you need to check or control the exact closing point.

```cpp
std::ifstream fin(filename.c_str());
if (!fin)
{
    std::cout << "error: open file for input failed!"
              << std::endl;
    exit(127);
}

std::string line;
while (std::getline(fin, line))
{
    std::cout << line << std::endl;
}
fin.close();
```

This opens the same file for reading and uses `std::getline()` to read it line by line. The loop stops when there are no more lines or when reading fails.

#### String Streams

The header `<sstream>` defines:

- `std::istringstream` for reading from a string;
- `std::ostringstream` for writing to a string;
- `std::stringstream` for both.

```cpp
std::stringstream ss {};
std::vector<std::string> studentNames {"john", "jane"};
for (auto student : studentNames)
{
    ss << student << ",";
}
// create a std::string and output to terminal
std::cout << ss.str() << std::endl;
```

This builds a string by streaming multiple values into `ss`, then obtains the accumulated string with `ss.str()`. The slide notes that `operator+` can concatenate strings, but streams are often more convenient and efficient when values are produced in a loop.

## Final Summary

The Standard Library provides portable, efficient building blocks for C++ programs. **Containers** manage collections of objects, **iterators** give a uniform way to traverse them, and **algorithms** operate on iterator ranges independently of concrete container types. `std::string` is a specialized character container, while streams provide typed input and output for terminals, files, and strings. For an oral exam, the key idea is the separation between storage, traversal, and computation: containers store, iterators connect, and algorithms operate.
