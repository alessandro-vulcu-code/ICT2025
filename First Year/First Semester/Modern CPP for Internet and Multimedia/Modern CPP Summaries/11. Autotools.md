**Autotools** is a suite of GNU programming tools that help developers make source code packages **portable** across different Unix-like systems.  
It automates the process of configuration, compilation, and installation for large software projects

### **GNU Autotools**

Autotools is composed of:
- **GNU Autoconf** – generates the `configure` script for the project.
- **GNU Automake** – simplifies creation of portable and consistent `Makefile`s.
- **GNU Libtool** – abstracts and simplifies the creation of **portable libraries**.

A **makefile** is a list of rules (expressed as shell commands) that the **make** utility applies to build, test, and install the project.

---

### **What’s inside the Git repo?**

Typical project directory using Autotools:

```
example/
test/
basic_utilities/
m4/
installer.sh
autogen.sh
configure.ac
Makefile.am
```

- **Folders:** source code and project components.
- **`installer.sh`:** installation script.
- **`autogen.sh`:** prepares the build environment automatically.
- **`configure.ac`:** configuration script source (written with M4 macros).
- **`Makefile.am`:** makefile enhanced with Automake syntax.

Each `Makefile` contains shell command rules applied by the `make` utility to compile and install the project.

### **Run the installer.sh (shell script)**

The `installer.sh` script automates the entire build process, from configuration to installation.

**Usage:**
```bash
./installer.sh -p <path> -t <flag>
```

**Options:**

- `-p` → sets the **installation path** (where the program will be installed).
- `-t` → enables (`1`) or disables (`0`) **tests**.
- `-h` → displays help message.
- `-c` → cleans the repository.

**Example:**

```bash
./installer.sh -p ~/my_path -t 1
```

This installs the program in the specified path and runs the tests.

---

### **installer.sh (shell script)**

The script executes the following sequence of commands:

1. **`autogen.sh`** – prepares the environment and generates `configure` and `Makefile.in`.
2. **`configure`** – creates `Makefile`s from templates.
3. **`make`** – compiles the source code according to the generated makefiles.
4. **`make check`** – (optional) runs automatic tests; aborts if tests fail.
5. **`make install`** – installs executables and libraries in `$PREFIX/bin` and `$PREFIX/lib`.

**Simplified version:**

```bash
./autogen.sh
./configure --prefix $PREFIX
make
if [ $TEST_UP -eq 1 ]; then
  make check
fi
make install
```

The prefix path (`-p`) and test flag (`-t`) are passed to control the installation behavior.

### **autogen.sh (shell script)**

The `autogen.sh` script initializes all Autotools components for the project.

It performs the following steps:
1. **(g)libtoolize** – prepares the package to use Libtool.
2. **aclocal** – generates `aclocal.m4` by scanning `configure.ac`.
3. **autoconf** – creates the `configure` script from `configure.ac`.
4. **automake** – produces `Makefile.in` from `Makefile.am`.
    

**Example content:**

```bash
case `uname` in
  Darwin*) glibtoolize ;;   # macOS
  *) libtoolize ;;           # Linux and others
esac
aclocal
autoconf
automake --add-missing
```

- `glibtoolize` is used on **macOS** (where `libtool` name is already taken).
- On other Unix systems, the command is simply `libtoolize`.

---

### **(g)libtoolize (shell script)**

The **GNU Libtool** utility simplifies the creation of shared libraries on multiple platforms.  
When `libtoolize` runs, it:

- Generates a customized `ltmain.sh` script (used by `config.status`).
- Copies Libtool-related **M4 macros** into the `m4/` folder:
    - `libtool.m4`, `ltobsolete.m4`, `ltsugar.m4`, `ltversion.m4`.
- These macros are then used by `aclocal` to handle library configuration.

> The macro language used by Autoconf is **M4**.
