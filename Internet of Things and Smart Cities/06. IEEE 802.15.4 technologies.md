
### General description

#### Overview
* **IEEE 800.15.4** defines the **Physical (PHY)** and **Media Access Control (MAC)** sublayers for Low-Rate Wireless Personal Area Networks (LR-WPANs).
* It is designed for easy installation, reliability, extremely low cost, reasonable battery life, and relaxed throughput.
* It supports a large number of nodes (unlike BLE) and asynchronous communication of small data packets.
* It is the foundation used by protocols like **ZigBee** and **6LoWPAN**.

#### Types of nodes
* **Full Function Device (FFD):**
    * Has full PHY and MAC capabilities.
    * Can relay messages.
    * Can act as a PAN coordinator.
    * Supports any topology.
* **Reduced Function Device (RFD):**
    * Simpler implementation with reduced functions.
    * Can only talk to an FFD and cannot be a PAN coordinator.
    * Cannot relay data (acts only as an end node).
    * Limited to star topology.

#### Frame structure
* **Preamble (32 bits):** For synchronization.
* **Start of Packet Delimiter (8 bits)**.
* **PHY Header (8 bits):** Indicates PSDU length.
* **PSDU (0 to 1016 bits / 0-127 bytes):** The data field.

#### MAC layer
![[Pasted image 20251021094457.png]]
The MAC layer operates in two main modes:

* **Beacon-enabled mode:**
    * The PAN coordinator periodically sends **beacons** for synchronization.
    * Time is divided into **Superframes** (the active part).
    * The Superframe is divided into 16 time slots and has two parts:
        1.  **Contention Access Period (CAP):** Uses slotted CSMA/CA for channel access.
        2.  **Contention Free Protocol (CFP) (optional):** Uses **Guaranteed Time Slots (GTS)** allocated by the coordinator for dedicated, contention-free resources.
			![[Pasted image 20251021095218.png]]
    * An **Inactive part** allows nodes to sleep to save power.
    * The ratio of superframe duration to beacon interval is the **duty cycle**.

* **Non-beacon-enabled mode:**
    * No periodic beacons are sent.
    * Channel access uses **unslotted CSMA/CA**.
    * Synchronization is not required, which saves power from beacon listening.
    * Devices must use **active scanning** (sending a Beacon Request) to join the network.

#### Security
The MAC layer provides several security services:
* **Unsecured:** No security.
* **Access Control List (ACL):** Accepts/rejects frames based on the source node.
* **Secured:** Implements multiple mechanisms:
    * Access control.
    * Data confidentiality (symmetric encryption).
    * Frame integrity.
    * Sequential freshness protection (prevents frame replay).

#### Amendments
* **Timeslotted Channel Hopping (TSCH):** Designed for industrial processes. It works in non-beacon mode and uses channel hopping to improve reliability.
* **Deterministic and Synchronous Multi-channel Extension (DSME):** Implements the use of multiple channels within the same superframe for robustness.

### ZigBee

#### Overview
* An industrial standard for IoT promoted by the Zigbee Alliance.
* It is built on top of the IEEE 800.15.4 PHY and MAC layers.
* It defines the **Network (NWK)**, **Application Support (APS)**, and **Application Layers (AF)**.
	![[Pasted image 20251021100429.png]]

#### Applications
* Building automation (HVAC, lighting, metering)
* Personal healthcare (patient monitoring)
* Industrial automation (asset management, process control)
* Consumer electronics (remotes)
* PC peripherals (mouse, keyboard)

#### Network layer: functionalities
* Starting, joining, and leaving a network.
* Configuring new devices.
* Assigning addresses to devices.
* Routing and route discovery.
* Applying and removing security to frames.

#### Network layer: topology
* **Star Network:** A central coordinator (FDD) communicates with end devices (FDD or RFD).
* **Mesh Network:** The network is extended using **ZigBee routers (FDDs)** that relay data, allowing nodes to communicate beyond the coordinator's direct range.

#### Network layer: addressing
Each device has two identifiers:
1.  **Extended Address (64-bit):** A unique, universal IEEE address assigned during production (like a MAC address).
2.  **Short Address (16-bit):** A dynamic ID assigned by the PAN Coordinator when a device joins the network (like an IP address). This allows for up to ~65,000 nodes.

#### Network layer: routing
* Can be **hierarchical** (following the network tree).
* Also uses **dynamic "best" path** searching based on the **AODV (Ad-hoc On-demand Distance Vector)** protocol.
* Routers are discovered on-demand.
* The algorithm finds the minimal cost path, calculated from the probability of packet delivery on each link.

#### Application layer: overview
Consists of three sublayers:
1.  **Application Support (APS)**
2.  **ZigBee Device Objects (ZDO)**
3.  **Application Framework (AF)** (manufacturer-defined apps)

#### Application layer: APS
Provides services such as:
* **Address mapping** (between 64-bit and 16-bit addresses).
* **Fragmentation and reassembly**.
* **Security** (encryption/decryption).
* **Binding** (matching two devices based on their services).
* **Service Discovery**.
* **Group Addressing** (e.g., "turn on all lights").

#### Application layer: ZDO
A special application that handles key network functions:
* Defining the device's role (Coordinator, Router, End Device).
* Device discovery and network formation.
* Network management (joining/leaving).
* Security management (key distribution).
* Network address management (resolving conflicts).

#### Application layer: AF
* Provides the platform for running the actual user application (Application Objects).
* Provides application **profiles** to ensure interoperability between different manufacturers.
* Exposes ZDO functions to the applications.

### 6LowPAN

#### Overview
* **6LoWPAN** is an IETF standard for **IPv6 over Low-Rate Wireless Personal Area Networks** (i.e., IEEE 800.15.4).
* The goal is to transform any device into an IPv6-addressable host.
* It introduces a **6LowPAN Adaptation layer** between the IPv6 Network layer and the 800.15.4 MAC layer.

#### Digression: IPv6 for IoT
* **Problem:** There is a large mismatch between IPv6 and IEEE 800.15.4.
    * **MTU Size:** The minimum IPv6 MTU is **1280 bytes**.
    * **800.15.4 MTU:** The maximum 800.15.4 frame payload is **127 bytes**.
    * **Header Overhead:** The standard IPv6 header is **40 bytes**, which would consume nearly one-third of the entire 800.15.4 payload.

#### General architecture
* 6LoWPAN networks connect to the internet using standard **IPv6 edge routers**.
* This avoids the need for special application-layer gateways (like those used in ZigBee).
* Network nodes can be **Hosts (H)** (end devices) or **Routers (R)** (FFDs).

#### Addressing
To solve the MTU and overhead problem, 6LoWPAN uses:
1.  **Header compression**
2.  **Fragmentation**

#### Header compression
* Works by eliding or compressing redundant information from the 40-byte IPv6 header.
* Fields like Version (always 6), Payload Length (derived from data-link layer), and Traffic Class/Flow Label (often zero) can be compressed or removed.
* **HC1 format**:
    | 7 bit | 1 bit | 2 bit | 2 bit | 2 bit | 1 bit | 8 bit | |
    | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
    | HC1<br>01000010 | TF | SA | DA | NH | HC2 | Hop<br>Limit | Payload |
* **IPHC format**: A more efficient format that uses context-based compression.
    | 3 bit | 2 bit | 1 bit | 2 bit | 1 bit | 1 bit | 2 bit | 1 bit | 1 bit | 2 bit | |
    | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
    | IPHC<br>011 | TF | NH | HLIM | CID | SAC<br>(S) | SAM | M | DAC<br>(D) | DAM | Payload |

| SAM/DAM value | Inline | IID |
| :--- | :--- | :--- |
| 000 | 128 | address fully inline |
| 001 | 64 | link-local 64-bit Interface ID |
| 010 | 16 | link-local 16-bit short address |
| 011 | 0 | link-local + link-layer source address |
| 100 | | reserved |
| 101 | 64 | context + 64-bit Interface ID |
| 110 | 16 | context + 16-bit short address |
| 111 | 0 | context |

#### Fragmentation
* If a packet is still too large after compression, it must be fragmented.
* Fragmentation information is carried in a **Fragment Header**.
* **First Fragment:**

| 8 bit | 11 bit | 16 bit |
| :--- | :--- | :--- |
| 11000xxx | Size | Tag |

* **Subsequent Fragments:**

| 8 bit    | 11 bit | 16 bit | 8 bit  |
| :------- | :----- | :----- | :----- |
| 11100xxx | Size   | Tag    | Offset |

#### Routing
* Standard IPv6 routing is too resource-consuming for IoT nodes.
* 6LoWPAN requires a new routing scheme, the de-facto standard being **RPL (Routing Protocol for Low Power and Lossy Networks)**.

#### Routing (RPL)
* **Topology:** RPL proactively (not on-demand) builds a **Destination-Oriented Directed Acyclic Graph (DODAG)**. This is a directed graph without cycles, oriented towards a root node (the edge router).
* **Rank:** Each node is assigned a **rank**, which represents the cost to reach the root. The rank must increase as you move down the graph (away from the root). This mechanism is used to **avoid loops**.
* **Control Packets:** RPL uses control packets to build and maintain the DODAG:
    * **DIO (DODAG Information Object):** Sent downwards (from root to leaves) to establish the upward path.
    * **DAO (Destination Advertisement Object):** Sent upwards (from leaves to root) to establish the downward path.
    * **DIS (DODAG Information Solicitation):** Used by nodes to request a DIO message.
* **Modes of Operation:**
    1.  **Storing:** Intermediate nodes store routing tables for all destinations in their sub-DODAG. DAOs are sent to the parent.
    2.  **Non-Storing:** Only the root (edge router) stores routing information. All routing passes through the root. DAOs are sent all the way to the root.
* **DODAG Creation Example:**
    1.  The Edge Router (ER, Rank 0) multicasts a **DIO** message.
    2.  Receiving nodes (e.g., 1, 2, 3) respond with a unicast **DAO** message sent back up the path.
    3.  The parent/root sends a **DAO-ACK** to acknowledge.
    4.  Nodes 1, 2, and 3 compute their own rank (e.g., Rank 1) and rebroadcast the **DIO** message to their neighbors (e.g., 4, 5, 6).
    5.  If a node (e.g., 4) receives multiple DIOs, it selects a **preferred parent** based on the lowest rank.
    6.  The process continues until all leaf nodes are reached.
